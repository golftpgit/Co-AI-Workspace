# Co-AI Workspace

ระบบ AI Agent ส่วนตัวบน Mac (Swift native) สำหรับงาน **เขียนโค้ด · วิเคราะห์ข้อมูล · งานเอกสารเชิงวิจัย**
สั่งหัวหน้าทีมคนเดียว แล้วทีมแบ่งงานและตรวจงานกันเองตามมาตรฐานที่ประกาศไว้ล่วงหน้า

> **pre-alpha** — เริ่มเขียน 10 ส.ค. 2569 เปิดให้ดูตอนที่ยังไม่เสร็จ ยังไม่ใช่ซอฟต์แวร์ที่พร้อมให้คนอื่นเอาไปทำงานจริง
> **โค้ดและเอกสารในรีโปนี้ AI เขียนทั้งหมด** — รายละเอียดที่ [§ AI เขียน 100%](#5-ai-เขียน-100-หมายความว่าอะไร)

## 1. จะทำอะไร

งานวิจัยหนึ่งชิ้นข้ามเลนตลอดเวลา: อ่านเปเปอร์ → เขียนโค้ดดึงข้อมูล → รันสถิติ → เขียนต้นฉบับที่อ้างอิงกลับไปยังเปเปอร์ที่อ่านตอนแรก
ทุกวันนี้แต่ละขั้นอยู่คนละเครื่องมือ และสิ่งที่หายระหว่างทางคือ **ที่มา** — สุดท้ายไม่มีใครตอบได้ว่าตัวเลขในตารางมาจากไฟล์ไหน ผ่านสมมติฐานอะไร และตรงไหนที่ AI เดาให้

โปรเจกต์นี้พยายามให้ทั้งสี่เลนอยู่ในแอปเดียว บนเครื่องตัวเอง และ**เดินผ่านประตูอนุมัติเดียวกัน** เพื่อให้ที่มาไม่ขาดตอน

### วัตถุประสงค์

1. **งานที่ AI ทำต้องตรวจสอบย้อนกลับได้** — ทุกข้อความที่อ้างคลังความรู้ต้องผูกกับ chunk ที่รองรับมันจริง ไม่ใช่ให้โมเดลพิมพ์ citation เอง
2. **สิ่งที่ AI เดา ต้องขึ้นบัญชี** — สมมติฐานที่ agent เสนอเองจะถูกทำเครื่องหมายไว้ และไปโผล่ในส่วน "ข้อจำกัดของการศึกษานี้" โดยอัตโนมัติ
3. **การกระทำที่มีผลจริงต้องผ่านประตูเดียว** — ไม่ว่าคำสั่งจะมาจากหน้าจอ, Telegram, Discord, LINE หรือ Siri
4. **ทำงานบนเครื่องตัวเองได้** — ข้อมูลผู้ป่วย/ข้อมูลวิจัยไม่ควรต้องออกจากเครื่องเพื่อให้ AI ช่วยงานได้
5. **ภาษาไทยเป็นพลเมืองชั้นหนึ่ง** — ตั้งแต่การตัดคำ ไปจนถึงฟอนต์ในไฟล์ `.docx` ที่ออกมา

## 2. แนวคิดสำคัญ

### 2.1 AI Team ไม่ใช่ agent เดี่ยวหลายตัว

ผู้ใช้คุยกับ **Team Lead** คนเดียว แล้ว Team Lead แตกงานให้ specialist (Researcher · Analyst · Engineer · Writer)
มี **QA** ตรวจตาม Definition of Done ต่อบทบาท ก่อนงานจะกลับไปหาผู้ใช้ — ไม่ผ่านก็ส่ง rework แบบจำกัดจำนวนรอบ เกินแล้วยกให้คนตัดสิน

กติกาถูกบังคับด้วย type system ไม่ใช่ prompt:

- `Assignment` บังคับให้มี `acceptanceCriteria` ตั้งแต่ระดับ struct — มอบหมายงานโดยไม่บอกว่า "เสร็จแปลว่าอะไร" ไม่ได้
- specialist เป็น Swift `actor` แยกกัน คืนได้แค่ `Deliverable { summary, artifacts, evidence }` **ไม่ใช่ transcript ทั้งก้อน** — compiler การันตี context isolation
- tool set ของ Team Lead ไม่มี `run_shell` — หัวหน้าทีมลงมือทำงานเองไม่ได้ตั้งแต่ระดับโครงสร้าง

### 2.2 หลักฐาน ไม่ใช่คำกล่าวอ้าง

QA ไม่ถามว่า "งานดีไหม" แต่ตรวจของที่ตรวจได้:

| บทบาท | ผ่านเมื่อ |
|---|---|
| Engineer | มี tool call ที่รัน build/test จริง และ exit code = 0 อยู่ใน transcript ของงานนั้น |
| Analyst | ผ่านประตูตรวจสมมติฐานสถิติ + ทุกนิยามตัวแปรถูกคนยืนยันแล้ว |
| Researcher | ทุกข้อสรุปมี ≥2 แหล่ง และ**อ่านเนื้อหาจริง** ไม่ใช่ตัดสินจาก snippet · ข้อขัดแย้งต้องเข้า Conflict Ledger ไม่ใช่เลือกข้างเงียบ ๆ |
| Writer | ทุกประโยคจากคลังความรู้มี citation ผูก provenance จริง · แหล่งที่ไม่มีผู้เขียน/ปี **หยุดการสร้างเอกสาร** |

### 2.3 ประตูเดียวสำหรับทุกการกระทำ

ทูลทุกตัวเดินผ่าน hook chain เส้นเดียว: **Critic → Risk → Policy → HITL (คนอนุมัติ)**
ช่องทางแชต (Telegram/Discord/LINE) เอื้อมถึง tool layer ไม่ได้เลย เพราะ type ของ tool ไม่อยู่ใน scope ของ module ช่องทาง — และ `check.sh` จะ fail ถ้ามีใครเผลอต่อสายข้าม

คำสั่งที่เปลี่ยนข้อมูลใน notebook/DB explorer มีแผ่นยืนยันที่แสดง **SQL คำต่อคำ** ทุกคำสั่ง ไม่ใช่แค่บอกจำนวนแถว

### 2.4 invariant บังคับด้วยโครงสร้าง ไม่ใช่วินัย

`scripts/check.sh` ไม่ได้รันแค่เทส แต่ fail ถ้าโครงพัง เช่น มีทางเรียกทูลที่ไม่ผ่าน hook chain · ทูลที่จัดชั้นความเสี่ยงไว้แล้วแต่ไม่มีตัวจริง · ความสามารถที่เข้าถึงได้จากเทสแต่ไม่มีทางเข้าถึงจากแอป · ปุ่มไอคอนที่ไม่มีป้ายให้ VoiceOver

กฎข้อสุดท้ายมาจากการเจ็บซ้ำ: ในโปรเจกต์นี้เอง "เขียนโค้ดแล้ว" กลายเป็น "ไม่มีใครเรียกใช้ได้" มาแล้ว **6 ครั้ง** (เช่น ทีม P4 ทั้งชุดที่ถูก init เฉพาะในเทสของตัวเอง · ทูล `ingest_url` ที่มีชื่ออยู่ในแผนแต่ไม่มีตัวตน) จึงเขียนเป็นกฎที่ทำให้ build แดง

### 2.5 โมเดลเป็นชั้น เลือกตามงาน

Tier 0 (on-device ~3B) รับงานเล็กและบ่อย · Tier 0.5 (MLX บนเครื่อง) · Tier 1 (endpoint ที่ตั้งเอง)
router สลับให้เอง และงานที่มีผลกระทบสูงถูกกันไม่ให้ลงโมเดล on-device ตามผลวัด guardrail จริงที่บันทึกไว้ใน ARCHITECTURE

## 3. Tech

- **UI**: SwiftUI (macOS 26+, Apple Silicon)
- **LLM**: Foundation Models on-device · MLX บนเครื่อง · endpoint แบบ OpenAI-compatible — ผ่าน `LLMExecutor` abstraction ที่เขียนเอง เพื่อให้สลับไปใช้ API ของ Apple ได้เมื่อ macOS 27 ออก โดยไม่ต้องรื้อ
- **Knowledge**: SurrealDB (graph + vector + BM25) ผ่าน client ที่เขียนเอง (JSON-RPC over WebSocket) — ไม่ผูกกับ SDK ที่ยัง alpha
- **Embedding**: `bge-m3` @ 1024 มิติ รันในโปรเซสตัวเอง — เลือกจากการวัดจริงว่าเป็นตัวที่ทำ cross-lingual ไทย↔อังกฤษได้
- **Analysis**: DuckDB (`duckdb-swift`) + Python notebook kernel (state ข้ามเซลล์ได้)
- **สถิติ**: เขียนเองใน Swift ทั้งชุด — assumption check, α/ω, ICC 6 รูป, Cohen's/Fleiss' κ, EFA (principal axis + varimax) ผ่าน LAPACK ของ Accelerate · ไม่ต้องมี Python หรือ R บนเครื่อง
- **เก็บข้อมูลภาคสนาม**: HTTP server ในแอป เสิร์ฟแบบสอบถามเป็น HTML/CSS ล้วน → SQLite (WAL, append-only) · ตารางเชื่อมตัวตนอยู่คนละไฟล์ เข้ารหัส AES-GCM ด้วยคีย์ใน Keychain
- **ค้นเว็บ**: `WKWebView` แบบไม่มีหน้าต่างในแอปเอง — ไม่ต้องมี API key ไม่ต้องแพ็ก runtime เพิ่ม และอ่านหน้าที่ render ด้วย JavaScript ได้
- **DocGen**: `.docx` / `.pptx` จริงที่ Word/Keynote เปิดได้ พร้อม citation ผูก provenance
- **OS-native ก่อนเขียนเอง**: Vision (OCR), NaturalLanguage (ตัดคำไทย), App Sandbox, App Intents/Siri, Accelerate, WebKit
- **ขยายได้**: MCP client ครบ 3 primitive + ระบบปลั๊กอิน (ติดตั้งแล้วทูลขึ้น tool list ทันที) + agent เขียน skill ของตัวเองได้ผ่าน gate ปกติ

ขนาดตอนนี้: Swift ~52,600 บรรทัดใน 29 target + เทสอีก ~22,700 บรรทัด

## 4. ทำไมถึงวางโครงแบบนี้ — สิ่งที่คาดว่าจะได้เปรียบเมื่อโตขึ้น

ส่วนนี้คือ **ความคาดหวัง ยังไม่ใช่ผลที่พิสูจน์แล้ว** — เขียนไว้เพื่อให้เถียงได้ว่าเดิมพันผิดตรงไหน

- **ประตูเดียวทำให้ของใหม่ได้ความปลอดภัยฟรี** — ตอนต่อ Telegram/Discord/LINE/Siri เข้ามา ไม่ต้องเขียนตรรกะอนุมัติใหม่สักบรรทัด ทูลตัวถัดไปก็ควรได้แบบเดียวกัน
- **invariant ที่ทำให้ build แดง กันการถดถอยตอนโค้ดโตขึ้น** — ยิ่ง codebase ใหญ่ กฎที่บังคับด้วยเครื่องยิ่งคุ้มกว่ากฎที่บังคับด้วยความจำคน โดยเฉพาะเมื่อคนเขียนโค้ดคือ AI
- **abstraction คั่นของ Apple ที่ยังไม่มา** — API ที่ยังไม่อยู่ใน SDK จริงถูกกันไว้หลัง protocol ทั้งหมด ตอน macOS 27 ออกจึงควรเป็นการเปลี่ยน implementation ไม่ใช่การรื้อ
- **provenance ที่ผูกตั้งแต่ตอน ingest ย้อนกลับมาใส่ทีหลังไม่ได้** — ถ้าจะได้ citation ที่เชื่อได้ ต้องเก็บตั้งแต่วันแรก นี่คือเหตุผลที่ยอมช้าตอนต้น
- **ทำงานบนเครื่องตัวเอง = ใช้กับข้อมูลที่ส่งออกไปไม่ได้** — เมื่อโมเดลบนเครื่องเก่งขึ้นตามเวลา โครงที่วางไว้ให้รันในเครื่องได้ตั้งแต่ต้นจะได้ประโยชน์เต็ม ๆ โดยไม่ต้องแก้สถาปัตยกรรม
- **หลักฐานที่เก็บไว้ต่อ task เป็นวัตถุดิบของสิ่งที่ยังไม่ได้ทำ** — span, ledger, evidence, conflict ที่บันทึกไว้แล้ว คือฐานของ eval/replay/รายงานความน่าเชื่อถือในอนาคต

## 5. AI เขียน 100% หมายความว่าอะไร

**โค้ด เทส สคริปต์ และเอกสารทั้งหมดในรีโปนี้เขียนโดย AI (Claude Code)** ไม่มีบรรทัดไหนที่คนพิมพ์เอง commit ทุกอันเป็นงานของ AI แม้ชื่อผู้ commit จะเป็นเจ้าของเครื่อง

สิ่งที่คนทำ: ตั้งเป้าหมาย · ตัดสินใจเชิงสถาปัตยกรรม · **กดหน้าจอจริงเพื่อหาบั๊กที่เทสมองไม่เห็น** · บอกว่าอะไรยังไม่ดีพอ

ข้อสังเกตที่บันทึกไว้ระหว่างทาง และเป็นเหตุผลที่กฎใน `check.sh` มีหน้าตาแบบนี้:

- **"มีโค้ดแล้ว" ไม่เท่ากับ "มีฟีเจอร์"** — เกิดขึ้นแล้ว **6 ครั้ง**ในโปรเจกต์นี้: โค้ดครบ เทสเขียว แต่ไม่มีทางเรียกใช้จากแอปได้เลย (ครั้งล่าสุดคือทูล `ingest_url` ที่มีชื่ออยู่ในแผนแต่ไม่มีตัวตน) จึงต้องมีกฎที่ตรวจว่าความสามารถ *เข้าถึงได้จากแอป* ไม่ใช่แค่จากเทส
- **การกดหน้าจอจริงเจอสิ่งที่เทสไม่เจอเสมอ** — รอบต่าง ๆ เจอบั๊กที่เทสมองไม่เห็น 8, 10, 5, 7, 7 และ 3 ตัวตามลำดับ · รอบที่เจอ 3 ตัวเกิดขึ้นตอนเทส 966 ตัวเขียวอยู่แล้ว · บันทึกทุกรอบไว้ที่ [`docs/DRIVING_LOG.md`](docs/DRIVING_LOG.md)
- **เทสที่ใช้ข้อมูลตัวอย่างสวยเกินจริงจะผ่านตลอด ในขณะที่ของจริงพัง** — บั๊กหนึ่งซ่อนอยู่ได้เพราะเทสใช้ id ว่า `"eng-1"` ส่วนของจริงเป็น UUID
- ข้อตกลงที่ขอไม่ยืดหยุ่นข้อเดียวของโปรเจกต์: **ห้าม mark งานเป็นเสร็จถ้ายังมีรายการค้าง** ทุกรายการค้างถูกเขียนไว้ในแผน

**เดินได้ทั้งเส้นแล้ว** และตรวจได้ว่าเดินได้จริงแค่ไหน

| | |
|---|---|
| งานตามแผน | 119 งาน — **73 งานผ่าน Done-when แล้ว · 29 งานมีโค้ดลงแล้วแต่ยังมีรายการ "ค้าง" เขียนกำกับไว้ · 17 งานยังไม่เริ่มเลย** (ทั้ง P12 กับ P14 และครึ่งหนึ่งของ P9) |
| ชุดทดสอบ | **1,029 ตัว / 183 suite** รันกับของจริงทั้งหมด — SurrealDB จริง, DuckDB จริง, SQLite จริง, โมเดลจริง (on-device + MLX), Python จริง, process/สัญญาณ/sandbox จริง, MCP server จริง, HTTP จริง |
| กฎเชิงโครงสร้าง | `scripts/check.sh` fail ถ้าโครงพัง (ดู [§2.4](#24-invariant-บังคับด้วยโครงสร้าง-ไม่ใช่วินัย)) |

### เดินได้แล้ว — ยืนยันบนแอปจริง ไม่ใช่แค่ในเทส

**แกนกลาง** — แชท → router สลับ tier เอง → tool call → hook chain → อนุมัติจาก GUI/Telegram/Discord/LINE ช่องไหนก็ได้ → `run_shell` ใน sandbox → span ลง SurrealDB ·
ทีม 4 บทบาท + QA loop + ledger · MCP client + ปลั๊กอิน · Siri/Shortcuts · เขียน skill เองผ่าน gate ปกติ

**ความรู้และข้อมูล** — คลังความรู้ (PDF/DOCX/PPTX/OCR, chunker+tokenizer ไทย, hybrid search, provenance ต่อ chunk) · การ์ดข้อขัดแย้งที่ระบบยกขึ้นมาเอง ·
**ค้นเว็บได้จริงในแอปที่ sandbox** พร้อมจัดชั้นแหล่ง T1–T5 และอ่านเนื้อหาหน้าเว็บจริงก่อนอ้างอิง · สมุดงาน SQL/Python + DB explorer + แผ่นยืนยันที่โชว์คำสั่งคำต่อคำ

**โปรเจกต์เป็น first-class** — 5 ขั้น + stage gate ที่ปฏิเสธทูลผิดขั้นจริง · WBS ผูกกับ ledger · RACI · tolerance 6 แกนที่หยุดงานได้ ·
baseline + change control · ทะเบียน 5 ตัว · รายงาน 3 แบบที่สร้างจากแถวจริง · แถบสถานะที่กดแล้วตัดสินใจได้

**งานวิจัย** — ออกแบบแบบสอบถามพร้อมผัง ข้อ↔construct↔คำถามวิจัย · ประตูความตรงเชิงเนื้อหา (IOC/CVI) ที่ต้องผ่านก่อนใครตอบแม้แต่คนแรก ·
**เปิดฟอร์มให้คนอื่นกรอกผ่าน LAN** พร้อมหน้าความยินยอม กรอกต่อทีหลังได้ และรหัสนิรนามที่แยกไฟล์+เข้ารหัส ·
α/ω · EFA · ICC · κ ระหว่างผู้ลงรหัส · ต้นฉบับ 5 บทที่ตัวเลขในบทที่ 4 **ผูกกลับถึงเซลล์ที่รันจริง ปลอมไม่ได้** ·
เอกสาร `.docx`/`.pptx` จริง + citation ผูก provenance + ส่วนข้อจำกัดที่เขียนตัวเอง

### ยังไม่ได้ — ควรรู้ก่อนลอง

- **ยังเซ็นแบบ ad-hoc** — Gatekeeper บนเครื่องอื่นจะปฏิเสธ ต้อง build จาก source เอง (ยังไม่ notarize เพราะยังไม่มี Developer ID)
- **macOS 26 + Apple Silicon เท่านั้น** และต้องมี Xcode 26 + Metal Toolchain เพื่อ build
- **หน้าจอยังไม่ครบ**: **Workflow Builder** กับ **File Viewer/Editor** ยังไม่ได้ทำเลย · หน้า Settings กับ Processes มีแล้วแต่ไม่ครบทุกหมวด — ตั้งค่าบางอย่าง (บัญชีบอต, connector, MCP server) ยังต้องแก้ไฟล์ JSON/plist เอง
- **ข้อจำกัดของ App Sandbox ที่วัดแล้ว**: แอปมองไม่เห็น `/opt/homebrew`, `/usr/local` และ `~/.lmstudio` → notebook ได้ Python จาก Command Line Tools ที่ไม่มี pandas/numpy (สถิติของแอปจึงเขียนเองใน Swift ทั้งชุด ไม่พึ่ง Python)
- **คุณภาพขึ้นกับเครื่อง** — บนเครื่อง 16 GB ชั้นในเครื่องคือโมเดล 4B ซึ่งพอสำหรับงานเบา งานจริงต้องต่อ endpoint · ยังไม่เคยทดสอบกับ API ที่คิดเงิน
- **secret ของ endpoint/connector/บอต ยังอยู่ใน environment variable ไม่ใช่ Keychain** (P9.3 ยังไม่ทำ — เก็บแค่*ชื่อ*ตัวแปรลงไฟล์ ไม่ใช่ค่า) · คีย์ที่ผูกคำตอบกับตัวผู้เข้าร่วมอยู่ใน Keychain แล้ว · **ยังไม่มี security review — ข้อนี้สำคัญที่สุดเพราะแอปรับข้อมูลจากคนนอกได้แล้ว**
- ยังไม่มี read/write file เป็นทูล · ยังไม่มี graph view ของ entity/relation · การสกัด entity ภาษาไทยยังได้ clause ปนมา · ไม่มี plot/แผนภูมิ · ยังไม่มีหน้าจอ*ประกอบ*ต้นฉบับ (ทางส่งออกพร้อมแล้ว) · ไม่มี multi-user/sync/แอปมือถือ

## 7. เริ่มใช้งาน

```bash
xcodebuild -downloadComponent MetalToolchain   # ครั้งเดียวต่อเครื่อง (Xcode 26 แยกเป็น component)
./scripts/fetch-helpers.sh   # ดึง sidecar binary (ครั้งเดียวต่อเครื่อง — vendor/ ไม่อยู่ใน git)
./scripts/build-metallib.sh  # คอมไพล์ Metal kernel ของ MLX (ครั้งเดียว; rebuild ~4 วิ)
./scripts/check.sh           # build + test + embedding model + structural rules
./scripts/build-app.sh       # ประกอบและเซ็น .app พร้อม App Sandbox + ตรวจว่าพาไปเครื่องอื่นได้
```

**เครื่องใหม่**: ต้องรัน `fetch-helpers.sh` ก่อน ไม่งั้นเทสฝั่ง Persistence จะข้าม และแอปจะเริ่มฐานข้อมูลไม่ได้ ·
ต้องมี Metal Toolchain + รัน `build-metallib.sh` ไม่งั้นโมเดล embedding โหลดไม่ขึ้น (`Failed to load the default metallib`) —
SwiftPM คอมไพล์ Metal shader ไม่ได้ จึงต้องมีขั้น `xcodebuild` แยกไว้ทำอย่างเดียว
([ARCH E.13](docs/VERIFICATION_LOG.md#e13-bge-m3-ในโปรเซสเราเอง--รันได้จริง--เจอกับดักสำคัญ-2026-08-11))

endpoint ของ Tier 1 ตั้งใน `bootstrap.plist` ที่
`~/Library/Containers/com.coaiworkspace.app/Data/Library/Application Support/CoAIWorkspace/`
(คีย์ `selfHostedEndpoint` + `selfHostedModel`) — เป็นค่าต่อเครื่อง ไม่ได้อยู่ใน repo

### การแจกจ่าย

`build-app.sh` จบด้วย `package-audit.sh` ซึ่งตรวจเฉพาะสิ่งที่ **ผ่านบนเครื่องนี้เสมอ ไม่ว่าจะพาไปเครื่องอื่นได้หรือไม่**:
resource bundle ของ SwiftPM ทุกอันที่ binary อ้างถึงต้องอยู่ในแอป · ไม่ลิงก์ dylib นอกระบบ · sidecar/Metal kernel/`Metadata.appintents` ต้องครบ · ลายเซ็นและ App Sandbox ต้องผ่าน

การแจกจริงต้องมี **Developer ID** ของเจ้าของแอปแล้วทำสองขั้นนี้เพิ่ม (ต้องมีบัญชี Apple Developer จึงทำแทนกันไม่ได้):

```bash
codesign --force --deep --options runtime --timestamp \
  --sign "Developer ID Application: ชื่อคุณ (TEAMID)" \
  --entitlements Resources/CoAIWorkspace.entitlements "build/Co-AI Workspace.app"
xcrun notarytool submit "build/Co-AI Workspace.app" --wait \
  --apple-id you@example.com --team-id TEAMID --password <app-specific-password>
xcrun stapler staple "build/Co-AI Workspace.app"
```
