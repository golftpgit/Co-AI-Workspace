## กฎแม่ 6 ข้อ — ใช้ตัดสินทุกข้อขัดแย้ง

เต็มอยู่ที่ [`RULES.md`](../../../RULES.md) · หกข้อนี้ต้องอยู่ในหัวตลอด

| | กฎ | แปลว่าอะไรในทางปฏิบัติ |
|---|---|---|
| **M1** | "มี implementation" ≠ "มี feature" | สร้างความสามารถแล้ว **ต้องหาเส้นทางจากผู้ใช้ถึงมันให้เห็น** — ไม่งั้นยังไม่เสร็จ · เกิดซ้ำมาแล้ว 9 ครั้ง |
| **M2** | "เทสเขียว" ≠ "ใช้งานได้" | งานที่มีหน้าจอต้องถูกกดจริงบน `.app` ที่ build + sandbox แล้ว |
| **M3** | "เขียว" ≠ "ตรวจครบ" | รายงานผลต้องบอกทุกครั้งว่า **ข้ามอะไรไป** |
| **M4** | กฎที่ไม่มีเครื่องบังคับ = ความตั้งใจ | กฎใหม่ต้องมีตัวบังคับใน `scripts/check.sh` |
| **M5** | ความเงียบคือความล้มเหลวที่แพงที่สุดที่นี่ | อะไรที่พลาดแล้วไม่มีใครรู้ ต้องทำให้ดังขึ้น |
| **M6** | ตัวเลขที่อ้าง ต้องวัดเอง | ห้ามเขียน "น่าจะเร็วขึ้น" — วัดแล้วเขียนตัวเลขลง `docs/VERIFICATION_LOG.md` |

## ขั้นตอนของงานทุกชิ้น

```
1. อ่านเอกสารที่ START_HERE §3 ชี้ให้   ← อย่าข้าม อย่าอ่านเกิน
2. เช็ค docs/DECISIONS.md               ← เรื่องนี้เคยถูกตัดสินไปแล้วหรือยัง
3. เขียนโค้ด + เทส
4. ./scripts/check.sh                    ← ต้องเขียว ไม่มีข้อยกเว้น
5. ถ้ามีหน้าจอ: ./scripts/build-app.sh แล้วกดจริง → บันทึก docs/DRIVING_LOG.md
6. อัปเดต docs/plan/pNN.md ของเฟสนั้น
```

## กับดักที่โปรเจกต์นี้ตกมาแล้ว — อย่าตกซ้ำ

| เรื่อง | อย่าทำ | ทำแทน |
|---|---|---|
| **เรียกทูล** | เรียก `AgentTool.call` ตรง ๆ | ผ่าน `ToolGateway` เท่านั้น — `check.sh` แดงถ้าไม่ทำ |
| **สร้างความสามารถใหม่** | จบที่เทสผ่าน | ต่อเข้า `Engine.swift` **และ** ให้มีหน้าจออ่าน |
| **หน้าจอ** | เขียน `.padding(12)` · `Color(red:)` · `.ultraThinMaterial` เอง | ใช้ `Space` · `Radius` · `.surface(_:)` จาก `DesignTokens.swift` |
| **ตัวเลขบนจอ** | วางบนชั้นแก้ว | พื้นทึบเสมอ — ค่า p ที่อ่านผิดคือความเสียหายที่แก้ไม่ได้ |
| **เทส** | เดาพอร์ตแล้ว bind · ใช้ `Task.sleep` รอ | port 0 แล้วถามระบบ · รอสัญญาณ |
| **เทส flaky** | รันใหม่จนเขียว | หาสาเหตุ — มักคือ RAM |
| **เพดานบริบท** | เขียนตัวเลขตายในโค้ด | อ่าน `max_model_len` จาก `/v1/models` |
| **ความคิดของโมเดล** | `text += reasoning` | ส่งเป็น event แยก — ไม่งั้นมันถูกบันทึกเป็นคำตอบ |
| **เอกสาร** | ปล่อยไฟล์โตเกิน 200 KB | แยกเป็นโฟลเดอร์ — `check.sh` แดง |

## สถานะที่ต้องรู้ก่อนเชื่อคำว่า "เขียว"

`check.sh` วันนี้ **ข้ามด่าน Tier 1 ทั้งด่าน** เพราะค่าเริ่มต้นชี้ไป LM Studio ที่ดับ ขณะที่ GX10 เปิดอยู่และใช้ได้ ([`docs/AUDIT_2026-08-17.md`](../../../docs/AUDIT_2026-08-17.md) F-2)

⇒ **อ่าน "เขียว" ว่า "ยังไม่พบว่าพัง ในส่วนที่ตรวจ"** จนกว่างานข้อ 1 ในคิวจะเสร็จ

## เขียนโค้ดสไตล์ไหน

| | |
|---|---|
| **ภาษา** | โค้ดและคอมเมนต์เป็นอังกฤษ · ข้อความบน UI และเอกสารเป็นไทย |
| **คอมเมนต์** | อธิบาย **ทำไม** ไม่ใช่ **อะไร** — และถ้าเคยมีบั๊กตรงนั้น ให้เขียนอาการไว้ด้วย นั่นคือสิ่งที่กันไม่ให้คนถัดไปแก้กลับ |
| **Concurrency** | Swift 6 strict · ห้าม `[String: Any]` บน `Sendable` · view model ห้าม I/O บน main actor |
| **ขนาดไฟล์** | ตามที่มีอยู่ — โมดูลใหญ่สุดคือ `CoAIWorkspaceApp` (51 ไฟล์) |

## เขียนเอกสารสไตล์ไหน

| | |
|---|---|
| **เอกสารข้อเท็จจริง** (สเปก · กฎ · แผน · protocol) | เก็บ **อะไร · อย่างไร · เพราะอะไร** ของสถานะปัจจุบัน · ผิดเมื่อไรให้แก้ทับ |

| **ตาราง** | ช่องสถานะต้องกวาดตาได้ — เหตุผลยาว ๆ ไปอยู่หัวข้อข้างล่างในไฟล์เดียวกัน |
| **ห้ามลบ** | จัดใหม่ = ย้าย + ทิ้งลิงก์ไว้ ไม่ใช่ลบ |
| **ทุกครั้งที่เพิ่มไฟล์** | เพิ่มแถวใน `START_HERE.md` §4 ด้วย ไม่งั้นไม่มีใครหาเจอ |
