### 22. Engineering Notes — SurrealDB v3 quirks

รวมจุดที่ SurrealDB v3.2.4 มี syntax/behavior ต่างจาก docs ทั่วไปที่เจอจริงระหว่าง implement `kb-store` (ย้ายมาจาก [ARCHITECTURE.md §9](ARCHITECTURE.md#9-graphrag-ingestion-pipeline) เพื่อไม่ให้ spec section ยาวเกินจำเป็น) — เก็บไว้ที่นี่เพื่อกันคนที่แก้โค้ดจุดนี้ทีหลังเจอปัญหาเดิมซ้ำ:

- **Implementation notes (v3.2.4, ยืนยันจากการ scaffold จริง)**: connect ด้วย `Surreal::new::<SurrealKv>(path)` แต่ตัว handle ที่เก็บไว้เป็น `Surreal<Db>` (ชนิด connection ไม่ใช่ engine marker); struct ที่ implement แค่ `serde::Serialize`/`Deserialize` เฉยๆ ต้องห่อด้วย `surrealdb::types::SerdeWrapper` ก่อนส่งเข้า `.bind()`/`.take()` เพราะ v3 เปลี่ยนมาใช้ trait `SurrealValue` ของตัวเอง; query ผ่าน HNSW index ต้องใช้ operator `<|k,ef|>` (เช่น `<|5,40|>`) ไม่ใช่ `<|k|>` เฉยๆ (แบบเก่าถูกถอดออกแล้ว); **`RELATE type::record(...)->edge->type::record(...)` parse ไม่ผ่าน** ("Unexpected token `::`, expected :") — grammar ของ `RELATE` ต้องการ graph-expression operand ตรงตำแหน่งนั้น ไม่ใช่ function call ตรงๆ ต้อง bind แต่ละฝั่งเข้า `LET` param ก่อน แล้วค่อย `RELATE $src_rec->edge->$tgt_rec` (พบและแก้ตอนสร้าง entity/relation graph, [§17.1](LOG_ARCHIVE.md#231-feature-gaps--user-feedback-audit-บันทึกดั้งเดิม-2026-08-08) #5, ดูตัวอย่างจริงใน `KbStore::create_relation`); **`CREATE ... CONTENT $data` ที่ bind `$data` เป็น raw `serde_json::Value` (ไม่ห่อ `SerdeWrapper`) ทำให้ field ตัวเลข/array (เช่น `embedding: Vec<f32>`) กลับมาอ่านไม่ได้ทีหลัง** ("invalid type: unit value, expected u32") แม้ query ตอน insert จะผ่าน — ต้อง bind struct ที่ derive `Serialize`/`Deserialize` จริงห่อด้วย `SerdeWrapper` เหมือนกับ path อื่นๆ เสมอ อย่า `serde_json::json!({...})` ตรงๆ แล้วส่งเข้า `.bind()` (พบตอนทำ `KbStore::import_chunk`, [§17.1](LOG_ARCHIVE.md#231-feature-gaps--user-feedback-audit-บันทึกดั้งเดิม-2026-08-08) #5.6); **full-text index clause คือ `FULLTEXT ANALYZER <name> BM25(k1,b) HIGHLIGHTS`ไม่ใช่ `SEARCH ANALYZER ...`** แบบที่ general SurrealDB docs (เวอร์ชันเก่ากว่า) อธิบายไว้; **`ORDER BY search::score(1)` parse ไม่ผ่าน** ("Unexpected token `::`, expected Eof") เพราะ `ORDER BY` รับแค่ plain field/idiom ไม่รับ function-call expression ตรงๆ — ต้อง project เป็น field ก่อนด้วย `SELECT *, search::score(1) AS relevance ... ORDER BY relevance DESC` (พบตอนทำ BM25 full-text search, [§17.2](LOG_ARCHIVE.md#232-โค้ดจริงเบี่ยงจากแผนเดิมของเอกสารนี้เอง-บันทึกดั้งเดิม-2026-08-08) D7, ดูตัวอย่างจริงใน `KbStore::bm25_search`) — ทั้งหมดตรวจสอบผ่าน integration test จริงใน [kb-store](agent-workspace/crates/kb-store) แล้ว
