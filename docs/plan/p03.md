### P3.1 — SearXNG sidecar

**สถานะ**

🔄 **ปิดแถวนี้: ถูกแทนที่ด้วย P13.1 แล้ว ไม่ใช่ของค้าง (ตรวจซ้ำ 2026-08-17)**

- ติดตั้งและค้นได้จริงแล้ว — SearXNG 2026.8.10 ใน `vendor/searxng/venv` + `scripts/fetch-searxng.sh`/`run-searxng.sh`
- `SearXNGSource` คืนผลพร้อม tier ของ**ผู้เผยแพร่** (ไม่ใช่ของ search engine)
- **ค้นภาษาไทยได้จริง**
- 🔴 **PyPI ชื่อ `searxng` ไม่ใช่ SearXNG** — เป็น MCP server ของบุคคลที่สามที่ใช้ชื่อซ้ำ (ลองติดตั้งแล้วได้ 40 แพ็กเกจที่ไม่เกี่ยว ไม่มี search engine) ต้องลงจาก git เท่านั้น
- build ต้องปิด isolation + ลง `msgspec`/requirements ก่อน เพราะ backend ของมัน import ตัวเองตอน build
- · **ต่อเข้า `SidecarManager` แล้ว** (health probe/restart/teardown เหมือน `surreal`, readiness 45 วิเพราะโหลด engine ~70 ตัวก่อนตอบ) ตั้ง path ผ่าน `searxngPython` ใน `bootstrap.plist`
- 🔄 **ถูกแทนที่แล้วโดย P13.1 (2026-08-14)** — venv ของ Python **ย้ายที่ไม่ได้** (สคริปต์ข้างในฝัง absolute path) จึงก๊อปเข้า `.app` ตรงๆ ไม่ได้ → Done-when ข้อ "user ไม่ต้องติดตั้งอะไรเอง" **ไม่มีวันผ่านด้วยทางนี้** จึงไม่ใช่งาน packaging ของ P9.6 อีกต่อไป
- T5 เดินผ่านสะพาน `WKWebView` แทน ซึ่งผ่าน Done-when ข้อนั้นแล้ว
- `SearXNGSource` **ยังอยู่และใช้ได้** ถ้าผู้ใช้รัน SearXNG เองไว้ — เก็บไว้ในฐานะ provider ทางเลือก ไม่ใช่ทางหลัก

### P3.3 — Tier 1–3 API clients

**สถานะ**

✅ **ยิง API จริงผ่านหมด**

- OpenAlex, Crossref, PubMed (esearch+esummary 2 ครั้ง), medRxiv (by DOI)
- ทุกแถวมี tier/url/accessedAt ครบตาม Done-when
- **เจอจากการยิงจริง 3 ข้อ**: (1) `doi.org` เป็นแค่ตัว redirect ไม่มีตัวตนเชิงบรรณาธิการ → เปเปอร์ peer-reviewed จะได้ T5 เท่าบล็อก แก้ด้วยการใช้ tier ของ index ที่หาเจอแทนเมื่อ URL เป็น DOI (ตรงกับตาราง §1.2 ที่บอกว่า OpenAlex/Crossref/PubMed = T2) แล้ว `fetch_page` จะประเมินใหม่ตอนตาม DOI ไปถึงสำนักพิมพ์จริง
- (2) **medRxiv ไม่มี API ค้นด้วยคำค้นเลย** ตอบได้แค่ตาม DOI/ช่วงวันที่ → `search` โยน error ตรงๆ แทนที่จะคืน preprint ล่าสุดมั่วๆ ให้ดูเหมือนผลค้นหา
- (3) **Semantic Scholar ติด 429 ตั้งแต่ request แรก** สำหรับผู้เรียกที่ไม่มี key → แยกเป็น `rateLimited` ให้ต่างจาก "ไม่มีผลลัพธ์"
- preprint เป็น T3 เสมอไม่ว่าจะหาเจอจากที่ไหน (การถูก index ไม่ใช่การ review)
- 7 เทส (live เป็น opt-in)

### P3.4 — `fetch_page`

**สถานะ**

- ✅ **ยิงเว็บจริงผ่านครบ 5 แห่ง**: RFC (`text/plain`), Wikipedia (317 ย่อหน้า), arXiv, MDN (63), WHO (131) + PDF ของ arXiv
- คืนเป็น**ย่อหน้า** ไม่ใช่ก้อนเดียว
- tier คิดจาก URL **ปลายทางหลัง redirect**
- บล็อก `file://`
- **เจอจากการยิงจริง 3 ข้อ**: (1) `text/plain` อ่านไม่ได้เลยเพราะโยนเข้า HTML extractor — แก้แล้ว (2) `ietf.org/rfc/*` redirect ไป `rfc-editor.org` ที่ไม่มีในทะเบียน — เพิ่มแล้ว (3) **หน้าที่ render ด้วย JS อ่านไม่ได้** (swift.org, developer.apple.com ส่ง HTML เปล่า) → เพิ่ม `FetchError.needsJavaScript` บอกตรงๆ แทนที่จะรายงานว่าเป็นหน้าบาง
- เทสยิงเน็ตเป็น opt-in (`COAI_TEST_NETWORK=1`), เทส extractor 7 ตัวรัน offline เสมอ

### P3.5 — `ingest_url`

**สถานะ**

✅ **(แก้สถานะ 2026-08-12: เคยถูก mark ✅ ทั้งที่ทูลชื่อเดียวกับ task ไม่มีอยู่จริง

- `grep URLIngestor` เจอไฟล์ตัวเองไฟล์เดียว ไม่มีทูล ไม่มี UI เอื้อมถึงจากที่ไหนไม่ได้เลย D6 ครั้งที่หก · ตอนนี้มี `IngestURLTool` เรียกผ่าน gateway ได้จริงและอยู่ใน tool list ของ Researcher)** `URLIngestor` — ค้นเจอใน KB พร้อม tier ที่มาจาก **source registry ผ่านหน้าเว็บ ไม่ใช่จาก caller** (ถ้าให้ caller ส่ง tier มาได้ คำว่า T1 จะแปลว่า "คนที่ ingest บอกว่าใช่")
- citation ชี้ระดับย่อหน้าได้ (`page` + `section`)
- ingest ซ้ำเพิ่ม 0 chunk
- scope ตรงตามที่สั่ง
- หน้าที่อ่านไม่ได้ไม่ทิ้ง chunk ครึ่งๆ ไว้
- แยก `PageReading` เป็น protocol ให้เทสได้โดยไม่ต้องพึ่งเว็บคนอื่น
- 6 เทส

### P3.6 — Conflict Ledger

**สถานะ**

✅ **ผ่าน Done-when ทั้ง 3 ข้อ (10 เทส · ตรวจซ้ำ 2026-08-17)**

- และข้อแรกพิสูจน์บนหน้าจอจริงแล้วด้วย — ต่างกันชัด (T1/2026 vs T5/2019) ตัดสินเอง แต่ยัง**บันทึกว่าเคยขัดกัน**, ก้ำกึ่งยกให้คน, ตัดสินแล้วครั้งถัดไปคืนคำตัดสินเดิม, แหล่ง tier สูงกว่าเปิดใหม่ได้/แหล่งอ่อนกว่าเปิดไม่ได้
- น้ำหนักคืนเป็น**เหตุผลรายข้อ**ไม่ใช่แค่ตัวเลข
- แหล่งอ่อน 10 แหล่งไม่ชนะ T1 หนึ่งแหล่ง และปีใหม่ไม่ชนะ tier
- · **`ConflictDetector` เสร็จแล้ว** (7 เทส) — ถามโมเดลด้วย structured output, ถามเฉพาะคู่ที่ retrieval หยิบมาคู่กันอยู่แล้ว, **ไม่แน่ใจ = ไม่ขัดแย้ง** (การ์ดปลอมทำให้ผู้ใช้เลิกอ่านการ์ด รวมถึงใบจริง), **โมเดลล่ม ≠ สองแหล่งตรงกัน**, ข้าม chunk จากเอกสารเดียวกัน
- · **persist ลง SurrealDB แล้ว** (ตาราง `conflict`, 4 เทสกับ DB จริง) — เก็บข้อความทั้งสองฝั่ง **verbatim** ไม่ใช่อ้างอิงถึง chunk เพราะข้อขัดแย้งอยู่ได้นานกว่าเอกสารที่ทำให้เกิด และเก็บ**เหตุผลของน้ำหนักตามที่เขียนไว้ตอนนั้น** ไม่ใช่คำนวณใหม่ — ข้อนี้เคยเป็นแค่ความตั้งใจ ตอนนี้บังคับด้วย `recordDecision` ที่เขียนเฉพาะคำตัดสิน และมีเทสที่จำลอง "ชั่งไว้เมื่อปีก่อน" คอยจับ (U11)
- ✅ **ต่อเข้าเส้นทางจริงแล้ว (2026-08-11)** — `Engine` สร้าง detector, `KnowledgeViewModel` review ทุกครั้งที่ ingest โดยยิงคำถามจาก chunk ใหม่แล้วให้ detector ดูเฉพาะเพื่อนบ้านที่ retrieval คืนมา (จำกัด 5 chunk × 3 เพื่อนบ้าน เพราะทุกคู่คือ model call ระดับ high-impact) ที่ตัดสินไปแล้วไม่ถูกยกซ้ำ
- **พิสูจน์ Done-when ข้อแรกบนหน้าจอจริงแล้ว**: ป้อนเอกสารขัดกัน 2 ฉบับ (ไทย/อังกฤษ เรื่องระยะเวลาให้ยาต่อหลังผ่าตัด) → ขึ้น "พบความรู้ที่ขัดกัน 1 จุด" และการ์ดโผล่เอง

### P3.7 — Conflict UI

**สถานะ**

- 🔶 **โค้ดครบทุกแถวของตาราง §11.6
- ขับหน้าจอจริงแล้ว (2026-08-11)** — การ์ดแสดงข้อความ**ทั้งสองฝั่งคำต่อคำ** + ที่มาพร้อม tier/ปี/วันที่เข้าถึง + เหตุผลของน้ำหนักรายข้อ + ข้อเสนอของระบบที่**ระบุฝั่งและเหตุผล** พร้อมกำกับว่าเป็นข้อเสนอ ไม่ใช่ข้อสรุป + 4 ทางเลือก (A / B / ถูกทั้งคู่ในบริบทต่างกัน **บังคับระบุเงื่อนไข** / ยังไม่ตัดสิน) + เลือกได้ว่าผูกเฉพาะโปรเจกต์หรือเป็นคำตัดสินกลาง
- กดตัดสินจริงแล้วบันทึกและไม่ถามซ้ำข้ามการรีสตาร์ท (U9)
- sheet เปิดที่ฝั่งที่ระบบเสนอ ไม่ใช่ฝั่ง A เสมอ
- **ประวัติที่กลับคำตัดสินได้ทำแล้ว (2026-08-16, 2 เทสกับ SurrealDB จริง + 1 กฎ)**: ตาราง `conflict_decision` **เขียนเพิ่มอย่างเดียว** — การกลับคำตัดสินคือการเขียนแถวใหม่ ไม่ใช่การ UPDATE ทับ เพราะประวัติที่แก้ได้ไม่ใช่ประวัติ มันคือความเห็นปัจจุบันที่มีเวลาแปะไว้
- **การเปิดใหม่ก็เป็นคำตัดสินหนึ่ง** และ**ต้องมีเหตุผล** (ปฏิเสธถ้าเว้นว่าง) เพราะการกลับคำตัดสินที่ไม่มีเหตุผลแยกไม่ออกจากการกดผิดเมื่อมีคนมาอ่านในอีกหกเดือน
- การ์ดกางประวัติได้และมีปุ่มกลับคำตัดสินตรงนั้น เพราะการ์ดคือที่ที่คนยืนอยู่ตอนรู้ว่าตัดสินผิด
- โหลดประวัติเมื่อกางเท่านั้น ไม่ใช่ query ต่อการ์ดทุกครั้งที่ reload
- **หัวการ์ดแก้แล้ว (2026-08-16, 6 เทส)**: `ConflictHeadline` — หัวการ์ดต้อง*เกี่ยวกับสองข้อความนั้น* ไม่ใช่สิ่งที่ผู้ใช้พิมพ์ลงช่องค้นหา
- ประโยคคำสั่ง ("จง…", "ช่วย…หน่อย", "summarize…") ไม่ใช่คำถามเกี่ยวกับแหล่ง และหัวเรื่องที่ไม่มีคำร่วมกับข้อความทั้งสองเลยคือหัวเรื่องของเรื่องอื่น — ทั้งสองกรณีถูกแทนด้วย**ข้อความจริงของสองฝั่ง** ซึ่งอ้างคำพูดมาตรง ๆ จึงพูดผิดเกี่ยวกับสิ่งที่อยู่บนการ์ดไม่ได้
- เป็น computed property ⇒ การ์ดที่ถูกบันทึกไว้ก่อนกฎนี้ถูกซ่อมตอนขึ้นจอ ไม่ใช่ค้างชื่อผิดถาวรเพราะเคยเขียนลงไปครั้งหนึ่ง
