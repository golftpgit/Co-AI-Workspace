### ตรวจความครอบคลุมเทียบ Bland, *An Introduction to Medical Statistics*

เจ้าของแอปตั้งเกณฑ์ไว้ว่า **สถิติในระบบอย่างน้อยต้องครอบคลุมตามหนังสือเล่มนี้** (2026-08-16) · ไล่ทีละบทแล้วเทียบกับของที่มี:

| บท | หัวข้อ | สถานะ |
|---|---|---|
| 4–8 | สรุปข้อมูล · การแจกแจงปกติ · ช่วงเชื่อมั่น | ✅ `Statistics` (mean/median/sd/quantile, normal, t, F, χ²) |
| 9–10 | การทดสอบนัยสำคัญ · t สามแบบ | ✅ `StatGate` (Student/Welch/paired) พร้อมตรวจ assumption |
| 11 | การถดถอยและสหสัมพันธ์ | ✅ regression เดิม · **สหสัมพันธ์เพิ่มใหม่ (2026-08-16)** |
| 12 | วิธีอันดับ | ✅ Mann–Whitney · Wilcoxon · Kruskal–Wallis · **Spearman เพิ่มใหม่** |
| 13 | ตารางไขว้ | ✅ χ² · Fisher · **McNemar และ χ² for trend เพิ่มใหม่** |
| 15 | หลายปัจจัย | ✅ multiple/logistic regression · ANOVA · Cox |
| 16 | เวลาถึงเหตุการณ์ | ✅ Kaplan–Meier · log-rank · Cox + Schoenfeld |
| 17 | meta-analysis | ✅ fixed/random · I²/τ² · Egger |
| 18 | ขนาดตัวอย่าง | ✅ สองค่าเฉลี่ย · สองสัดส่วน · power |
| 19 | ข้อมูลขาด | ✅ **เพิ่มใหม่ (2026-08-16)** `MissingData` — นับรูโหว่ต่อตัวแปรและต่อแถว และทดสอบว่าคนที่ขาดต่างจากคนที่ไม่ขาดไหม · **ไม่เติมค่าให้** |
| 20 | การวัดทางคลินิก | ✅ Bland–Altman · sensitivity/specificity/PPV/NPV/LR/AUC · ICC · **κ (รวมแบบถ่วงน้ำหนัก) เพิ่มใหม่** |
| 21 | สถิติการตาย | ✅ อัตราปรับมาตรฐานตามอายุ (direct) เดิม · **SMR (indirect, ช่วง exact Poisson) และตารางชีพ เพิ่มใหม่ (2026-08-16)** |
| 22 | การทดสอบหลายครั้ง | ✅ **เพิ่มใหม่**: Bonferroni · Holm · Benjamini–Hochberg |

**ที่เพิ่มรอบนี้ (19 เทส)** — สหสัมพันธ์ Pearson/Spearman พร้อมช่วงเชื่อมั่นแบบ Fisher z (**ช่วงสมมาตรรอบ r = 0.99 จะทะลุ 1 ซึ่งไม่ใช่ค่าสหสัมพันธ์**) และประโยคที่ติดมากับทุกผลว่า **ความสัมพันธ์ไม่ใช่ความสอดคล้อง** (เครื่องมือที่อ่านเป็นสองเท่ากันเป๊ะ ๆ ได้ r = 1.00 และไม่ตรงกันสักค่า — บทที่ 20 มีอยู่เพราะความผิดพลาดนี้) · **κ** ที่หักความตรงกันจากความบังเอิญออก (ผู้ให้คะแนนสองคนที่ตอบว่า "ไม่ใช่" 95% ตรงกัน 90% ด้วยความบังเอิญล้วน) · **McNemar** ที่นับเฉพาะคู่ที่เปลี่ยน และ**เลือก exact เองเมื่อคู่ที่เปลี่ยนน้อยกว่า 25** (การทดสอบที่ถูกต้องเฉพาะตอนที่มีคนนึกออกว่าต้องขอ คือการทดสอบที่มักผิด) · **χ² for trend** ที่ถามว่าสัดส่วนไล่ตามลำดับไหม ไม่ใช่ว่ากลุ่มไหนต่างจากกลุ่มไหน (และรับคะแนนขนาดยาจริงได้ เพราะ 10/20/100 มก. ไม่ใช่สามขั้นเท่ากัน) · **การปรับค่า p เมื่อทดสอบหลายครั้ง** สามวิธี พร้อมประโยคที่บอกว่าคุมอะไรคนละอย่าง และบอกจำนวนข้อที่ p ดิบผ่านแต่ไม่รอดหลังปรับ

**บทที่ 19 และ 21 ปิดแล้ว (2026-08-16, 12 เทส)** — **ข้อมูลขาด**: ทุกไฟล์อื่นรับ `[Double]` ซึ่งแปลว่าค่าที่ขาดถูกทิ้งไปก่อนถึงมือแล้ว และไม่มีอะไรบอกได้ว่าตัวแปรที่ครบต่างจากตัวแปรที่คนหายไปหนึ่งในสาม — รายงานบอก**จำนวนแถวที่ครบจริง** ซึ่งมักน้อยกว่าที่ทุกคนคาด เพราะแต่ละแถวขาดคนละที่ · และทดสอบสัญญาณว่าการขาดหายสัมพันธ์กับตัวแปรอื่นไหม (พิสูจน์ MCAR จากข้อมูลไม่ได้ แต่พิสูจน์ตรงข้ามได้บ่อย) · **ไม่มีฟังก์ชันไหนเติมค่าให้** เพราะการเติมเป็นการตัดสินใจเชิงโมเดลที่มีสมมติฐานของตัวเอง และไลบรารีที่เติมเงียบ ๆ คือการผลิตตัวเลขที่มั่นใจจากข้อมูลที่ไม่มีอยู่ · **SMR**: standardisation แบบ indirect (ถามว่าอัตราอ้างอิงทำนายว่าจะตายกี่คน) ซึ่งเป็นคำถามที่ถูกเมื่อกลุ่มเล็ก · **ช่วงเป็น exact Poisson** เพราะที่ 6 ศพ การประมาณแบบปกติให้ขอบล่างต่ำกว่าศูนย์ · **ตารางชีพ** เปลี่ยนอัตรารายอายุเป็นจำนวนผู้รอดและอายุคาดเฉลี่ย ซึ่งเป็นรูปที่คนนอกวงการเอาไปใช้ได้

## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P14.1 — ตัวช่วยตั้งค่าสะพาน

**สถานะ**

✅ **ผ่าน Done-when (2026-08-16, 15 เทส + ขับกับ R จริง

- E.28)** — ขับจริงก่อนเขียนโค้ด: R **4.5.3** ที่ `/usr/local/bin` มี `httpuv` + `jsonlite` แต่**ไม่มี `plumber`** ⇒ **เขียนสะพานบน httpuv แทน plumber ตามที่ §12.7 วาดไว้** เพราะไม่งั้นประโยคแรกที่ตัวช่วยพูดกับผู้ใช้คือ "ติดตั้งแพ็กเกจก่อน ตัวช่วยถึงจะทำงาน" — plumber เองก็เป็นชั้นบน httpuv
- `/health` และ `/eval` ตอบจริง data frame กลับมาพร้อม `NA` เป็น JSON `null` และโค้ดที่ parse ไม่ผ่านได้ 400 พร้อมข้อความของ R เอง (`<text>:2:0`)
- **สถานะแยกสี่แบบ และทุกแบบมีขั้นถัดไปเป็นคำพูด**: ไม่มี R ≠ ขาดแพ็กเกจ ≠ R ที่เสีย — ยุบรวมเมื่อไหร่ก็ส่งคนไปติดตั้ง R ที่ใช้ได้อยู่แล้วใหม่
- **ตัวช่วยไม่ติดตั้งอะไรให้** (กฎใน check.sh พิสูจน์ว่า fail ได้) เพราะตัวช่วยที่รัน `install.packages` เองคือตัวช่วยที่แก้เครื่องคนอื่นเพื่อให้ไฟของตัวเองเขียว
- **แอปไม่เปิด R ให้** — สะพานเป็นของผู้ใช้ รันด้วยไลบรารีและโฟลเดอร์ของเขา ตามที่ §12.7 ขอ
- เทส 15 ข้อ**ไม่เรียก R เลย** ใช้รูปคำตอบที่บันทึกไว้ เพราะเครื่องที่ไม่มี R คือเครื่องที่ฟีเจอร์นี้มีไว้ให้

### P14.2 — `r_eval` เป็นทูลที่เดินประตูเดิม

**สถานะ**

✅ **ผ่าน Done-when (2026-08-16, 4 เทส)**

- `r_eval` ลง `RiskScorer` เป็น **high** และ `StageGate` เป็น **`.mutating`** ⇒ ขั้นวางแผนปฏิเสธจริง (เทสยิงผ่าน gateway ตัวจริง ไม่ใช่เทียบตาราง)
- สะพานเป็น HTTP ที่รัน R อะไรก็ได้ = เชลล์คนละไวยากรณ์ สิ่งเดียวที่ทำให้ยอมมีได้คือมันเดินประตูเดียวกับทูลอื่น
- **สะพานปิด = "เปิดเทอร์มินัลแล้วสั่ง Rscript …"** พร้อมพาธจริงของไฟล์ ไม่ใช่ connection refused (เทสยิงกับพอร์ตที่ไม่มีใครฟังจริง)
- error ของ R ส่งกลับแบบคำต่อคำ เพราะบรรทัดกับตำแหน่งคือสิ่งเดียวที่บอกได้ว่าผิดตรงไหน
- ทูลลงทะเบียนในแอปตั้งแต่บูตแม้สะพานยังไม่เปิด — ทูลที่โผล่เฉพาะตอนสะพานขึ้นคือทูลที่โมเดลไม่มีวันรู้ว่ามี

### P14.3 — ผลลัพธ์ลง DuckDB

**สถานะ**

✅ **ผ่าน Done-when (2026-08-16, 5 เทส กับ DuckDB จริง)**

- data frame → CSV → `AnalysisStore.importFile` ซึ่งเป็น**เส้นทางเดียวกับการนำเข้าไฟล์ทุกอันในแอป** ⇒ DuckDB เดาชนิดให้ (id เป็น INT, value เป็น DOUBLE — เทสยืนยัน) ถ้าเขียน `INSERT` เองจะกลายเป็นตัวเดาชนิดตัวที่สอง และสิ่งแรกที่มันจะเดาผิดคือ factor ที่หน้าตาเหมือนตัวเลข
- **`NA` เขียนเป็นช่องว่าง ไม่ใช่ตัวอักษร NA** ไม่งั้นคอลัมน์ตัวเลขที่มีค่าว่างกลายเป็นข้อความทั้งคอลัมน์
- **เขียนตารางเมื่อสั่งเท่านั้น** (`into_table`) — ถ้าเขียนเองทุกครั้งโปรเจกต์จะเต็มไปด้วย `r_result_7` และประเด็นของ §12.7 คือผลจาก R ต้อง*อ้างอิงได้* ซึ่งแปลว่ามีชื่อที่คนตั้ง
- **สั่ง into_table แต่โค้ดไม่ได้คืน data frame = error ไม่ใช่ตารางว่าง** เพราะตารางว่างจะถูกอ่านรอบหน้าว่า "ไม่มีแถวที่ตรงเงื่อนไข"

### P14.4 — ขอบเขตของสะพาน

**สถานะ**

✅ **ผ่าน Done-when (ตรวจซ้ำ 2026-08-17)**

- `install_package` ทำแล้ว (2026-08-15, 4 เทส) — `AlwaysAsk` ทำให้มันหยุดถามคนเสมอแม้อยู่โหมดอัตโนมัติเต็ม และรายการอยู่ข้าง `RiskScorer` ไม่ใช่บนตัวทูล เพราะ manifest ประกาศอะไรก็ได้
- **หน้าตั้งค่าบอกขอบเขตแล้ว (2026-08-16)**: หน้าสถานะระบบมีส่วนของสะพาน R ที่พูดตรง ๆ ว่าสะพานรันด้วยสิทธิ์ของผู้ใช้ เห็นไฟล์ทุกอย่างที่ผู้ใช้เห็น ใช้ไลบรารี R ของผู้ใช้ และฟังเฉพาะ 127.0.0.1
- **ครึ่งของ R ทำแล้ว (2026-08-16, 4 เทส)**: `r_install_package` เป็นทูลของตัวเองและอยู่ใน `AlwaysAsk` ⇒ หยุดถามคนแม้อยู่โหมดอัตโนมัติเต็ม
- **และปิดช่องที่ทำให้กฎนี้ไร้ความหมาย**: `AlwaysAsk` ผูกกับ*ชื่อทูล* แต่ `install.packages("x")` ที่อยู่ในบล็อกโค้ดของ `r_eval` ไม่ใช่ชื่อทูล ⇒ `r_eval` ปฏิเสธคำสั่งติดตั้งทั้งหกแบบ (`install.packages` · `remotes::` · `devtools::` · `BiocManager::` · `renv::` · `pak::`) แล้วชี้ไปที่ทูลที่ถาม — จับแบบหยาบโดยตั้งใจเหมือน destructive pattern ของ `run_shell` เพราะเตือนเกินราคาหนึ่งครั้งที่ถูกส่งไปทางอื่น ส่วนพลาดคือโค้ดของคนอื่นรันบนเครื่องโดยไม่มีใครถาม
- ชื่อแพ็กเกจต้องเป็น*ชื่อ* ไม่ใช่นิพจน์ R และ repository ต้องเป็น https
