## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P10.1 — Project entity + สองสภาพแวดล้อม

**สถานะ**

🔶 **ทำแล้วบางส่วน (2026-08-13)**

- `Project`/`ProjectStage`/`ScopeStatement` อยู่ใน AgentKit, `ProjectStore` ใน Persistence (schema v3), `ProjectService` ใน **M14 ProjectKit** ตัวใหม่
- หน้า "โปรเจกต์" สร้าง/เลือก/แก้ขอบเขตได้จริงในแอป และ Chat ผูก identity กับ scope ที่เลือก ดังนั้นสลับโปรเจกต์แล้วรายการบทสนทนาเปลี่ยนตาม
- `grep ProjectID("default")` เหลือแต่ในคอมเมนต์ที่อธิบายว่าเคยมี
- **แยกบนดิสก์แล้ว (2026-08-13)**: `AppPaths.project(id)` ให้โฟลเดอร์ต่อโปรเจกต์ (`projects/<id>/` → analysis · notebooks · documents · files) และ `WorkspaceStoreCache` เปิด DuckDB/notebook/connector ของโปรเจกต์นั้นครั้งเดียวแล้วถือไว้ — สอง `AnalysisStore` บนไฟล์เดียวไม่ใช่ทางช้า แต่คือผู้เขียนคนที่สอง
- working directory ของ `run_shell` ตั้งเป็นโฟลเดอร์ `files/` ของโปรเจกต์เอง (อยู่ใน container จึงไม่ต้องขอสิทธิ์)
- **ดูแยกต่อโปรเจกต์ได้แล้ว (2026-08-16, 1 เทสกับ SurrealDB จริง)** — `recent(limit:scope:)` และหน้าสายบังคับบัญชาถามเฉพาะ workspace ที่เปิดอยู่
- เดิมหน้านั้นถูกจุดจาก span **ทุกโปรเจกต์รวมกัน** แล้วเรียกว่างานของโปรเจกต์นี้
- ไม่ระบุ scope ยังเป็นคำถามจริง ("เครื่องนี้ทำอะไรอยู่บ้าง") และต้องไม่ถูกเปลี่ยนเป็นคำตอบของโปรเจกต์เดียวเงียบ ๆ
- ลบโปรเจกต์ลบแค่แถว ไม่แตะโฟลเดอร์โดยตั้งใจ (ลบไฟล์คนอื่นย้อนไม่ได้)
- ยังไม่มี worktree ต่อโปรเจกต์

### P10.2 — Stage machine + StageGate ใน hook chain

**สถานะ**

✅ **ผ่าน Done-when (12 เทส)**

- StageGate อยู่ในโซ่จริงระหว่าง Critic กับ Risk Scorer และเทสทุกตัวยิงผ่าน `ToolGateway.call` ซึ่งเป็นประตูเดียวที่มี
- **แกนการจัดชั้นเป็น "effect" ไม่ใช่ "risk"**: `save_document` กับ `analysis_execute` เสี่ยงเท่ากัน (medium) แต่ขั้นวางแผนอนุญาตตัวแรกและปฏิเสธตัวหลัง — ความเสี่ยงตอบว่าพังได้แค่ไหน ขั้นตอบว่างานนี้ถึงคิวหรือยัง

### P10.5 — RACI

**สถานะ**

✅ **ผ่าน Done-when (6 เทส + 1 กฎโครงสร้าง)**

- สองข้อแรกไม่ได้เทส **เพราะเทสไม่ได้**: `RACI.accountable` เป็นฟิลด์เดี่ยวไม่ optional ⇒ "A สองคน" ไม่ใช่สถานะที่เขียนลงไปได้ และ `Accountable` เป็น enum ที่ไม่มี case รับ `Role` ⇒ `.agent(.engineer)` คอมไพล์ไม่ผ่าน
- `BoardRole` ไม่มี case/initializer/ฟิลด์ใดรับ `Role` และ `check.sh` fail ถ้าไฟล์นั้นเอ่ยถึง `Role` นอกเคสผู้ร่วมงาน — กันไม่ให้กฎย้ายจาก compiler ไปเป็น validator เงียบ ๆ
- ข้อที่สาม (เสี่ยงสูง → A ต้องเป็นคน) เป็น judgement ไม่ใช่รูปร่าง จึงตรวจที่ G2 พร้อมเหตุผล
- G1 เพิ่มเงื่อนไข "มีชื่อ Executive ที่เป็นคน" และ**ไม่เติมชื่อให้อัตโนมัติ** เพราะประเด็นของกฎคือมีคนเอาชื่อตัวเองไปใส่
- **ตาราง RACI เต็มโครงการทำแล้ว (2026-08-16, 6 เทส)** — คนอยู่แกนหนึ่ง ใบงานอยู่อีกแกน เพราะคำถามที่ RACI ถูกสร้างมาตอบเป็นคำถามข้ามแถวทั้งนั้น: ใครรับผิดชอบทุกใบ (คือคอขวดจริงของแผน)
- ใครอยู่ในโครงการแล้วไม่ถือตัวอักษรไหนเลย
- ใบไหนมี A แต่ไม่มี R (มีคนรับผิดชอบผลแต่ไม่มีคนทำ) — ทั้งสามข้อดูจากหน้าจอรายใบไม่เห็น
- **ช่องหนึ่งแสดงทุกตัวอักษรที่ตรง ไม่ยุบเหลือตัวเดียว** เพราะคนที่เป็นทั้ง A และ C บนใบเดียวกันคือสิ่งที่คนอ่านตารางนี้กำลังตามหา
- แถวถูกอ่านออกเสียงเป็นประโยค ไม่ใช่ลำดับตัวอักษร
- `riskClass` ต่อใบงานยังต้องตั้งเอง ยังไม่ได้ดึงจาก `RiskScorer`

- breach เดิมไม่ raise ซ้ำทุกครั้งที่ตรวจ

- **เวลา** = เวลาที่ลงจริงจาก span หารด้วย p90 ของงานชนิดเดียวกัน (แผนที่ยังไม่มีประวัติ ⇒ **ไม่รายงานอัตราส่วน ไม่ใช่รายงานศูนย์**)
- **เงิน** = `SurrealSpendLedger`
- **คุณภาพ** = จำนวนครั้งที่ต้องทำซ้ำสูงสุดจาก task ledger
- **ความเสี่ยง** = ชั้นความเสี่ยงสูงสุดของใบงานที่ยังเปิดอยู่ (ไม่ต้องมี store — แผนถืออยู่แล้ว)
- **ประโยชน์** = นับเฉพาะที่มีคนวัดจริง ไม่งั้นแถบบอกว่า "ยังไม่ได้วัด" เพราะ business case ที่ดูดีเพราะไม่มีใครดูคือสิ่งที่แกนนี้มีไว้จับ
- ทั้งสี่ store ถูก attach จริงตอนเปิดหน้าโปรเจกต์
- **กฎของการผูกสไลเดอร์กับกรอบทำแล้ว (2026-08-17, 5 เทส)**: `Tolerances.Preset`
- `matchingPreset`
- `following(_:)` — **กรอบที่ยังเป็น preset จะตามสไลเดอร์ไป** (ไม่เสียอะไร เพราะเดิมก็ไม่มีอะไรนอกจาก preset) ส่วน **กรอบที่คนตั้งเองจะไม่ถูกเขียนทับ** และ `matchingPreset` ที่เป็น nil คือสิ่งที่หน้าจอใช้บอกว่าสไลเดอร์กับตัวเลขไม่ตรงกันแล้ว
- ใช้การเทียบครบทั้งหกแกน ไม่ใช่เก็บว่า "เลือก preset ไหนไว้" เพราะค่าที่เก็บไว้จะล้าสมัยทันทีที่มีคนแก้เลขเดียว แล้วกลายเป็นใบอนุญาตให้เขียนทับอีกห้าแกน
- **ค้าง**: การต่อบนหน้าจอ — สไลเดอร์อยู่ใน `ChatViewModel` (เป็นโหมดของ gateway) ส่วนกรอบอยู่ใน `ProjectsViewModel` (เป็นของโปรเจกต์) **ซึ่งคือเหตุผลที่มันไม่เคยถูกต่อกัน** และการต่อต้องตัดสินก่อนว่าโหมดที่ผูกกับ gateway ทั้งตัว ควรตามโปรเจกต์ที่กำลังเปิดอยู่หรือไม่

- **ลองเขียนเทสนั้นแล้วและได้ข้อมูลกลับมาสองอย่าง (2026-08-17)**: (1) fixture ต้องเดินผ่าน G1–G4 จริง ซึ่ง G4 ขอ **หลักฐานที่ QA รับแล้ว

- ไม่มีสมมติฐานที่ยังไม่ยืนยัน
- คำตอบ practice 13 ข้อ
- การตัดสินใจเรื่องปลายทางของข้อมูล** ⇒ เป็นงานประกอบ fixture ขนาดจริง ไม่ใช่เทสสั้น

- (9 เทส) — ทะเบียนใช้โครงเดียวกันทั้ง 5 (ที่มา/เจ้าของ/สถานะ/ประวัติ) ต่างที่ `RegisterDetail` ซึ่งเป็น enum ⇒ เขียน risk ด้วยฟิลด์ของ change ไม่ได้
- **`decided(approve:by:)` รับชื่อคน ไม่มีอาร์กิวเมนต์ไหนที่ส่ง `Role` เข้าไปได้** — รูปแบบเดียวกับที่นั่ง Executive คือกฎอยู่ใน signature ไม่ใช่ใน validator
- change เริ่มที่ `proposed` เสมอโดยไม่ต้องมีใครจำ
- lesson ไหลเข้า `central` ตอนปิดโครงการ เขียนเป็น chunk ธรรมดาพร้อม provenance แบบ `authored` ⇒ โปรเจกต์ถัดไปค้นเจอผ่าน hybrid search เส้นเดิม ไม่ใช่ทางพิเศษ
- **ทูลของ agent ทำแล้ว (2026-08-16, 5 เทส + 2 กฎ)**: `raise_risk` และ `propose_change` ⇒ ตอนนี้ทดสอบ "agent เสนอได้ แต่ตัดสินไม่ได้" **จาก tool layer** ได้จริงตามที่ Done-when ขอ
- **กฎถูกรักษาด้วยการไม่มีทางพูดเป็นอย่างอื่น**: `origin` มาจาก `ToolContext` ไม่ใช่จาก argument ⇒ ไม่มีพารามิเตอร์ให้ agent อ้างว่าเป็นคน ซึ่งเป็นรูปเดียวของกฎนี้ที่รอดจาก manifest ที่คนอื่นเขียน
- `propose_change` เขียนสถานะ `proposed` เสมอ และ `decided(approve:by:)` ต้องมีชื่อคน อยู่อีกฝั่งของประตู ไม่มีทูลไหนเอื้อมถึง
- คะแนน 1–5 ที่เกินช่วง**ถูกปฏิเสธ ไม่ใช่ตัดให้พอดี** เพราะการตัดคือการบันทึกตัวเลขที่แต่งขึ้นไว้ในช่องที่บอกว่าประเมินมา
- คำขอเปลี่ยนต้องตอบครบสามด้าน ("ไม่กระทบ" เป็นคำตอบที่ใช้ได้และใช้คำเดียว)
- `raise_risk` อยู่ในรายการของ**ทุก role ที่ทำงาน** — ทะเบียนที่มีแค่คนเดียวเขียนได้คือทะเบียนที่เต็มหลังเหตุการณ์
- ยังไม่ได้ค้นบทเรียนซ้ำจากโปรเจกต์ใหม่จริงในเทส end-to-end

### P10.10 — Benefits + Closing gate

**สถานะ**

✅ **ผ่าน Done-when (15 เทส + ขับจริง)**

- เงื่อนไขปิด 8 ข้อ **ทดสอบทีละข้อ** (gate ที่ทดสอบแต่กรณี "ขาดทุกอย่าง" ผ่านได้ทั้งที่ตรวจอยู่ข้อเดียว) และขับจริงกับฐานข้อมูลก็ไล่ทีละข้อเหมือนกัน
- **เงื่อนไขที่ยังตรวจไม่ได้ ต้องไม่อ่านว่าผ่าน** — `ClosingFacts` ใช้ optional สำหรับข้อขัดแย้ง/สมมติฐาน/conformance ดังนั้นการต่อ store ไม่ครบทำให้ gate 8 ข้อกลายเป็น 4 ข้อไม่ได้ กฎเดียวกับ "ไม่มีทางถาม ไม่เท่ากับอนุญาต"
- **หลักฐานที่ QA ตีกลับ ไม่ใช่หลักฐาน** — ข้อ 2 อ่าน `passed` ไม่ใช่นับ array
- benefit วัด**ทิศทาง** จากค่าฐาน ⇒ ประโยชน์แบบ "ลดลง" (เวลา/ต้นทุน) ไม่ถูกนับเป็นสำเร็จตอนตัวเลขแย่ลง ซึ่งเป็นครึ่งหนึ่งของ benefit จริง
- ประโยชน์ที่ยังไม่วัด **ไม่ใช่ 0** — ledger คืน nil และแถบกรอบขึ้นว่า "ยังไม่ได้วัด" ⇒ business case ที่ดูดีเพราะไม่มีใครดู ถูกกันไว้
- แกนประโยชน์อ่านจาก ledger ที่ service ถือเอง ไม่ใช่จากค่าที่หน้าจอส่งมา ⇒ **tolerance ครบ 6 จาก 6 แกน** (ปิดของค้างจาก P10.6/P10.15)
- วัดผลได้หลังปิดโครงการ (post-project review) เพราะวันทบทวนมักอยู่หลังปิด
- ข้อ 8 ระบบ**บันทึกการตัดสิน ไม่ลบไฟล์ให้เอง**
- **ค้าง**: ปิดก่อนกำหนด (`terminate`) มีอยู่ก่อนแล้วและเทสไว้แล้ว แต่ยังไม่มีปุ่ม "ทบทวนประโยชน์" นอกโปรเจกต์ (ปิดแล้วต้องเข้าโปรเจกต์เดิม)
- รายงานปิดโครงการเป็น P10.11

### P10.11 — Reporting 3 แบบ

**สถานะ**

✅ **ผ่าน Done-when (10 เทส + 2 ด่านขับจริง)**

- `ReportBuilder` เป็นฟังก์ชันบริสุทธิ์ของ (kind, inputs, now) และเทสหลักคือ**เปลี่ยนแถวเดียวแล้วรายงานเปลี่ยน** (ปิดใบงาน → หลักฐาน α = 0.74 โผล่ในรายงานเอง) ไม่ใช่การตรวจว่ามีหัวข้อครบ
- **สิ่งที่ยังไม่ได้วัด ต้องพิมพ์ว่ายังไม่ได้วัด** — รายงานถูกยกไปอ้างในที่ประชุม เลข 0 ในรายงานแย่กว่าเลข 0 บนจอ
- "ใหม่ตั้งแต่รายงานฉบับก่อน" อ่านจากวันที่ของฉบับก่อนจริง ⇒ รายงานรอบสองไม่ซ้ำทะเบียนทั้งชุด
- **บั๊กที่การขับจับได้**: เทียบเวลาแบบ `>` ทำให้ความเสี่ยงที่เกิด*วินาทีเดียวกัน*กับรายงานฉบับก่อนหายไปเลย (ISO-8601 ที่เก็บลง DB ไม่มีเศษวินาที) — แก้เป็น `>=` เพราะรายงานซ้ำหนึ่งรายการคือเสียงรบกวน แต่รายการใหม่ที่หายคือการ escalate ที่ไม่เกิด
- เพิ่มเทสกันถอยหลัง
- รายงานถูก**เก็บไว้** (ตาราง `report`, append-only) ⇒ "เดือนมิถุนาเราพูดว่าอะไร" ตอบได้ และ practice `reporting` มีของจริงแทนที่จะต้อง tailoring (ขับจริงเปลี่ยนจากของจริง 11 → **12** ข้อ)
- ไฟล์ `.docx` เขียนผ่าน DocGen เข้าโฟลเดอร์ documents ของโปรเจกต์ และเทสตรวจว่า**ไม่มีหัวข้อไหนหายไปตอนกลายเป็นไฟล์**
- ข้อความที่ส่งเข้า channel เป็นสตริงเดียวกับที่อยู่ในไฟล์
- **รอบอัตโนมัติทำแล้ว (2026-08-16, 6 เทส)** — เลือกรอบได้ (สัปดาห์/สองสัปดาห์/เดือน/ไม่ออกเอง) และเมื่อถึงรอบ หน้าจอขึ้นแถบว่าถึงเวลาแล้ว
- **ไม่มี daemon และไม่ควรมี**: แอปนี้ไม่ได้รันตอนปิดอยู่ ตัวจับเวลาที่แกล้งว่ารันคือรายงานวันอังคารที่ออกวันพฤหัส — คำถามที่ตอบได้จริงคือ "ครั้งล่าสุดออกเมื่อไร ตอนนี้ถึงรอบหรือยัง และครอบคลุมช่วงไหน"
- **รอบไม่ออกรายงานเอง** มันบอกว่าถึงกำหนด ส่วนปุ่มเดิมเป็นตัวออก ⇒ ไม่มีทางที่รายงานจะมาโดยข้ามสิ่งที่การกดปุ่มตรวจ
- **รอบที่ขาดถูกพูด ไม่ถูกย้อนออก** — หายไปสามสัปดาห์ = รายงานหนึ่งฉบับกับหนึ่งประโยค ไม่ใช่สามฉบับ เพราะฉบับย้อนหลังคือตัวเลขที่ใส่ไว้ใต้วันที่ที่ไม่มีใครทำงาน
- โปรเจกต์ที่ยังไม่เคยออกรายงานรอให้ครบรอบแรกก่อน (รายงานที่ครอบคลุมบ่ายวันแรกไม่มีอะไรอยู่ในนั้น และสอนคนให้เลิกอ่านฉบับถัดไป)
- รายงานยังไม่แนบกราฟ/ตาราง เป็นบรรทัดข้อความล้วน

### P10.14 — ประวัติบทสนทนา

**สถานะ**

✅ **ผ่าน Done-when (5 เทส + ขับจริง)**

- ค้นด้วย **BM25 + tokenizer ตัวเดียวกับคลังความรู้** เพราะภาษาไทยไม่มีช่องว่าง `CONTAINS` จึงเจอทุกอย่างหรือไม่เจอเลย ทั้งสองอย่างไม่ใช่การค้นหา
- ผลลัพธ์แสดง**ข้อความที่ตรง** ไม่ใช่แค่ชื่อบทสนทนา (คำถามคือ "พูดไว้ตรงไหน" ไม่ใช่ "มีบทสนทนาอะไรบ้าง")
- บทสนทนาเดียวที่ตรง 5 ข้อความ = ผลลัพธ์เดียว
- ปักหมุดอยู่บนสุดโดย**ไม่นับเป็นการใช้งาน** (ถ้าปักหมุดแล้ว `updated_at` ขยับ มันจะแยกไม่ออกจากการตอบ)
- ตั้งชื่อจากข้อความแรกโดยใช้ตัวช่วยตัวเดียวกับ Project Brief
- ค้นข้ามโปรเจกต์เป็น**คำถามคนละข้อ ไม่ใช่ค่าเริ่มต้นที่กว้างกว่า**
- **ค้นแบบ semantic ทำแล้ว (2026-08-16, 6 เทส)** — ฝั่ง vector รวมเข้ากับ BM25 ด้วย **RRF ค่าเดียวกับ knowledge index** (สองกฎสำหรับ "คำกับ vector รวมกันยังไง" จะเพี้ยน และอันที่สองคืออันที่ไม่มีใครจูน) ⇒ ค้น "ยาปฏิชีวนะก่อนผ่าตัด" เจอบทสนทนาชื่อ "เตรียมผู้ป่วยก่อนเข้าห้องผ่าตัด" ที่ไม่มีคำนั้นเลย
- **หนึ่ง embedding ต่อบทสนทนา ไม่ใช่ต่อข้อความ** — ฝังตอนบทสนทนาได้ชื่อ ซึ่งเป็นจังหวะเดียวที่มีอะไรให้ฝังและคุ้มค่า
- **ข้อจำกัดที่พูดตรง ๆ**: มันหาจาก*เรื่องที่คุยกัน* ไม่ใช่ทุกประโยค — วลีที่ฝังอยู่กลางบทสนทนายาว ๆ เป็นงานของการค้นด้วยคำ
- ผลที่มาจาก vector ล้วนบอกว่ามาจากเรื่อง ไม่ยกบรรทัดแรกมาแสดงราวกับเป็นคำที่ตรง
- **ไม่มีโมเดล embedding = ค้นด้วยคำเหมือนเดิม** ไม่ใช่ค้นไม่ได้
- มี floor ของความคล้าย เพราะ vector ทุกตัวคล้ายกันนิดหน่อยเสมอ และอันดับที่ไม่มี floor คือรายชื่อบทสนทนาทั้งหมดเรียงมั่ว ๆ

### P10.16 — Plan แก้ inline

**สถานะ**

- **ไม่บล็อก ไม่เตือนทีหลัง** ตาม §19.2.4 — ขึ้นแถบตรงนั้นว่า "จะกลายเป็นคำขอ #N
- กระทบ: ขอบเขต/เวลา/เงิน" พร้อมปุ่มยืนยัน/ยกเลิก

### P10.13 — Conformance + tailoring
