## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P2.1 — เลือก embedding model ✅

**สถานะ**

✅ **`bge-m3` @ 1024 มิติ** — 100% ทุกมิติ ([ARCH E.10](../verification/01-e01-e15.md#e10-d-2--เลือก-embedding-model-วัดจริง-ปิดแล้ว)); พบว่า embedding ของ Apple แยก vector space ตามสคริปต์ จึงทำ cross-lingual ไม่ได้เลย


---
### P2.2 — Chunker + Thai tokenizer

**สถานะ**

- ✅ target `Knowledge` (tokenizer + chunker + BM25) **14 เทส**
- `โลจิสติก`/`โควิด` ไม่แตกแล้ว และมีเทสยืนยันว่าถ้าปิด merge layer มันแตกจริง
- **วัดแล้วได้ผลค้านข้อสันนิษฐานของ Done-when เอง**: recall@1/MRR เท่ากันเป๊ะทั้งเปิดและปิด (1.00) เพราะ index/query ใช้ tokenizer เดียวกัน — ของจริงที่ layer นี้แก้คือ **precision** (ค้น `สติ` แล้วไม่ได้เปเปอร์ logistic regression ติดมา) บันทึกไว้ที่ [ARCH E.3.1](../verification/01-e01-e15.md#e31-merge-layer-ให้ผลอะไรจริง--วัดตอน-p22-แก้ข้อสันนิษฐานเดิม)
- chunker ไม่ตัดกลางประโยค + overlap แบบ best-effort


---
### P2.3 — Ingestion pipeline

**สถานะ**

✅ **ทั้งสอง Done-when ผ่านกับไฟล์สแกนจริง**

- เทสวาดข้อความไทยลง bitmap แล้วยัดเป็นหน้า PDF (ไม่มี text layer เลย) OCR จึงเป็นทางเดียวที่ข้อความจะเข้า index ได้
- ค้นเจอทั้งฝั่ง BM25 และฝั่ง vector (bge-m3 @ **1024 มิติ** ตามที่ P2.1 ล็อก)
- ingest ซ้ำ = เพิ่ม 0 chunk
- dedup 2 ชั้น: sha256 หลัง normalize ช่องว่าง + near-duplicate ด้วย cosine ≥ 0.97 (กันเคสสแกนใหม่แล้ว OCR เพี้ยนนิดหน่อย)
- reader ครบ PDF (text layer บาง = ส่งเข้า OCR), รูป, docx/pptx (unzip + OOXML), plain text
- **ปฏิเสธการ index ถ้า embedder อ่านสคริปต์ไม่ออก** ([E.11](../verification/01-e01-e15.md#e11-embedding-model-ที่-ตาบอดภาษาไทย--เจอตอน-p24-2026-08-11))
- พบว่า Vision รองรับไทยเฉพาะ `.accurate` ([E.12](../verification/01-e01-e15.md#e12-vision-ocr-รองรับไทยแค่โหมดเดียว--ตรวจตอน-p23-2026-08-11))
- **ค้าง**: relation extraction (ต้องใช้โมเดลอ่านประโยค) เลื่อนไปพร้อม graph view ใน P2.7 — ตอนนี้สกัดเฉพาะ entity ด้วย `NLTagger`


---
### P2.4 — Hybrid search

**สถานะ**

✅ `KnowledgeIndex`

- RRF (k=60) fuse BM25 + cosine, ทุกแถวคืน provenance + tier + บอกได้ว่าอันดับมาจากฝั่งไหน (`lexicalRank`/`semanticRank`)
- chunk ที่ยังไม่มี embedding ยังแข่งฝั่ง lexical ได้ ไม่หายไปเฉยๆ
- scope filter เทสครบ central/project ก/project ข/policy ไม่รั่วข้ามกัน
- **เจอของจริงระหว่างทำ**: embedding model บนเครื่องนี้คืน vector เดียวกันหมดสำหรับภาษาไทย → เพิ่ม `diagnose(_:)` กันไม่ให้ index ผ่าน embedder ที่ตาบอดสคริปต์ ([ARCH E.11](../verification/01-e01-e15.md#e11-embedding-model-ที่-ตาบอดภาษาไทย--เจอตอน-p24-2026-08-11))


---
### P2.5 — Provenance + credibility

**สถานะ**

✅ `IndexedChunk` ไม่มี initialiser ที่ไม่รับ `Provenance` และ `Provenance` ของแหล่งภายนอก **บังคับ `tier` แบบไม่ optional** (ตัว optional มีทางเดียวคือ `.authored` ของงานที่ระบบเขียนเอง) — บังคับด้วย type ตาม Done-when


---
### P2.6 — Policy scope + Policy Gate

**สถานะ**

- ✅ `PolicyDocumentParser` ตัด 1 กฎ/chunk (ข้ามหัวข้อ) และแยก **ห้าม/must not = hard** ออกจาก **ควร = คำแนะนำ**
- `KnowledgePolicyGate` แทน `NoPolicyGate` ที่ P1 วางไว้
- เทสยิงผ่าน `ToolGateway` จริงและพิสูจน์ว่า**ทูลไม่ถูกเรียก** (ไม่ใช่แค่ค่าที่คืนมา) แม้เปิด full-autonomous
- ข้อความที่คืนคือ**ตัวกฎคำต่อคำ + ชื่อเอกสารต้นทาง**
- matching ตั้งใจให้แคบ (ทุก content term ของกฎต้องปรากฏใน action) เพราะ gate ที่ fire มั่วจะบล็อกงานจริงจนคนเลี่ยงมัน
- 11 เทส


---
### P2.8 — Embedding profile + reindex *(ใหม่ 2026-08-11)*

**สถานะ**

- ✅ `EmbeddingProfile` + ปฏิเสธ vector ข้าม profile ทั้งตอนเขียนและตอนค้น
- `Reindexer` re-embed จากข้อความที่เก็บไว้ (ไม่แตะไฟล์ต้นฉบับ, resume ได้, chunk id/provenance/entity คงเดิม) + **golden-query gate ที่วัดก่อนสลับ** โมเดลที่แย่ลงถูกปฏิเสธและ index เดิมยังทำงานต่อ
- **เจอระหว่างทำ**: gate ที่วัดแค่ผล fused ยอมรับโมเดลที่คืน vector เหมือนกันหมดด้วย recall@1 = 1.00 เพราะ BM25 แบกไว้ทั้งหมด → ต้องวัดฝั่ง vector แยกด้วย (`searchSemantically`) + เช็ค `diagnose` ก่อนรับ
- รวม 15 เทส


---
### P2.7 — KB UI

**สถานะ**

- 🔶 **ตรรกะเสร็จ+พิสูจน์แล้ว
- หน้าจอยังไม่ได้ขับจริง** — entity ถูก index ไปพร้อมเนื้อความ ทำให้ Done-when เป็นจริงในระดับ index (เทส: ก่อนแก้ค้นไม่เจอ → แก้ entity → เจอ → ลบ entity → หายอีกครั้ง)
- `KnowledgeView` มี list + tier badge + ค้นหาที่บอกว่าอันดับมาจากฝั่งไหน + อัปโหลดผ่าน NSOpenPanel + แก้ entity + ลบเอกสาร + export/import (ไม่ส่ง vector ไปด้วย เพราะเครื่องปลายทางอาจใช้โมเดลคนละตัว)
- · **KB ลง SurrealDB แล้ว** — ตาราง `chunk` + unique index บน `content_hash` (กัน chunk ซ้ำที่ชั้นที่ bypass ไม่ได้)
- หน้าจอเขียนผ่านลง DB ทันทีทั้งตอน ingest / แก้ entity / ลบ / import และโหลดกลับตอนเปิดหน้าจอ
- vector ที่สร้างด้วยโมเดลอื่นถูกตัดทิ้งตอนโหลด (เก็บข้อความไว้ให้ re-embed) ไม่ปนเข้า index
- 7 เทสกับ SurrealDB จริง
- **ค้าง**: relation extraction (P2.3 ยกยอดมา)
- **graph view ทำแล้ว** และ**เริ่มขับผ่านหน้าจอจริงแล้ว (2026-08-17)**: หน้ากราฟเปิดได้จริง เอนทิตีขึ้นครบพร้อมชื่อที่อ่านออกเสียงได้ทีละตัว (`ดูความเชื่อมโยงของ …` 12 โหนด รวมชื่อไทย) และตัวควบคุมขอบเขต (ส่วนกลาง/โปรเจกต์/นโยบาย) กับระยะ 1–4 ชั้น อ่านค่าปัจจุบันได้ถูกต้อง
- **กดโหนดแล้วกราฟย้ายจุดกึ่งกลางจริง**: กด `wound closure` แล้วขึ้น `wound closure · ห่างจากจุดกึ่งกลาง 0 ชั้น` กับ `prophylactic antibiotics` ที่ชั้นถัดออกไป ⇒ ปุ่มต่ออยู่
- รอบก่อนหน้าที่ตัวขับรายงาน "หน้าจอไม่เปลี่ยนเลย" คือตอนกด `cefazolin` **ซึ่งเป็นจุดกึ่งกลางอยู่แล้ว** — ไม่ใช่บั๊ก และเป็นตัวอย่างที่ดีว่าทำไมผลลบต้องวัดซ้ำก่อนจะเรียกว่าบั๊ก
- ✅ **กราฟ entity/relation ทำแล้ว (2026-08-15, 13 เทส)** — แท็บ "กราฟ" ในคลังความรู้
- **ความสัมพันธ์ถูกสกัดและเก็บมาตั้งแต่ P2.7 และไม่มี view ไหนอ่านเลย** — `KnowledgeViewModel.relations` โหลดตอน attach แล้วไม่ถูกเรนเดอร์ที่ไหน
- **เป็นย่านรอบสิ่งที่เลือก ไม่ใช่ทั้งกราฟ** เพราะ 500 โหนดพร้อมกันคือก้อนขนที่ดูเหมือนมีความรู้เยอะแต่ไม่ตอบอะไร — มีจุดกึ่งกลางเสมอ มีระยะเสมอ และ**บอกจำนวนที่อยู่ไกลกว่าที่แสดง**เสมอ เพราะภาพที่แสดงหนึ่งในสามของกราฟเงียบ ๆ แย่กว่ารายการ
- โหนดอยู่ที่ระยะ*สั้นที่สุด* (BFS) ไม่ใช่ตามเส้นแรกที่เจอ ไม่งั้นกราฟเดียวกันจะวาดต่างกันตามลำดับแถวที่ฐานข้อมูลคืนมา
- **เลย์เอาต์คงที่** ข้อมูลเดิมได้ภาพเดิมทุกครั้ง — กราฟ force-directed ที่ลงตัวคนละที่ทุกรอบคือกราฟที่ไม่มีใครชี้คุยกันได้
- **ทุกเส้นพกไปยัง chunk ที่พูดมัน** เพราะลูกศรระหว่างคำสองคำอ่านได้ว่าเป็นข้อเท็จจริง กดแล้วเห็นประโยคต้นทางกับเอกสาร
- โหนดเป็น `Button` ไม่ใช่รูปวงกลม (canvas คือที่ที่ accessibility ตายบ่อยที่สุด และสคริปต์ของโปรเจกต์เองก็ fail ให้)
- **ขับจริงแล้ว เจอ 2 ข้อ**: กราฟไม่บอกว่ากำลังวาดคลังไหน (เพิ่มตัวเลือกขอบเขต)
- และ `changeScope` โหลดเอกสารใหม่แต่**ไม่โหลดความสัมพันธ์ใหม่** ซึ่งไม่มีใครเห็นได้ตราบใดที่ไม่มีอะไรเรนเดอร์มัน — สลับไปโปรเจกต์แล้วยังเห็นความสัมพันธ์ของคลังกลาง โดยตัวเลือกบอกความจริงแต่หน้าจอไม่
- **ลบความสัมพันธ์จากหน้ากราฟได้แล้ว (2026-08-16, 2 เทสกับ SurrealDB จริง + 1 กฎ)** — ปุ่มอยู่ในชีต "ที่มาของความสัมพันธ์" ซึ่งเป็นที่ที่คนกำลังยืนอยู่ตอนไม่เห็นด้วยกับสิ่งที่โมเดลอ่าน
- **ลบการอ่าน ไม่ใช่ลบประโยค** — chunk ต้นทางอยู่ที่เดิม
- **และการแก้ต้องรอดจากการ ingest ครั้งถัดไป**: การลบถูกบันทึกเป็น `relation_rejection` และ `save` กรองออกให้ ไม่งั้นการอ่านเอกสารเดิมซ้ำจะวาดเส้นเดิมกลับมา และการแก้ของคนถูกลบทิ้งโดย ingest ที่เขาไม่รู้ว่าเกิดขึ้น (กฎใน check.sh บังคับว่าตัวกรองต้องอยู่ใน `save` ซึ่งเป็นทางเดียวที่ทุกการสกัดผ่าน)
