## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P17.1 — ชั้น AX เป็นหลัก

**สถานะ**

✅ **ขับบนหน้าจอจริงแล้ว ([E.33](../verification/03-e31-e46.md#e33-ตัวขับหน้าจอบนของจริง--และการ-พิมพ์สำเร็จ-ที่แอปไม่รู้เรื่องด้วย-2026-08-16), 2026-08-16, 9 เทส)**

- target `ScreenDriver` ใหม่
- `AXNavigator` หาองค์ประกอบจาก**ชื่อที่ screen reader อ่าน** แล้วสั่ง `AXPress` (ไม่ใช่คลิกพิกัด ซึ่งพังเงียบเมื่อเลย์เอาต์ขยับหนึ่งพิกเซล และบางครั้งไปโดนตัวอื่นแทน)
- **snapshot เป็น value** จึงค้นและเปรียบเทียบได้โดยไม่ต้องมีจอ ซึ่งเป็นเหตุผลที่กฎการค้นหาเทสได้จริง
- **เจอสองอันขึ้นไป = error ไม่ใช่เอาอันแรก** เพราะตัวขับที่เงียบ ๆ เลือกปุ่มผิดคือเทสที่ผ่านทั้งที่กดผิด
- **ปุ่มที่กดไม่ได้ ต่างจากปุ่มที่หาไม่เจอ** — อันหนึ่งคือหน้าจอบอกว่ายังทำไม่ได้ อีกอันคือตัวขับมองผิดหน้าต่าง
- **ขับจริงแล้ว**: กด "ส่งข้อความ" ติดพร้อมรายงานว่าหน้าจอเปลี่ยนอะไร
- กด "โมเดล" ตอนมีห้าอันชื่อคล้ายกัน **ถูกปฏิเสธจริง** ("เจอ 5 อัน — ต้องระบุให้เจาะจงกว่านี้ ก่อนจะกดอันไหนก็ได้แล้วหวังว่าถูก") และชื่อที่ไม่มีบนจอได้ข้อความที่บอกว่าหาอะไรไม่เจอพร้อมรายการที่เห็นจริง — กฎ "เจอสองอันขึ้นไป = error" เคยพิสูจน์ได้แค่ในเทส รอบนี้ยิงใส่ของจริงแล้วมันยิงกลับ

### P17.2 — CGEvent สำหรับสิ่งที่ AX เขียนไม่ได้

**สถานะ**

- ✅ **ขับจริงแล้ว และการขับพลิกการตัดสินใจของ task นี้ ([E.33](../verification/03-e31-e46.md#e33-ตัวขับหน้าจอบนของจริง--และการ-พิมพ์สำเร็จ-ที่แอปไม่รู้เรื่องด้วย-2026-08-16), 2026-08-16, +3 เทส)** — `CGEventKeyboardSetUnicodeString` ไม่ใช่ key code เพราะ **key code คือตำแหน่งบนคีย์บอร์ด US และ `ก` ไม่มีตำแหน่ง** — นี่คือกำแพงที่ตัวขับ AppleScript เดิมชนและเป็นเหตุผลทั้งหมดของ task นี้
- ลอง `AXValue` ก่อนเสมอ (ช่องที่เขียนค่าได้ เร็วกว่าและรบกวนน้อยกว่า) แล้วค่อยตกมาที่คีย์บอร์ด ไม่ใช่กลับกัน
- โฟกัสช่องผ่าน AX ก่อนพิมพ์ ตัวอักษรจะได้ลงที่ที่ตั้งใจ ไม่ใช่ที่ที่โฟกัสบังเอิญอยู่
- **แต่ "ลอง `AXValue` ก่อนเสมอ" คือสิ่งที่การขับจริงพิสูจน์ว่าผิด**: ตัวอักษรขึ้นบนช่องครบ **แต่ผลค้นไม่ขยับเลยไม่ว่าพิมพ์คำไหน** — `AXUIElementSetAttributeValue` คืน `.success` แต่ไม่เดินผ่าน responder chain ⇒ binding ของ SwiftUI ไม่เปลี่ยน ⇒ `.task(id: query)` ไม่มีอะไรให้รันใหม่
- ไล่ทีละชั้นจนแน่ใจว่าไม่ใช่ตัวค้น (BM25 บนคลังจริง 42 ข้อความเจอ 3 hits คะแนน 4.168 · "หมดไฟ" ที่ไม่มีจริงได้ 0 hits · เทสใหม่ที่จำลองรูปทรงคลังจริงผ่าน) ⇒ **กฎ: การเขียนค่าที่ตัวควบคุมยอมรับ ไม่เท่ากับการเขียนที่แอปรับรู้** และตัวขับแยกสองอย่างนี้จากภายนอกไม่ได้ ⇒ สลับลำดับเป็น **คีย์บอร์ดคือทางหลัก เขียนค่าเป็นทางสำรอง**ของช่องที่รับโฟกัสไม่ได้ และทางสำรองเขียนไว้ในหลักฐานตรง ๆ ว่า "แอปอาจไม่รู้ว่าค่าเปลี่ยน"
- **วัดใหม่แล้วผลเปลี่ยนตามคำจริง**: `ผ่าตัด`/`นาที` → ยกประโยคที่ตรงมา
- `หมดไฟ` → ตรงด้วยเวกเตอร์และบอกว่าตัวเองเป็นแบบไหน
- `เบาหวาน` → ไม่มีผลลัพธ์เลย

### P17.3 — สิทธิ์และขอบเขต

**สถานะ**

✅ **ทำแล้ว (2026-08-16, 5 เทส)**

- จำกัดที่ pid ของตัวเองเป็นค่าเริ่มต้น (API ชุดนี้ขับได้ทุกแอปบนเครื่อง รวมถึงโปรแกรมจัดการรหัสผ่าน)
- ไม่มีสิทธิ์ = บอก**ชื่อ pane ตรง ๆ** และบอกว่าต้องใช้ทำอะไร เพราะ "ขออนุญาต accessibility" ไม่ใช่คำสั่งที่ใครทำตามได้บนเครื่องที่ไม่เคยตั้งมาก่อน
- **ข้อที่แพงที่สุดคือสิทธิ์ที่หายหลัง build**: TCC ผูกกับลายเซ็น แอปเซ็น ad-hoc (R11) อาการคือตัวขับที่เคยทำงานเงียบไปเฉย ๆ — จำสถานะที่เคยได้รับไว้ (**ลืมไม่ได้ ไม่งั้นการถูกเพิกถอนจะอ่านเป็นการรันครั้งแรก**) แล้วรายงานว่า *เพิกถอน* พร้อมวิธีแก้ที่ถูกต้องคือ**เอารายการเดิมออกแล้วเพิ่มใหม่** — บอกให้ "เปิดสวิตช์" กับคนที่มองสวิตช์ที่เปิดค้างอยู่ คือคำแนะนำที่ใช้ไม่ได้

### P17.4 — หลักฐานที่ QA อ่านได้

**สถานะ**

✅ **ทำแล้ว (2026-08-16, 4 เทส)**

- `Evidence.kind` มี `.screenObservation` แล้ว และทุกการกระทำคืน `ScreenAction` ที่พก snapshot ก่อน/หลัง
- **หน้าจอไม่เปลี่ยน = `nothingHappened` ไม่ใช่สำเร็จ** — "ผมกดแล้ว" คือคำกล่าวอ้าง ส่วนสอง snapshot มันต่างหรือไม่ต่างก็เท่านั้น
- เทียบจาก**บรรทัดที่ screen reader จะอ่าน** ไม่ใช่พิกัด — หน้าต่างที่แค่ถูกลากไปสองพิกเซลไม่นับว่าเปลี่ยน มิฉะนั้นทุกอย่างจะ "เปลี่ยน" และการตรวจจะผ่านโดยไม่ตรวจอะไรเลย
- หลักฐานบอกด้วยว่า*อะไร*ขึ้นมาใหม่และอะไรหายไป
- **ตัวควบคุมที่ AX กดไม่ได้ถูกรายงานเป็นข้อค้นพบด้าน accessibility** เพราะสิ่งที่ตัวขับกดไม่ได้ คนใช้ VoiceOver ก็กดไม่ได้ — ถ้าไม่บันทึกไว้ ข้อบกพร่องจะถูกซ่อนเพราะทางอ้อมมันใช้ได้
- ทุกการกระทำเป็น span

### P17.5 — สิ่งที่อ่านจากจอคือข้อมูลที่ไม่น่าเชื่อถือ

**สถานะ**

✅ **ทำแล้ว (2026-08-16, 4 เทส + 1 กฎใน check.sh)**

- การป้องกันเป็น**เชิงโครงสร้าง ไม่ใช่เชิงถ้อยคำ**: ข้อความจากจอเข้ามาเป็น **tool output** ผ่าน `read_screen` ซึ่งโปรโตคอลบอกโมเดลอยู่แล้วว่าเป็น*ผลลัพธ์* ไม่ใช่*คำสั่ง* — การเอาไปใส่เป็น system/user message คือช่องโหว่ทั้งหมด และไม่มีการเขียนคำเตือนแบบไหนแก้ได้
- **กฎใน check.sh ห้ามไม่ให้ snapshot กลายเป็น system message** พิสูจน์แล้วว่าแดง
- บรรทัดที่พยายามสั่งงาน AI ถูก**ชี้ให้เห็น ไม่ใช่ลบทิ้ง** เพราะการลบคือการซ่อนสิ่งที่เอกสารนั้นพยายามทำ และหน้าที่เหลือก็ยังต้องอ่านได้
- ข้อความธรรมดาไม่ติดธง เพื่อให้ธงยังมีความหมาย
