## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P6.1 — DuckDB store

**สถานะ**

🔶 **`AnalysisStore` ทำงานกับ DuckDB จริง 9 เทส ไม่มี stub**

- เปิดไฟล์/in-memory, query, `SHOW TABLES`, schema, import CSV/Parquet
- **ผลลัพธ์เป็นค่า ไม่ใช่ cursor** — materialise ให้จบก่อนคืน ไม่มี handle ค้างข้าม await (ซ้ำรอย D6)
- **NULL ไม่เท่ากับสตริงว่าง**
- error แนบ SQL มาด้วยเสมอ
- **สองกับดักที่เจอกับของจริง**: (1) `cast(to: String.self)` ของ duckdb-swift **ไม่ fail แต่คืน nil ทั้งคอลัมน์**ถ้าชนิดไม่ตรง — ตารางจะว่างเปล่าแทนที่จะ error จึงต้องอ่านตามชนิดที่ DuckDB บอก แล้วให้ DuckDB เอง `CAST(... AS VARCHAR)` เฉพาะชนิดที่เราไม่ได้รองรับ (list/struct/interval) (2) **`DESCRIBE` รับ quoted identifier ที่มี `\"` ไม่ได้** ("Unterminated quote in qualified name") ตารางที่ชื่อแปลกจึงสร้างได้แต่ describe ไม่ได้ → อ่านจาก `information_schema` ด้วย **bound parameter** แทน ซึ่งไม่มีปัญหาการ quote ตั้งแต่แรก
- **หน้าจอมีแล้ว** — DB Explorer อยู่ในหน้าวิเคราะห์ (รายชื่อตาราง กางดูคอลัมน์และชนิด แยกภายใน/ภายนอกตาม P10.12) ข้อความเดิมในแถวนี้เขียนไว้ก่อนที่หน้าจอนั้นจะถูกสร้าง

### P6.2 — Extension + federated query

**สถานะ**

✅ **ผ่าน Done-when กับฐานข้อมูลภายนอกจริง**

- สร้างไฟล์ SQLite ด้วย `/usr/bin/sqlite3` (ของที่เครื่องมีอยู่ ไม่ใช่ของที่เราเขียนเอง) → `INSTALL/LOAD sqlite_scanner` จาก Swift → `ATTACH` → เห็น schema → **join ตาราง local กับ remote ในคำสั่งเดียว** → `pull` เข้ามาเป็นสำเนา → `DETACH` แล้วสำเนายังอยู่
- 5 เทส
- **attach เป็น read-only โดยปริยาย** และมีเทสยืนยันว่า INSERT ลงฐานที่ attach มาถูกปฏิเสธ — ข้อมูลของคนอื่นบ่อยกว่าของเรา
- **ยืนยันกับเซิร์ฟเวอร์จริงแล้ว (2026-08-16, E.31)** — ยกคอนเทนเนอร์ PostgreSQL 16 กับ MySQL 8 ขึ้นบนเครื่องนี้แล้วยิงจริง: `ATTACH` ผ่าน
- อ่าน `information_schema` ได้
- `SELECT` คืนค่าครบและชนิดถูก (ไม่มีคอลัมน์ไหนกลายเป็น NULL ทั้งคอลัมน์)
- **ชื่อตาราง/คอลัมน์ภาษาไทยอ่านผ่าน DuckDB ได้ตรง**
- และที่สำคัญที่สุด **รหัสผ่านผิดล้มเหลวโดยรหัสผ่านถูกปิดเป็น `••••`** ซึ่งเป็นเส้นทางที่การปิดสำคัญที่สุด เพราะ DuckDB คืนคำสั่งที่ล้มเหลวกลับมาทั้งประโยค
- เก็บกวาดคอนเทนเนอร์แล้ว
- ข้อความเดิม
- mssql ไม่มี extension ทางการ ([§12.2](../architecture/02-core-modules.md#122-db-connectors) เขียนไว้แล้วว่าไปทาง ATTACH)
- การโหลด extension ครั้งแรกต้องมีเน็ต — เทสจึง skip ดังๆ ถ้าโหลดไม่ได้

### P6.3 — DB connectors

**สถานะ**

- 🔶 **ตรรกะครบ 7 เทส
- หน้าจอมีแล้วแต่ยังไม่ได้กด (U19)** — P6.2 พิสูจน์กลไกไว้แล้ว สิ่งที่ขาดคือทุกอย่างรอบๆ: **แหล่งที่บันทึกไว้แล้วยังอยู่พรุ่งนี้** (ไฟล์ `connectors.json` ข้างๆ สมุดงาน), **มี scope ต่อแหล่ง** (โปรเจกต์เห็นของตัวเอง + ของส่วนกลาง ไม่เห็นของโปรเจกต์อื่น), และ **รหัสผ่านไม่ได้อยู่ในไฟล์** — เก็บแค่*ชื่อตัวแปรสภาพแวดล้อม* รูปแบบเดียวกับทะเบียน endpoint (§9.3/P5.5) เทสเปิดไฟล์อ่านแล้วยืนยันว่าไม่มีคำว่า `password=`
- **จุดที่ต้องมีเทสจริงๆ คือการรั่วของรหัสผ่าน**: `AnalysisError.queryFailed` แนบ SQL มาด้วยตามที่ออกแบบไว้ และ DuckDB เองก็คืน statement ที่ล้มเหลวกลับมาในข้อความ — ซึ่งสำหรับ `ATTACH 'host=… password=…'` แปลว่ารหัสผ่านสดๆ จะไปโผล่ใน log, ใน span และบนหน้าจอ
- ตอนนี้ `AnalysisStore` มี `secretInFlight` ที่ลบรหัสผ่านออกจากทั้งบรรทัด log และ error ที่โยน (เทสยิงผ่านเส้นทางจริงกับ host ที่ไม่มีอยู่ แล้วยืนยันว่าข้อความที่ได้ไม่มีรหัสผ่าน)
- **ต่อเมื่อสั่ง ไม่ใช่ตอนบูต** — การ attach ยื่นออกเน็ตและอาจต้องใช้รหัสผ่าน ทั้งสองอย่างไม่ควรอยู่ในเส้นทางของการเปิดหน้าจอ หน้าจอบอกสถานะแทนว่าต่ออยู่หรือไม่
- ปุ่ม "ต่อ" ถูก disable พร้อมบอกชื่อตัวแปรที่ยังไม่ได้ตั้ง แทนที่จะให้ไปล้มที่ไดรเวอร์
- ดึงตารางเข้ามาวิ่งผ่าน `NotebookRunner` เส้นเดียวกับทุกคำสั่ง จึงถูก `SQLGuard` ถามยืนยันก่อนเขียนทับ
- **ค้าง**: **SQL Server และ MongoDB ยังต่อไม่ได้จริง** — ขึ้นในรายการพร้อมเหตุผล (`UnsupportedConnector`) แทนที่จะเป็นตัวเลือกที่ล้มเงียบ: DuckDB ไม่มี extension ทางการสำหรับ MSSQL และ MongoDB ต้องใช้ไดรเวอร์ native ที่ยังไม่ได้เพิ่มเป็น dependency
- postgres/mysql ยังไม่ได้ยืนยันกับ server จริง (เหมือน P6.2) — เส้นทางเดียวกับ sqlite ที่พิสูจน์แล้ว

### P6.5 — Shared SQL guard

**สถานะ**

✅ **ผ่าน Done-when แบบบังคับด้วยเครื่อง ไม่ใช่ด้วยวินัย**

- `SQLGuard` ตัวเดียว (18 เทส) และ `check.sh` มีกฎใหม่ที่ **fail ถ้าเจอคำกริยา mutating เป็น string literal นอก `SQLGuard.swift`** ใน `Sources/Analysis` หรือ `Sources/CoAIWorkspaceApp`
- **ทั้งสามทางเรียกใช้ตัวเดียวกันจริง**: เซลล์ SQL, DB Explorer และการนำเข้า CSV ต่างวิ่งผ่าน `NotebookRunner.run` เส้นเดียว — และ **runner เป็นคนปฏิเสธ ไม่ใช่หน้าจอ** (`run()` โยน `.needsConfirmation` พร้อม assessment; เทสยืนยันว่าตอนที่ยังไม่ยืนยัน **ตารางไม่ถูกสร้างจริง** ไม่ใช่แค่คืนค่า error)
- **สิ่งที่แยกตัวคุมนี้ออกจาก `split(";")`**: semicolon ในสตริง/คอมเมนต์/dollar-quote ไม่ตัดคำสั่ง
- ตารางชื่อ `"delete"` ที่ quote ไว้ไม่ถูกอ่านเป็นคำกริยา
- **CTE ที่ลบข้อมูล** (`WITH x AS (DELETE …)`) ไม่ใช่ read
- `DELETE`/`UPDATE` ที่ไม่มี WHERE = destructive แยกจากที่มี WHERE
- `CREATE OR REPLACE` = เขียนทับ
- **คำสั่งที่ไม่รู้จัก = ถือว่าเปลี่ยนข้อมูล** (กฎเดียวกับ P1.7 ที่ให้ทูลที่ไม่รู้จัก = High)

### P6.4 — Notebook kernel

**สถานะ**

✅ **ผ่าน Done-when ทั้งสองข้อกับ Python จริง (10 เทส)**

- `x = 41` แล้วเซลล์ถัดไป `x + 1` ได้ 42, โมดูลที่ import ไว้ยังอยู่
- restart แล้วตัวแปรหายจริง (`NameError`) และเคอร์เนลยังใช้ได้
- โปรโตคอลเป็น JSON บรรทัดละคำสั่ง ผ่าน `KernelProcess` ใหม่ใน Execution (§13 "stdin piping สำหรับ notebook kernel")
- **สี่บั๊กที่เจอเพราะรันกับ Python จริง**: (1) **`exit()` ในเซลล์ฆ่าเคอร์เนล** — `site.Quitter` **ปิด `sys.stdin`** ก่อนโยน SystemExit ช่องรับคำสั่งจึงตายไปด้วย แก้ด้วยการอ่านคำสั่งจาก `os.dup(0)` ส่วนตัว แล้วชี้ fd 0 ไป `/dev/null` (2) **SIGINT ไม่ถึงลูก** — `posix_spawn` ไม่ได้ตั้ง `SETSIGDEF` ลูกจึงรับ SIG_IGN ของ SIGINT มาจากเชลล์ที่ไม่ interactive และ **CPython ไม่ติดตั้ง handler ทับของที่ถูก ignore ไว้** → `time.sleep(60)` ขัดจังหวะไม่ได้เลย (แก้ที่ `Spawn` ทั้งไฟล์ — `run_shell` ได้ผลนี้ไปด้วย) (3) เซลล์ที่เขียน fd 1 ตรงๆ ปลอมเป็นคำตอบของโปรโตคอลได้ → เก็บ fd 1 ตัวจริงไว้ส่วนตัวแล้วชี้ fd 1 ไป stderr (4) SIGPIPE ตอนเขียนหาเคอร์เนลที่ตายแล้วจะฆ่าแอปทั้งตัว
- **cell ที่รันนานถูก interrupt ไม่ใช่ restart** — KeyboardInterrupt คือผลลัพธ์ และตัวแปรทั้ง session ยังอยู่
- เซลล์ SQL วิ่งผ่าน `NotebookRunner` + `SQLGuard` (P6.5)
- สมุดงานเก็บเป็นไฟล์ JSON ต่อเล่ม มี scope ต่อเล่มตาม §12.5

### P6.6 — Statistical Verification Gate

**สถานะ**

✅ **ผ่าน Done-when ตรงตัว (33 เทส · ตรวจซ้ำ 2026-08-17)**

- Done-when ของแถวนี้เป็นเรื่องพฤติกรรมของ gate ซึ่งผ่านครบ
- การกดบนหน้าจอเป็นความตั้งใจเพิ่มเติม ไม่ใช่เงื่อนไขของแถว และยังไม่ได้ทำ — t-test บนข้อมูลเบ้ → `Shapiro–Wilk p < 0.05` → เตือนพร้อมตัวเลข → เสนอ Mann–Whitney → `requiresPlanReapproval` เป็นจริง
- **โครงสร้างที่ทำให้ข้ามไม่ได้**: ไม่มีทางเรียกให้ได้ค่า p โดยไม่ได้ผลตรวจข้อสมมติมาด้วย — `StatResult` มีทางออกทางเดียวคือ `report` ซึ่งพ่วงผลตรวจเสมอ
- **คณิตศาสตร์เขียนเองใน Swift ทั้งหมด** เพราะ gate ต้องทำงานบนเครื่องที่ไม่มี Python/เน็ต/แพ็กเกจ: Shapiro–Wilk (Royston AS R94), Levene แบบ Brown–Forsythe, incomplete beta/gamma สำหรับ t/F/χ², OLS + VIF + Tukey non-additivity, logistic ด้วย IRLS, Mann–Whitney/Wilcoxon/Kruskal–Wallis/Fisher's exact
- **เทสเทียบกับค่าที่เปิดตารางดูได้** ไม่ใช่กับผลของตัวเอง (t(10)=2.228→0.05, F(3,10)=3.708→0.05, χ²(3)=7.815→0.05, ชาของ Fisher = 0.4857, KW = 7.2)
- **ข้อสมมติที่ตรวจไม่ได้ ≠ ข้อสมมติที่ผ่าน** — proportional hazards และ linearity ของ logit รายงานเป็น "ยังไม่ได้ตรวจ" และทำให้ผลไม่ clean
- ต่อถึง Analyst แล้วผ่านทูล `run_stat_test` บน `ToolGateway` (6 เทสยิงผ่าน gateway จริง) ซึ่งเป็นหลักฐานที่ Definition of Done ของ Analyst เรียกร้องอยู่แล้ว
- **survival ผ่านด่านแล้ว (P19.2/P19.3)** — `StatGate.survival` มี `.survival` เป็นการทดสอบของตัวเอง และ `run_stat_test` รับ `test: survival` ⇒ ข้อความเดิมในแถวนี้ล้าสมัยตั้งแต่ P19
- ยังไม่มีหน้าจอเฉพาะ — ผลออกทางทรานสคริปต์ของทีม
- ✅ **logistic รายงานค่า p รายสัมประสิทธิ์แล้ว** — Wald z = β/SE จาก inverse ตัวเดียวกับที่ fit ใช้ พร้อม OR และ 95% CI ต่อตัวแปร (รายตัวไม่ใช่ค่าเดียวของทั้งโมเดล เพราะค่าเดียวไม่บอกว่าตัวแปรไหนเป็นคนทำงาน) และไม่มีความหมายเมื่อเกิด separation ซึ่งบอกไว้แล้วในผลตรวจ

### P6.7 — Gap Detection + Analysis Plan

**สถานะ**

✅ **ผ่าน Done-when โดยบังคับที่ type (18 เทส · ตรวจซ้ำ 2026-08-17)**

- การกดบนหน้าจอเป็นของแถม ไม่ใช่เงื่อนไขของแถว (แบบเดียวกับ P5.3/P6.6) และยังไม่ได้ทำ — `AnalysisPlan.approve(by:)` **โยน error ถ้ายังมี `agent_suggested` เหลืออยู่** จึงไม่มีทางมีแผนที่อนุมัติแล้วแต่ยังมีข้อเสนอค้าง
- **แบ่งงานกับโมเดลให้ชัด**: โมเดลอ่านร้อยแก้วอย่างเดียว ส่วนการเทียบกับสคีมาจริงและการตัดสินว่าอะไรบล็อกการอนุมัติเป็นการเปรียบเทียบล้วน เทสได้โดยไม่ต้องมีโมเดล
- gap 3 ระดับตาม §12.4: ไม่มีคอลัมน์เลย = critical
- ชื่อชนกันหลายตาราง/มีแต่ชื่อใกล้เคียง = ambiguous พร้อมตัวเลือก
- โครงร่างไม่ได้ระบุวิธี = assumption-needed **ซึ่งกลายเป็น decision ที่ติดป้าย `agent_suggested`** จึงบล็อกการอนุมัติผ่านกฎเดียวกัน
- **ค่าที่โมเดลสรุปมาแต่ไม่ปรากฏในโครงร่างจริง = ของ agent ไม่ใช่ของโครงร่าง** (กฎเดียวกับ `RelationExtractor` §11.4 — ปลายที่ไม่อยู่ในข้อความถูกทิ้ง)
- **แผนที่อนุมัติแล้วแก้ไม่ได้โดยยังอนุมัติอยู่** — แก้แล้วการอนุมัติถูกถอนเองและบันทึกเหตุผลไว้ นี่คือความหมายของ pre-registration และเป็นทางที่ §12.3 วนกลับมา (assumption ไม่ผ่าน → `methodologyChanged` → วิธีใหม่เข้ามาเป็น `agent_suggested` → ต้องมีคนยืนยันก่อนอนุมัติใหม่)
- ลง SurrealDB แล้ว (ตาราง `analysis_plan`, 5 เทสกับ DB จริง)
- **`doc_type` ทำแล้ว (2026-08-16, 4 เทส + 1 กฎ)** — `Provenance.documentKind` ถูกประกาศตอนอัปโหลด (picker อยู่ข้างปุ่มเพิ่มเอกสาร) และ**ไม่เคยถูกเดา**: §12.4 ใช้ `doc_type: proposal` เป็นตัวจุดชนวนแผนวิเคราะห์ ระบบที่เดาจากชื่อไฟล์จะเปลี่ยน literature review ให้กลายเป็นแผนวิเคราะห์ของใครสักคน (มีกฎห้ามอ่านเนื้อหามาตัดสิน)
- "ยังไม่มีใครบอก" (`nil`) ต่างจาก "บอกแล้วว่าอื่น ๆ" และแถวที่เขียนก่อนมีฟิลด์นี้ยัง decode ได้
- หน้าวิเคราะห์เอาโครงร่างขึ้นก่อนและติดป้ายให้ **แต่ยังลิสต์ทุกเอกสาร** เพราะเอกสารเก่าไม่มีชนิด และตัวกรองที่ซ่อนมันคือการซ่อนคลังทั้งคลังจากคนที่ไม่รู้ว่าทำไม
- **สมุดงาน**: เซลล์ SQL/Python สลับชนิดได้, ป้ายบอกผลกระทบก่อนกดรัน, รันทีละเซลล์หรือทั้งเล่ม (หยุดที่เซลล์แรกที่ล้ม), แถบสถานะเคอร์เนลพร้อมปุ่มเริ่ม/เริ่มใหม่/ปลดออก
- **ฐานข้อมูล**: รายชื่อตารางพร้อมชนิดคอลัมน์และจำนวนแถว, กดตารางแล้วได้ `SELECT * … LIMIT 100`, นำเข้า CSV/Parquet, รายชื่อฐานที่ ATTACH อยู่
- **ตารางผลลัพธ์**: NULL แสดงเป็น NULL ไม่ใช่ช่องว่าง (ตามสัญญาของ `AnalysisStore`) และ **บอกว่าตัดที่กี่แถวจากกี่แถว** ไม่ตัดเงียบ
- **หนึ่งเซลล์ = หนึ่งตารางต่อหนึ่งคำสั่ง** ไม่ซ่อนผลของคำสั่งที่ 2 และ 3
- **แผ่นยืนยันแสดงคำสั่งคำต่อคำ** ไม่ใช่จำนวน (เหตุผลเดียวกับ Conflict Card §11.6)
- **ค้าง**: **ยังไม่ได้กดบนหน้าจอจริง** — จอเครื่องหลับตอนถึงคิว แล้วพอปลุกจอมีผู้ใช้ทำงานอยู่หน้าเครื่องพอดี จึงหยุดไว้ (P1.10/U1 พิสูจน์แล้วว่ารอบนี้เจอบั๊กที่เทสมองไม่เห็นเสมอ)
- **ตอบแล้วด้วยการวัด (P9.6, 2026-08-12): แอปที่ sandbox มองไม่เห็น `/opt/homebrew` และ `/usr/local` เลย** ล่ามเดียวที่รันได้คือตัวจาก Command Line Tools (ไม่มี pandas/numpy) เคอร์เนลตอนนี้ resolve ไปที่ตัวนั้นแล้ว — เดิมเขียนว่า — ถ้าไม่เห็น หน้าจอจะขึ้นว่าไม่มี Python และเซลล์ SQL ยังทำงานได้ตามปกติ
