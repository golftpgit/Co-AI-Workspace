# แผนการสร้าง — Co-AI Workspace

> ตอบว่า **สร้างอะไรก่อนหลัง และรู้ได้ยังไงว่าเสร็จจริง** · สเปกอยู่ที่ [`ARCHITECTURE.md`](../../ARCHITECTURE.md) · กฎที่บังคับด้วยเครื่องอยู่ที่ [`RULES.md`](../../RULES.md)
>
> **กติกาของแผนนี้** (เรียนจากความผิดพลาดของ v1)
>
> 1. ทุก Task มี **Done-when ที่เป็นหลักฐานตรวจได้** ไม่ใช่ "เขียนโค้ดเสร็จ" — ห้าม mark DONE ด้วยความรู้สึก
> 2. **"มี implementation" ≠ "มี feature"** — ทุก task ที่ให้ความสามารถ agent ต้องมี integration test ที่พิสูจน์ว่ามันถูกเรียกใช้จริงใน path ของผู้ใช้
> 3. **"เทสเขียว" ≠ "ใช้งานได้"** — task ที่มีหน้าจอต้องถูกกดด้วยมือบน `.app` ที่ build + sandbox แล้ว
> 4. **"เขียว" ≠ "ตรวจครบ"** — รอบตรวจต้องบอกทุกครั้งว่า*ข้ามอะไรไป* ([`TEST_PROTOCOL.md`](../TEST_PROTOCOL.md))
> 5. ช่อง "ค้าง" ในทุกแถวบอกตรง ๆ ว่าอะไรยังไม่จริง — แถวที่ไม่มีช่องนี้แปลว่าไม่มีอะไรค้าง

### สิ่งที่ต้องทำทุกครั้ง ไม่ใช่ครั้งเดียว

ข้อตกลงเต็มอยู่ที่ [`docs/TEST_PROTOCOL.md`](../TEST_PROTOCOL.md) — สรุปสี่ข้อที่ห้ามข้าม:

1. **pre-flight ก่อนทุกรอบ** — `pkill -if 'helpers/surreal'` · บันทึก RAM ว่าง · ตรวจว่า GX10 อยู่ไหม
2. **ขับหน้าจอด้วยมือหลังทุก task ที่มี UI** — สถิติของโปรเจกต์นี้: ทุกรอบเจอบั๊กที่เทสทั้งชุดมองไม่เห็น (8 · 10 · 5 · 7 · 7 · 3) แล้วบันทึกลง [`docs/DRIVING_LOG.md`](../DRIVING_LOG.md)
3. **`./scripts/build-app.sh` ก่อนขับทุกครั้ง** — และเทียบเวลาไฟล์ binary กับเวลาเริ่มโปรเซสก่อนอ่านผล
4. **ปิดแอปด้วย ⌘Q เสมอ** — `kill -9` ทำให้ macOS restore เป็น "ไม่มีหน้าต่าง" ซึ่งหน้าตาเหมือน boot ล้มเหลวเป๊ะ (U24-2)

**และข้อที่ห้า ซึ่งเพิ่มจากการตรวจครั้งนี้**: รายงานผลต้องบอกว่า **ข้ามอะไรไป** ทุกครั้ง — รายงานที่บอกว่า "ผ่านหมด" โดยไม่บอกจำนวนข้าม เป็นรายงานที่ผิด แม้ตัวเลขทุกตัวจะถูก

## หลักการเรียงงาน


1. **Walking skeleton ก่อน breadth** — P1 สร้างเส้นทางบางที่สุดที่วิ่งครบตั้งแต่ UI → Router → Tool → Hook chain → Approval → Span → DB **ให้ใช้งานได้จริงตั้งแต่สัปดาห์แรกๆ** แล้วค่อยขยายทีละ module ไม่ใช่สร้างทุก module ให้เสร็จแล้วค่อยต่อกันตอนท้าย (v1 เจอปัญหานี้: workflow execution ไม่เคยผ่าน gate เลยจนมาเจอตอน Phase F)
2. **อะไรที่ spike แล้วเอาโค้ดมาใช้เลย** — [`spikes/`](../../spikes/) มีโค้ดที่รันผ่านจริงแล้ว 6 ชิ้น ไม่ต้องเริ่มจากศูนย์ (`SurrealClient` · `LLMExecutor` · `EmbeddingEval` · `EmbeddingRuntime` · `EFAReference` · `ScreenDriver`)
3. **Invariant ก่อน feature** — hook chain, approval broker, span store ต้องมาก่อนสิ่งที่ต้องใช้มัน ไม่ใช่ตามมาแก้ทีหลัง (v1 bug B2: Telegram bridge ข้าม hook chain เพราะ bridge มาก่อน invariant)
4. **ทุก Phase จบด้วยสิ่งที่ใช้งานได้** ไม่ใช่ half-built layer
