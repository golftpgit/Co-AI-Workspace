## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P11.1 — Project type manifest

**สถานะ**

✅ **ผ่าน Done-when

- ขับจริงแล้ว** (2026-08-14): 6 ชนิดตาม §20.2 เป็นไฟล์ใน `Resources/project-types/` โหลดเข้า picker ได้ครบทั้ง 6 พร้อมคำอธิบายว่าเลือกแล้วจะได้อะไร
- สร้าง `research.quantitative` จริงแล้วได้ **แผน 5 บท 17 รายการ** พร้อม deliverable
- เกณฑ์รับงานที่มีหลักฐานกำกับทุกข้อ
- role ตามไฟล์ — และ **G1 ยังไม่ผ่าน** เพราะทุกใบยัง "ยังไม่ผูก" ขอบเขตและยังไม่มีผู้รับผิดชอบ (แผนตั้งต้นที่ผ่านประตูได้เองคือแผนที่ไม่มีใครเขียน)
- **ไม่มี parser ตัวที่สอง**: ใช้ frontmatter reader ตัวเดิม เพิ่มแค่ "เก็บทุกค่าของ key ที่ซ้ำ" เพื่อให้เขียน `gate:` หลายบรรทัดได้ และ `check.sh` แดงถ้ามีไฟล์อื่นใน `Sources/` ไปอ่านรั้ว `---` เอง หรือถ้า type ชี้ไป template ที่ไม่มีอยู่ (**ทดสอบแล้วว่าจับได้จริง**)
- **ข้อค้นพบเชิงออกแบบ**: manifest **ตัดสิน practice ทิ้งเองไม่ได้** — §19.15 ให้เป็นการตัดสินใจที่มีชื่อคนกำกับ และ `TailoringRecord` ปฏิเสธถ้าไม่มีชื่อ ไฟล์จึงทำได้แค่ *เสนอ* พร้อมเหตุผลที่เขียนไว้ให้
- **gate ที่ไฟล์ประกาศถูกบังคับแล้ว (2026-08-14 ค่ำ)**: `ProjectTypeGate` ย้ายมาอยู่ ProjectKit และกลายเป็นเงื่อนไขของประตูขาออกจาก "ขั้นดำเนินการ"
- ตอบสามทางโดยตั้งใจ — **เงื่อนไขที่ระบบตอบได้** บล็อกจริงเมื่อเป็นเท็จ (`content_validity_passed` · `consent_approved` · `ethics_recorded` อ่านจากเครื่องมือของโปรเจกต์)
- **ช่องว่างที่มีชื่อ** (เช่น `saturation_reached` ที่รอ P11.8) ไม่บล็อก แต่ขึ้นเป็น `vacuous` คือ "ยังไม่ได้ตรวจ" ไม่ใช่ติ๊กเขียว — ถ้าบล็อกจะทำให้ 4 ใน 6 ชนิดออกจากขั้นดำเนินการไม่ได้เลย ซึ่งเป็นบั๊กที่แต่งตัวเป็นความเข้มงวด
- **ชื่อที่ไม่มีในทะเบียน** บล็อก เพราะเงื่อนไขที่แต่งขึ้นแล้วเงียบ ๆ ไม่ทำอะไร คือการทำให้บรรทัด `gate:` กลับไปเป็นของประดับ
- มีเทสที่**อ่านไฟล์ชนิดโปรเจกต์ที่ ship จริง**แล้วยืนยันว่าทุกเงื่อนไขที่ไฟล์เอ่ยถึง อยู่ในทะเบียนใดทะเบียนหนึ่ง
- **ค้าง**: โปรเจกต์ที่สร้างก่อนหน้านี้ยังไม่มี `typeName` จึงไม่มี gate ของชนิดใด ๆ มาบังคับ (ถูกต้องตามการออกแบบ แต่แปลว่าฟีเจอร์นี้มีผลกับโปรเจกต์ที่สร้างใหม่จากไฟล์ชนิดเท่านั้น)
- ยังไม่ได้เห็นบนหน้าจอเพราะยังไม่มีโปรเจกต์ไหนบนเครื่องนี้อยู่ที่ขอบขั้นดำเนินการ
- roster ต่อ type ยังไม่ผูกกับ agent จริง

### P11.2 — Instrument Builder + Blueprint

**สถานะ**

✅ **ผ่าน Done-when**

- `Instrument`/`Item`/`Construct`/`ResearchQuestion` ครบ 9 ชนิดข้อ
- skip logic ที่ชี้ไปข้างหน้าหรือชี้ไปข้อที่ไม่มีอยู่ถูก `Blueprint` จับ
- สองภาษาตั้งแต่ชั้น type (`Bilingual`)
- แก้ได้ทุกชั้นจาก Workbench จริง (ขับมือแล้ว)
- **ข้อที่ไม่ผูก construct และไม่ติดป้าย `demographic` ทำให้ publish ไม่ผ่าน** ทั้งจากเทสและจากปุ่ม
- **matrix/ranking สร้างได้จากหน้าจอแล้ว (2026-08-16)** — picker เสนอทั้งสองชนิด และมีช่องพิมพ์แถว/คอลัมน์ (หรือรายการที่จะจัดอันดับ) อยู่ข้างกันทันที เพราะคนที่กำลังเพิ่มตารางรู้ว่าแถวคืออะไรตั้งแต่ตอนเลือกชนิด
- **รายการว่างปล่อยไปให้ด่านจับ ไม่เติม "แถว 1" ให้** — ตารางที่ไม่มีแถวคือความผิดพลาดที่ควรถูกบอก ส่วน placeholder จะถูกเผยแพร่ราวกับเป็นคำถามจริง
- **ค้าง**: `fileUpload` ยังไม่มีทั้ง editor และการวาด (เหตุผลเดียวกับที่ renderer บอก)
- ยังไม่มีตัวร่างด้วย AI

### P11.3 — Validity (Swift)

**สถานะ**

✅ **ผ่าน Done-when เกือบครบ**

- IOC
- I-CVI
- S-CVI/Ave
- Cronbach α
- item-total
- **ICC ทั้ง 6 รูปของ Shrout & Fleiss (1979)**
- **Cohen’s κ และ Fleiss’ κ** — ทุกตัวตรวจกับตัวอย่างที่ตีพิมพ์แล้ว ไม่ใช่กับผลของตัวเอง (ICC เทียบกับตาราง 2 ของ Shrout & Fleiss ได้ .17/.29/.71 และ .44/.62/.91 ตรงทุกตัว · κ เทียบกับ 2×2 มาตรฐานที่คำนวณบนกระดาษได้)
- รันใน Swift ล้วน ไม่ต้องมี Python
- **ออกแบบให้ปฏิเสธเมื่อออกแบบไม่พอ**: ผู้ประเมินคนเดียว หรือหน่วยเดียว หรือทุกหน่วยได้คะแนนเท่ากัน คืน `nil` ไม่ใช่ตัวเลข เพราะตัวเลขที่ออกมาจะถูกเอาไปอ้างในเล่ม
- รายงาน % ความตรงกันจริงคู่กับ κ เสมอ เพราะ κ ต่ำเพราะหมวดเดียวกินหมดเป็นคนละเรื่องกับผู้ลงรหัสไม่เก่ง
- **EFA ครบแล้ว (2026-08-14 ดึก)**: KMO + MSA รายข้อ
- Bartlett

### P11.5 — M16 HTTPServer + FormRuntime

**สถานะ**

✅ **ผ่าน Done-when

- ขับจริงบน `.app` ที่ sandbox แล้ว** (2026-08-14): เปิดเซิร์ฟเวอร์จากในแอปแล้วได้ที่อยู่ LAN จริง
- `curl` จากนอกแอปได้หน้าฟอร์ม 200 (7,974 bytes) ที่มีหน้าความยินยอมก่อนข้อแรก
- **ตรวจซ้ำฝั่ง server จริง**: ไม่ติ๊กยินยอม → 400
- ตอบ Likert เกินระดับที่มี → 400 **พร้อมบอกว่าข้อไหน**
- ส่งเวอร์ชันผิด → 400
- `/admin` → 404 (ไม่มี endpoint จัดการใด ๆ ให้หา)
- ส่งครบ → 200 และคำตอบลง SQLite ของโปรเจกต์จริง
- **field แปลกปลอม `is_admin` ถูกทิ้งและบันทึกเป็นแถวใน `dropped_field`**
- ยิงพร้อมกัน 3 ชุดได้ 200 ทั้งหมด และแอปนับได้ 4 ชุด
- ปิดรอบจากในแอปแล้ว POST **ได้ 410 ที่ endpoint** ไม่ใช่ซ่อนปุ่ม
- ฟอร์มเป็น native control ล้วน (`fieldset`/`legend`/`radio`) จึงใช้คีย์บอร์ดและ screen reader ได้ พร้อม viewport และเป้ากด 44pt สำหรับมือถือ
- ****resume token ทำแล้ว** (§20.7 SessionStore): กดปุ่ม "บันทึกไว้ก่อน" ได้ลิงก์ `?resume=<token 32 ตัว>` กลับมากรอกต่อโดยคำตอบเดิมอยู่ครบ
- ไม่มีบัญชีผู้ใช้ ไม่มี cookie
- ส่งแล้วร่างถูกลบ
- ปิดรอบแล้วร่างที่ค้างถูกลบตามไปด้วย (§20.5)
- ร่างของอีกเวอร์ชันถูกปฏิเสธ ไม่ใช่เทลงฟอร์มใหม่
- **matrix กับ ranking วาดได้แล้ว (2026-08-16, 12 เทส)** — ทั้งสองเป็น "หลายคำถามในพรอมป์เดียว" กฎจึงมาจากตรงนั้น: **grid ที่ตอบบางแถวไม่ใช่คำตอบครึ่งเดียวที่เอาไปเกลี่ยได้** (บังคับตอบครบเมื่อ required และบอกว่าแถวไหนหาย) และ**ranking ที่มีสองอันดับสามคือคำกล่าวอ้างคนละอย่าง ไม่ใช่เกือบถูก** (ต้องเป็น permutation 1…n ห้ามซ้ำห้ามข้าม)
- แต่ละแถว/ตัวเลือกเก็บเป็นคำตอบของตัวเอง (`<id>#<index>`) ⇒ การวิเคราะห์แยกตัวแปรได้
- **grid เป็น `<table>` จริงพร้อม `scope=row/col` และ label ต่อ radio** เพราะหัวตารางไม่ใช่ label และ grid ที่ทำจาก stack อ่านออกมาเป็นปุ่มไร้ชื่อ
- **ranking พิมพ์เลข ไม่ลาก** — การลากคีย์บอร์ดเข้าไม่ถึงและใช้นิ้วเดียวบนวอร์ดไม่ได้
- ฟอร์มที่กรอกต่อกลับมาเห็นของเดิมครบ
- **`fileUpload` ยังไม่วาด และตั้งใจ**: มันคือ multipart, ไฟล์ที่มีข้อมูลคนอยู่บนดิสก์ และกฎการเก็บรักษาของตัวเอง (§20.5) — ครึ่งเดียวแย่กว่าช่องว่างที่พูดตรง ๆ

### P11.7b — Linkage + waves

**สถานะ**

✅ **ผ่าน Done-when ครบ

- ชั้นข้อมูลและหน้าจอ ขับจริงแล้ว** — `LinkageStore` อยู่ในไฟล์ `linkage.sqlite` **คนละไฟล์กับคำตอบ** (สำเนาข้อมูลคำตอบจึงไม่มีตัวตนติดไปเลย ไม่ใช่ "มีแต่อ่านยาก")
- ตัวตนถูกผนึกด้วย AES-GCM คีย์ 256-bit จาก Keychain **แยกต่อโปรเจกต์** (`kSecAttrAccessibleWhenUnlockedThisDeviceOnly` ไม่ sync ข้ามเครื่อง)
- **เทสอ่านไบต์ดิบของไฟล์ (รวม `-wal`) แล้วหาไม่เจอทั้งชื่อผู้เข้าร่วมและคีย์** ซึ่งเป็นข้อเท็จจริงบนดิสก์ ไม่ใช่คำอ้างเรื่องโค้ด
- `resolve` **เขียน span ทุกครั้ง** รวมถึงครั้งที่หารหัสไม่เจอ (คำถามที่ audit ตอบคือ "ใครเปิดดู" ไม่ใช่ "ใครเปิดดูสำเร็จ")
- คีย์ของอีกโปรเจกต์เปิดไฟล์นี้ไม่ได้
- attrition ต่อรอบ = จำนวนที่เชิญเทียบจำนวนที่ตอบ
- รหัสอ่านออกเสียงได้ (ไม่มีสระ ไม่มี O/0 I/1) เพราะงานภาคสนามมีคนต้องอ่านให้กันฟัง
- **`check.sh` บังคับสองข้อ**: FieldServer ห้าม import `Linkage` (พื้นผิวที่รับคนนอกถามไม่ได้ว่าใครเป็นใคร) และไฟล์ตัวตนต้องไม่ใช่ไฟล์เดียวกับคำตอบ — **ทดสอบแล้วว่าจับได้จริง**
- **รหัสเดินทางถึงคำตอบแล้ว**: ลิงก์ที่ลงท้าย `?code=P-…` ทำให้ฟอร์มพารหัสไปด้วย และคำตอบถูกเก็บคู่รหัส (M16 เก็บ*สตริง* ไม่ใช่ตัวตน และยัง import `Linkage` ไม่ได้)
- ฐานข้อมูลเก่าที่ยังไม่มีคอลัมน์นี้ถูก `ALTER TABLE` เติมให้ ไม่ใช่เงียบ ๆ ขาดไป
- **หน้าจอผู้เข้าร่วมทำแล้ว**: ลงทะเบียน → ได้รหัส
- คัดลอกลิงก์เฉพาะคน
- เชิญเข้ารอบ
- attrition ต่อรอบ
- "ดูว่าเป็นใคร" ต้องกรอกเหตุผลกับชื่อ และแสดงทีละคนแล้วลืมทันทีที่ปิด
- **ขับจริงครบทั้งเส้นแล้ว** (2026-08-14 บ่ายแก่) — ดูรอบขับด้านล่าง

### P11.8 — Qualitative

**สถานะ**

✅ **ผ่าน Done-when ทั้งสองข้อ (ตรวจซ้ำ 2026-08-17)**

- ครึ่งหลัง (κ จากการลงรหัสสองชุด) อยู่ที่ `Sources/Instruments/Agreement.swift` พร้อมเทส และเป็นตัวเดียวกับที่ P19.6 อ้างถึงว่า "มีตั้งแต่ P11.8"
- ครึ่งแรกขับจริงแล้ว (2026-08-14): สมุดรหัส (นิยาม + รหัสแม่ + รายงานรหัสที่ไม่มีนิยาม)
- ช่วงข้อความที่**กำหนดครั้งเดียวแล้วทุกคนลงชุดเดียวกัน** ซึ่งเป็นเงื่อนไขที่ทำให้ κ คำนวณได้เลย
- κ รายรวมและ**รายรหัส** (Cohen เมื่อสองคน Fleiss เมื่อมากกว่า)
- หน่วยที่ลงไม่ครบถูกตัดออกและนับให้ดู
- "ไม่เข้ารหัสไหนเลย" เป็นหมวดหนึ่ง ไม่ใช่ช่องว่าง
- เส้นโค้งความอิ่มตัวที่**รายงานโดยไม่ตัดสิน**
- schema v13 สามตาราง โดยแถวลงรหัสมีคีย์ (ช่วง, ผู้ลงรหัส) เพื่อไม่ให้คนหนึ่งคนเข้าไปอยู่ใน κ สองครั้ง
- **หน้าจอใหม่ "ลงรหัส"** ซึ่งเป็นที่แรกที่ ICC/κ ถูกเรียกใช้จริง
- **ขับจริง**: ผู้ลงรหัสสองคนลงสี่ช่วงผ่านหน้าจอ ได้ κ 0.50
- ตรงกัน 75% ตรงกับที่คำนวณบนกระดาษก่อนรัน
- **ครึ่งหลังผ่าน Done-when แล้ว (2026-08-15)**: `Transcript` (รหัสผู้เข้าร่วม ไม่มีช่องใส่ชื่อ)
- `TranscriptQuotation` ที่**สร้างเองไม่ได้** — ผู้ผลิตทางเดียวเฉือนข้อความจากบทถอดเทป ข้อความกับตำแหน่งจึงขัดแย้งกันไม่ได้
- `TextSpan` บน `Provenance` เป็นตัวระบุตำแหน่งของเอกสารที่ไม่มีเลขหน้า และขึ้นในบรรณานุกรม
- `Origin.fieldwork` ที่ tier เป็น `nil` โดยเจตนา
- `TranscriptIngest` แบ่งด้วย `Chunker` ตัวเดิมของ M7 และทุก chunk พกตำแหน่งของตัวเอง
- หน้าจอเปลี่ยนเป็นวางบทถอดเทปแล้วแบ่งตามย่อหน้า (ตำแหน่งจริงแทนเลขที่พิมพ์เอง)
- **ขับจริง**: สี่ย่อหน้า ได้ตำแหน่งต่อเนื่อง 0–32/33–76/77–100/101–144 และข้อความตรงต้นฉบับทุกช่วง
- **ข้อค้นพบ**: บรรทัดไทยที่แสดง 43 รูป = 44 code point = 32 `Character` จึงปักหมุดหน่วยไว้ด้วยเทส
- **เคยค้าง**: ปุ่มส่งบทถอดเทปเข้าคลังความรู้จากหน้าจอ
- ✅ **ปุ่มส่งเข้าคลังความรู้ทำแล้ว (2026-08-15, 8 เทส)** — `TranscriptIngest.chunks` เสร็จตั้งแต่ P11.8 พร้อมเทสสามข้อ และ**ไม่มีอะไรเรียกมัน** คำสัญญา “ผลค้นอ้างกลับไปที่ย่อหน้าได้” จึงจริงกับฟังก์ชัน แต่ไม่จริงกับแอป
- ทางที่ง่ายกว่าคือเขียนบทถอดเทปลงไฟล์ชั่วคราวแล้วเรียก `ingest(urls:)` เดิม — **ทำไม่ได้** เพราะ offset จะหายไปกับไฟล์ และ offset คือสิ่งเดียวที่ทำให้ chunk อ้างถึง*ย่อหน้า*แทนที่จะอ้างบทสัมภาษณ์สองชั่วโมงทั้งอัน
- จึงเพิ่ม `IngestionPipeline.ingest(chunks:)` ที่รับ chunk ที่แบ่งมาแล้ว แล้วเดินต่อบนเส้นทางเดิมทั้ง dedup
- embedding
- near-duplicate เพราะบทถอดเทปที่ถูกจัดดัชนีคนละแบบจะถูกค้นเจอคนละแบบกับทุกอย่างในโครงการ
- **การส่งซ้ำแทนที่ของเดิม ไม่ใช่เพิ่มเข้าไป**: บทถอดเทปเก็บ id เดิมไว้ตอนถูกแก้ การส่งครั้งที่สองจึงคือ*บทสัมภาษณ์เดิมที่พูดถูกขึ้น* ถ้าเก็บทั้งสองรุ่น คลังจะถือประโยคที่ถูกถอนกับประโยคที่แก้แล้วไว้พร้อมกันโดยไม่มีอะไรบอกว่าคำตอบมาจากรุ่นไหน (ต่างจากไฟล์อัปโหลดที่ id คิดจากเนื้อไฟล์ จึงเป็นคนละเอกสารจริง ๆ เมื่อเนื้อเปลี่ยน)
- และ**ปฏิเสธถ้าไม่ได้อยู่ในโครงการ** — คลังกลางถูกค้นจากทุกโครงการ คำพูดของผู้เข้าร่วมจึงไม่ควรไปอยู่ตรงนั้น และคนที่เผลอจะกู้กลับเองไม่ได้ (§20.7)
