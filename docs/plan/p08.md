## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P8.1 — Manifest loader

**สถานะ**

✅ **ผ่าน Done-when (12 เทส)**

- parser ตัวเดียวใช้ทั้ง agent และ skill ตาม §7.2 (สองตัวจะเพี้ยนจากกัน และสิ่งแรกที่เพี้ยนคือ `tools:` ซึ่งเป็นฟิลด์ที่ตัดสินว่าอะไรแตะอะไรได้)
- **ชื่อทูลที่ไม่มีอยู่ = ปฏิเสธทั้งไฟล์ตอนโหลด พร้อมบอกชื่อที่พิมพ์ผิดและรายการทูลที่มีจริง** — ไม่ใช่คำเตือน และไม่ใช่การเงียบๆ ตัดทูลนั้นทิ้ง เพราะ agent ที่หาย `run_shell` ไปเพราะพิมพ์ผิดจะดูเหมือนโมเดลที่เลิกทำตามคำสั่ง (ปรัชญาเดียวกับ Config ที่ reject ค่าผิดตรงที่มันถูกเขียน)
- `base:` สืบทูลจาก role จริง และ **ตารางนั้นเขียนที่เดียวใน `SpecialistTools`** โดยมีเทสใน `RosterTests` คอยเทียบ (Roster เข้าถึง CoreEngine ไม่ได้ตามกฎเดียวกับ channel)
- ไฟล์เสียหนึ่งไฟล์ไม่ทำให้ทั้งทะเบียนหาย
- **ชื่อซ้ำกันสองไฟล์ = ถอนทั้งคู่** เพราะไฟล์ไหนชนะขึ้นกับลำดับไดเรกทอรี ซึ่งไม่ใช่การตัดสินใจของใคร
- จำนวนรายการและไฟล์ที่โหลดไม่ได้ขึ้นบนหน้าสถานะระบบ

### P8.2 — Invariant: risk-sensitive → gated

**สถานะ**

✅ **ผ่าน Done-when**

- `RosterEntry.riskCeiling` คำนวณจากรายการทูลที่ resolve แล้ว โดยใช้ risk ที่ `ToolGateway` ประกาศจริง และ **ทูลที่ไม่รู้จัก = High** (กฎเดียวกับ §5.3)
- **ฟิลด์ที่พยายามให้คะแนนตัวเองถูกปฏิเสธ ไม่ใช่ถูกเพิกเฉย** — `risk` / `requires_approval` / `bypass_gate` / `autonomy` / `trusted` ทำให้ทั้งไฟล์โหลดไม่ผ่านพร้อมเหตุผล เพราะไฟล์ที่เขียน `risk: low` แล้วโหลดผ่านเงียบๆ คือไฟล์ที่บอกเจ้าของมันว่าเป็นเรื่องจริง (เทสวน 5 ฟิลด์)
- agent ที่ขอ `run_shell` ได้ ceiling เป็น high เสมอไม่ว่าไฟล์จะเขียนว่าอะไร

### P8.3 — MCP client

**สถานะ**

✅ **ผ่าน Done-when (11 เทส)**

- เทสหลักต่อเซิร์ฟเวอร์จริง แล้ว**เรียกผ่าน `ToolGateway` ด้วยชื่อที่โมเดลจะใช้** (`mcp__probe__echo`) ไม่ใช่แค่ list ทูลได้
- เซิร์ฟเวอร์ปลายทาง**ไม่ใช่ของเรา** — สคริปต์ Python ที่พูดโปรโตคอลตรง ๆ เพราะการคุยกับเซิร์ฟเวอร์ที่เขียนด้วย SDK เดียวกันพิสูจน์แค่ว่า SDK ตรงกับตัวเอง
- **ครบทั้ง 3 primitive**: `tools/*` เป็น agent tool, `resources/*` เป็น**ทูลเดียวต่อเซิร์ฟเวอร์** (`read_resource` — เซิร์ฟเวอร์หนึ่งมี resource ได้เป็นพัน แต่ tool list คือสิ่งที่โมเดลอ่านทั้งหมดทุกเทิร์น), `prompts/*` **ไม่เป็นทูล** และมีเทสยืนยันว่าไม่อยู่บน tool list — prompt เป็นของผู้ใช้ในช่องพิมพ์
- **ทุกทูล MCP = High เสมอ** และ `readOnlyHint` ของเซิร์ฟเวอร์ไม่มีผล ด้วยเหตุผลเดียวกับ P8.2 (ไฟล์ที่ให้คะแนนตัวเองไม่ถูกเชื่อ) — เทสยืนยันว่าไม่มีช่องทางอนุมัติ = ไม่ได้รัน
- **spawn ผ่าน `Execution`** (`PipedChild`) ไม่ใช่ผ่าน SDK: เซิร์ฟเวอร์ที่ไม่ได้เกิดจาก `Spawn` คือลูกที่อยู่ใน process group ของเราเอง ซึ่งปุ่ม Stop เอื้อมไม่ถึง — มีเทสว่า shutdown แล้วโปรเซสหายจริง (`pgrep`)
- **cwd ถามจากเซิร์ฟเวอร์เอง** (ทูล `where` คืน `os.getcwd()`) ไม่ใช่ตรวจค่าที่เราตั้ง
- **handshake มี deadline** พร้อม stderr ของเซิร์ฟเวอร์ในข้อความ — และกับดักที่เจอตอนเขียน: task group รอลูกทุกตัวเสมอ ส่วน `client.connect` ที่ค้างรอ `initialize` ไม่สนใจ cancel เลย timeout กลายเป็นการค้างแบบเดียวกับที่มันควรกัน (เทสค้างแทนที่จะ fail) — แก้ด้วยการให้ฝั่งที่หมดเวลา `disconnect` ปลดล็อกก่อนแล้วค่อยโยน และให้ deadline เป็นเจ้าของสาเหตุเมื่อจุดชนวนแล้ว ไม่งั้นข้อความจะสลับไปมาตามภาระเครื่อง
- **บั๊กที่เจอตอนขับแอปจริง ไม่ใช่ตอนเทส**: เซิร์ฟเวอร์ที่**ออกทันที**ที่ถูกสั่งรัน (เช่นขาด dependency) ทำให้ปุ่มติดตั้งเงียบจนครบ timeout เพราะ deadline เฝ้าแต่ "ความเงียบ" ส่วนเซิร์ฟเวอร์ที่ตายแล้วเป็นข้อเท็จจริงที่รู้ได้ทันที — เพิ่ม watchdog ที่เฝ้าโปรเซสคู่กับตัวจับเวลา และพา stderr ของมันมาด้วย (31.8 วิ → ต่ำกว่า 1 วิ)
- ต่อเข้าแอปแล้ว: อ่าน `mcp-servers.json` → connect → register ใน gateway **ก่อน**อ่านทะเบียน P8.1 (manifest จึงอ้าง `mcp__…` ใน `tools:` ได้) และ `scripts/check.sh` เพิ่ม `MCPRegistry` เข้ารายการ "built but never wired" ซึ่งเป็นกฎที่มีอยู่เพราะ D6

### P8.4 — Plugin = packaged MCP server

**สถานะ**

✅ **ผ่าน Done-when (11 เทส)**

- ทั้งสองครึ่งของประโยคถูกเทสแยกกัน: **"tool ใช้ได้"** = เรียกผ่าน `ToolGateway` ด้วยชื่อที่โมเดลใช้ (กับดัก D6 ตัวเดิม สูงขึ้นมาอีกชั้น — ติดตั้งได้ ลิสต์ได้ ต่อได้ แล้วยังไปไม่ถึง session) และ **"ทันที"** = เทสเริ่มจาก gateway ที่ว่างและกำลังทำงานอยู่แล้ว ติดตั้ง → connect → register → เรียกได้ในเทิร์นเดียวกัน โดยไม่มี restart
- **Roster ยังแตะทูลไม่ได้** — `MCPTool` เป็น `AgentTool` และ M3 ห้ามเอื้อมถึงเหมือนที่ channel ห้าม (กฎใน Package.swift) Roster จึง*บรรยาย*แพ็กเกจเป็นข้อมูลล้วน ส่วนการต่อจริงอยู่ที่แอป และรอยต่อนั้นถูกเทสในเทสที่ import ทั้งสองฝั่ง
- **แพ็กเกจต้องอยู่ในตัวเอง**: manifest ระบุล่ามบน PATH หรือไฟล์ในโฟลเดอร์ตัวเองเท่านั้น — **พาธเต็มถูกปฏิเสธ** เพราะ "ปลั๊กอิน" ที่ชี้ไปที่อื่นบนเครื่องคือทางลัดไปหาของสิ่งนั้น ไม่ใช่แพ็กเกจ และการถอนจะรายงานว่าสำเร็จทั้งที่ทิ้งของไว้
- `..` ในคำสั่งหรืออาร์กิวเมนต์ถูกปฏิเสธด้วยเหตุผลเดียวกัน
- **คัดลอกเข้ามา ไม่ใช่อ้างอิง** — โฟลเดอร์ต้นทางมักอยู่ใน Downloads และปลั๊กอินที่พังเพราะเจ้าของเก็บกวาดโฟลเดอร์คือความล้มเหลวที่ไม่มีใครโยงกลับไปหาสาเหตุได้
- ชื่อซ้ำ = ปฏิเสธ (ไม่ใช่เขียนทับของที่กำลังรันอยู่)
- แพ็กเกจเสียหนึ่งอันไม่ทำให้ทั้งทะเบียนหาย ตามกฎเดียวกับ P8.1
- เจอตอนเทส: manifest ที่ไม่เขียน `arguments`/`environmentVariables` ถูกปฏิเสธเพราะ Codable สังเคราะห์ให้ทุกฟิลด์บังคับ — คือการปฏิเสธไฟล์เพราะมันธรรมดา
- และ `connect` ตัวเดียวไม่ได้บันทึก failure แบบที่ `connectAll` บันทึก แปลว่าเซิร์ฟเวอร์ที่พังหลังบูตจะไม่ขึ้นหน้าสถานะเลย
- ต่อเข้าแอปแล้ว: ปลั๊กอินที่ติดตั้งไว้ต่อพร้อม MCP server ปกติตอนบูต และมีปุ่มติดตั้ง/ถอนบนหน้าสถานะ ซึ่งบอกด้วยว่าปลั๊กอินนั้น**ให้เครื่องมืออะไรมาบ้าง** (ติดตั้งแล้ว กับ ให้เครื่องมือกับ session แล้ว เป็นคนละเรื่อง)
- **แก้แล้วใน P9.6 (2026-08-12)**: ปัญหา "ปลั๊กอินรันไม่ได้ในแอปจริง" มาจาก `/usr/bin/python3` เป็น shim ที่เรียก `xcrun` ซึ่งรันใน App Sandbox ไม่ได้ — `ExecutableSearch` หาล่ามตัวจริงก่อน และ**ยืนยันบนแอป sandbox จริงแล้วว่า `mcp__weather__forecast` ขึ้น tool list**
- **ค้าง**:  — ขับหน้าจอจริง (2026-08-12): ติดตั้งสำเร็จ ไฟล์เข้า container ครบ แถวขึ้นบนหน้าสถานะ แต่เชื่อมต่อไม่ได้ เพราะ `/usr/bin/python3` เป็น shim ของ Command Line Tools ที่โปรเซสใน App Sandbox เรียกไม่สำเร็จ (สคริปต์เดียวกันรันผ่านนอก sandbox) **เทสทุกตัวรันนอก sandbox จึงมองข้อนี้ไม่เห็นเลย** — Done-when "ใช้ได้ทันที" จริงในเทส แต่ยังไม่จริงในแอปที่ sandbox ทางแก้คือแพ็กล่ามมากับแพ็กเกจหรือผ่อน entitlement ซึ่งเป็นงาน P9.6
- ไม่มี `install_plugin` ให้ agent เรียกเอง — ตอนนี้ติดตั้งเป็นการกระทำของคน
- **`install_package` ยังไม่มี** (checklist เทียบ v1 ผูกไว้กับ task นี้) — `RiskScorer` จัดชั้น High ไว้แล้วและบันทึกเองว่า "ต้องมีนโยบายเน็ตก่อน"
- อยู่ใน[คิวถัดไปข้อ 6](archive.md#คิวถัดไป--เรียงตามลำดับที่ตั้งใจทำ) หลัง security review
- ไม่มีการตรวจลายเซ็น/ที่มาของแพ็กเกจ
- หน้า Plugins เต็ม ๆ อยู่ใน P8.6

### P8.5 — `write_skill`

**สถานะ**

✅ **ผ่าน Done-when (8 เทส)**

- เทสหลักเขียน skill **ผ่าน `ToolGateway`** อย่างที่ agent ทำ แล้วโหลดโฟลเดอร์กลับด้วย `ManifestParser` ตัวเดียวกับที่แอปใช้ตอนบูต ไม่ใช่เช็กว่ามีไฟล์โผล่มา แต่เช็กว่า**ทะเบียนมีมัน** และได้ `riskCeiling` ที่คำนวณจากทูลจริงตาม P8.2
- **ไม่ใช่ backdoor** ตาม §7.3 — และวิธีรับประกันคือไม่ทำอะไรพิเศษเลย: เป็น `AgentTool` เหมือน `run_shell`, `check.sh` บังคับว่ามีแต่ gateway ที่เรียกทูลได้, §5.3 จัดชั้นให้เป็น Medium อยู่แล้ว มีเทสว่าไม่มีช่องทางอนุมัติ = ไม่มีไฟล์เกิดขึ้น
- **กฎที่ทำให้ Done-when เป็นจริงแทนที่จะเป็นความหวัง**: ไฟล์ถูก parse ด้วย loader ตัวที่จะโหลดมันจริง **ก่อน**เขียน และถ้าจะโหลดไม่ผ่านก็ไม่เขียน — ไม่งั้น agent ถูกบอกว่าสำเร็จแล้ว skill หายไปเงียบ ๆ ตอนเปิดแอปครั้งหน้า ซึ่งเป็นความล้มเหลวที่โปรเจกต์นี้เจอมาแล้วสามครั้งในชื่ออื่น
- **รายชื่อทูลอ่านตอนเรียก ไม่ใช่ตอนสร้าง** — MCP server กับ plugin มาถึงระหว่างแอปทำงาน และ skill ที่อ้างทูลของมันต้องไม่ถูกปฏิเสธเพราะทูลตัวนี้ถูกสร้างก่อนหน้านั้น (มีเทส)
- `ManifestParser.text` อยู่ข้างตัว parser เพราะสองที่ที่รู้จักฟอร์แมตจะเพี้ยนจากกัน และสิ่งแรกที่เพี้ยนคือ `tools:` — และมันไม่มีพารามิเตอร์สำหรับ `risk`/`bypass_gate` เลย skill จึงเขียนฟิลด์พวกนั้นไม่ได้แม้จะพยายาม
- เจอตอนเทส: ชื่อ `../evil` ถูก sanitise เป็น `---evil.md` ซึ่ง *ปลอดภัย* แต่คือการบันทึกไฟล์ในชื่อที่ไม่มีใครขอ — เปลี่ยนเป็นปฏิเสธ เพราะตัวเขียนที่เปลี่ยนชื่อให้เงียบ ๆ คือตัวเขียนที่เดาผลจาก input ไม่ได้
- เช็กที่ตัดสินได้ก่อนถามคนถูกย้ายไป `precheck` ทั้งหมด (ชื่อ, การเขียนทับ, อาร์กิวเมนต์) — การอนุมัติที่ใช้ไปกับงานที่ยังไงก็ไม่เกิดคือความสนใจที่เสียเปล่า และครั้งที่สองคนจะเลิกอ่านคำขออนุมัติ

### P8.7 — Accessibility

**สถานะ**

🔶 **บังคับด้วยสคริปต์แล้ว ไม่ใช่ความตั้งใจ**

- `scripts/accessibility-audit.py` รันใน `check.sh` และ fail build ด้วย 3 กฎ เพราะ**ข้อกำหนดที่ไม่มีอะไรบังคับคือความชอบส่วนตัว** (บทเรียน v1 ที่ต้องไล่แก้ 16 ปุ่ม 8 ไฟล์ย้อนหลัง): (1) ปุ่มที่มีแต่ไอคอนต้องมี `accessibilityLabel` — ปุ่มที่ label เป็น SF Symbol ล้วน VoiceOver จะอ่านว่า "play.fill" (2) **ห้าม `.onTapGesture` เป็นทางเดียวไปหา action** — แถวที่กดได้ด้วยเมาส์อย่างเดียวไม่มี control ให้โฟกัส action นั้นจึงไม่มีอยู่จริงสำหรับคนที่ไม่ได้ชี้เมาส์ (3) **`.contextMenu` ต้องมีประตูที่สอง** — คลิกขวาคือเมาส์ และคีย์บอร์ด Mac ส่วนใหญ่ไม่มีปุ่มเมนู ทุกกฎมี `// a11y-ok: <เหตุผล>` ให้ยกเว้นได้แบบที่เหตุผลติดไปกับบรรทัด
- **พิสูจน์ว่ากฎจับได้จริง** ด้วยการใส่ violation กลับเข้าไปทั้งสามแบบแล้วดูว่า fail (กฎที่ผ่านเพราะไม่มีอะไรให้จับ ไม่มีค่า)
- แก้ที่ค้างอยู่: 5 `onTapGesture` เป็น `Button(.plain)` (เปิดสมุดงาน/เปิดแผน/ใส่ SELECT จากชื่อตาราง ×2/ปิดข้อความสถานะ), 5 context menu มี `.accessibilityAction` คู่กัน, จุดสีเขียว "ต่ออยู่" ของ connector ที่เดิมสื่อด้วย**สีกับรูปทรงเท่านั้น** ตอนนี้มีข้อความ
- **⌘1–⌘7 สลับหน้าจอ, ⌘0 หน้าสถานะ** — segmented picker บน toolbar คีย์บอร์ดเข้าถึงได้ต่อเมื่อเปิด Full Keyboard Access ไว้ ซึ่ง "ไปถึงได้ถ้าไปเปลี่ยนค่าในระบบก่อน" ไม่ใช่สิ่งเดียวกับ "ไปถึงได้"
- Dynamic Type: คอลัมน์ป้ายชื่อที่ตรึงไว้ 150/90pt เปลี่ยนเป็น `@ScaledMetric` — ความกว้างคงที่จะตัดข้อความตัวเองทิ้งที่ขนาดใหญ่ ซึ่งคือขนาดที่คนที่ต้องใช้มันเปิดอยู่พอดี
- **ตรวจด้วยตัวขับบนสิทธิ์จริงแล้ว (2026-08-16, E.30)** — `ScreenCheck` อ่าน accessibility tree ซึ่งเป็นต้นไม้เดียวกับที่ VoiceOver อ่าน: รอบแรกเจอ **6 ปุ่มไร้ชื่อ** → สี่เป็น chrome ของ AppKit (scrollbar) สองเป็นปุ่มปิด/ย่อหน้าต่าง → **แก้ของเราแล้วกวาดทั้ง 5 พื้นที่ได้ 0 ทุกพื้นที่**
- สิ่งที่เจอ: `.accessibilityLabel` บน `Button` ที่มี label เป็น `Image` ล้วน**ไม่ถึง VoiceOver** (ต้องอยู่บน `Image` — แก้ 13 จุด) และ placeholder ไม่ใช่ label
- เพิ่ม `subrole` ลง `ScreenElement` เพราะเป็นสิ่งเดียวที่แยกเฟอร์นิเจอร์ของระบบออกจากปุ่มของเรา
- **ลำดับโฟกัสเดินจริงแล้ว (Tab ×20)**: หยุด 3 จุด (ช่องพิมพ์ · ช่องค้น · sidebar) **วนกลับที่เดิม ไม่มีกับดัก และทุกจุดมีชื่อ**
- Tab ไปไม่ถึงปุ่มเลย ซึ่งเป็นพฤติกรรมของ macOS เอง (ต้องเปิด Full Keyboard Access) ตรงกับที่ §14.4 เขียนไว้ ⇒ คีย์ลัดคือทางที่ใช้ได้กับทุกคน
- **การเดินนี้จับได้ว่า "บทสนทนาใหม่" ไม่มีคีย์ลัด** — เริ่มบทสนทนาด้วยคีย์บอร์ดไม่ได้เลยในค่าเริ่มต้น ใส่ ⌘N แล้ว
- **ตรวจป้ายในฐานะ*คำพูด* ไม่ใช่ช่องที่กรอกแล้ว**: `ScreenCheck` ถามเพิ่มว่าป้ายไหนยาวเกิน 80 ตัวอักษร (VoiceOver อ่านทั้งประโยค) และปุ่มไหน**ชื่อซ้ำกัน** (หูแยกไม่ออก) ⇒ โต๊ะทำงานเจอ ×3 "รันเซลล์นี้"
- ×3 "ลบเซลล์นี้" — คำว่า "นี้" ทำงานได้ด้วยสายตาเพราะตาเห็นกรอบ แต่**หูไม่เห็นกรอบ** ⇒ ร้อยเลขลำดับเข้า `CellView` เป็น "รันเซลล์ที่ N" / "ลบเซลล์ที่ N" / "ชนิดของเซลล์ที่ N"
- ส่วน ×3 "Python"/"SQL" **ไม่ใช่ความผิด** เพราะเป็นตัวเลือกใต้ตัวควบคุมที่มีชื่อแล้ว ("ชนิดของเซลล์ที่ 2, Python, เลือกอยู่") ⇒ ตัวตรวจไม่นับลูกที่พ่อแม่มีชื่อ ไม่งั้นทุก segmented picker จะเป็นความผิดตลอดไป
- กวาดใหม่ทั้งห้าพื้นที่: **ป้ายยาวเกิน 0
- ชื่อซ้ำ 0**
- **ค้าง**: เปิด VoiceOver ฟังจริงว่าเสียงที่พูดออกมาเข้าใจได้ไหม
- เดิมเขียนว่า — สคริปต์พิสูจน์ได้ว่าไม่มี action ที่เมาส์เท่านั้นเข้าถึงได้ แต่ "ลำดับโฟกัสสมเหตุสมผลไหม" ต้องมีคนลอง
- sheet/panel ที่กว้างคงที่ (460–520pt) ยังไม่ได้ปรับตาม Dynamic Type
