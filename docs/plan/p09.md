## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P9.1 — Golden-task eval harness

**สถานะ**

- 🔶 **ทำแล้วสำหรับส่วนที่ไม่ต้องใช้โมเดล ([E.35](../verification/03-e31-e46.md#e35-ตาข่ายกันถอยหลังสำหรับสิ่งที่ตัดสินใจก่อนถามโมเดล-p91-2026-08-16), 2026-08-16, 2 ไฟล์อ้างอิง)** — เหตุผลที่ค้างมาตลอด ("ต้องมีงานจริงที่สำเร็จก่อน") จริงเฉพาะกับรูปที่คิดไว้ตอนแรกคือเล่นซ้ำการรันทั้งรอบ ซึ่งต้องมีโมเดล และโมเดลคือสิ่งเดียวที่ `check.sh` ไม่มี
- **แต่สิ่งที่ควรตรึงไม่ต้องใช้โมเดลเลย**: ก่อนถาม LLM สักคำ ระบบตัดสินไปแล้วว่า tier ไหนตอบและเพราะอะไร และทูลที่จะเรียกอันตรายแค่ไหน — ทั้งคู่เป็นฟังก์ชันบริสุทธิ์ของคำขอ และเป็นที่ที่การถอยหลังแบบเงียบแพงที่สุด (ไม่มีอะไร fail คำตอบแค่เริ่มมาจากโมเดลเล็กลง หรือเชลล์เลิกถามก่อนรัน)
- `routing.golden` + `risk.golden` วางข้างเทส **ไฟล์คือสาระ**: การเปลี่ยนพฤติกรรมยังทำได้ แต่ต้องแก้ไฟล์ในคอมมิตเดียวกัน
- **พิสูจน์แล้วว่าจับได้**: ปิดกฎ "งานสำคัญไม่ใช้ on-device" (E.7) ชั่วคราว → แดงทันทีพร้อมบรรทัดที่ต่าง
- **ค้าง**: เล่นซ้ำ*แผนของ agent* จริง ยังต้องมี endpoint จึงยังรันใน `check.sh` ไม่ได้

### P9.2 — Config migration

**สถานะ**

✅ **ผ่าน Done-when (11 เทส)**

- และสิ่งที่ต้องแก้คือพฤติกรรมเดิมที่ทำ *ตรงข้าม* กับ Done-when ในเคสที่ธรรมดาที่สุด: `schemaVersion` เป็นฟิลด์บังคับ ไฟล์รุ่นแรกที่ยังไม่มีคีย์นี้จึง decode ไม่ผ่าน → เข้าทาง `repairedInvalid` → **เขียนค่าเริ่มต้นทับทับของผู้ใช้** ทั้ง endpoint, โมเดล, งบ หายหมด และที่ผู้ใช้เห็นคือแอปลืมการตั้งค่า ซึ่งคือ D5 ของ v1 เป๊ะ
- กฎสามข้อ ทุกข้อเกี่ยวกับการตั้งค่าของคนอื่น: (1) **ไม่มีเวอร์ชัน = เวอร์ชัน 0 ไม่ใช่ไฟล์เสีย** (2) **ไฟล์จากรุ่นที่ใหม่กว่าไม่ถูกเขียนทับเลย** — ใช้ค่าเริ่มต้นรอบนี้ยังกู้ได้ แต่เขียนทับแล้วการตั้งค่าหายจากรุ่นที่เขาจะถอยกลับไปด้วย (เทสเทียบไบต์ว่าไฟล์ไม่ถูกแตะ รวมฟิลด์ที่รุ่นนี้ไม่รู้จัก) (3) **ไม่เขียนทับอะไรโดยไม่สำรองก่อน** — สำเนาอยู่ข้างไฟล์เดิม และหน้าสถานะบอกชื่อไฟล์สำรอง เพราะ "ค่าของคุณถูกย้ายแล้ว" น่าเชื่อได้ต่อเมื่อไปดูได้
- migration เป็น **ข้อมูล ไม่ใช่ `switch`** จึงมีเทสว่าไม่มีเวอร์ชันไหนระหว่าง 1 ถึงปัจจุบันที่ไม่มีขั้นรองรับ — เวอร์ชันที่ถูกบั๊มโดยลืมเขียน migration คือการตั้งค่าที่จะหายในรีลีสหน้า
- ย้าย `effectiveEndpoints` มาเป็น migration step จริง (เดิมแปลงใหม่ทุกครั้งที่อ่าน ไฟล์จึงค้างรูปเก่าตลอดไป)
- **และแก้บั๊กรูปเดียวกันในสี่ store ที่เก็บ list เป็น JSON** (channels, connectors, MCP servers, templates): ไฟล์ที่ decode ไม่ผ่านคืน list ว่าง แล้ว save ครั้งถัดไปเขียนรายการเดียวทับไฟล์ที่มีห้ารายการ — ตอนนี้สำรองไฟล์ก่อนเสมอ และ**เก็บสำเนาที่เก่าที่สุดไว้** เพราะรอบที่สองไฟล์จริงอาจเป็นเวอร์ชันที่ถูกตัดไปแล้ว
- **สี่ไฟล์นั้นมี schema version แล้ว (2026-08-16, 7 เทส + 1 กฎ)** — `VersionedList` เขียนเป็นซอง `{schemaVersion, items}` และอ่านได้ทั้งสองรูป
- **ไม่มีเวอร์ชัน = เวอร์ชัน 0 ไม่ใช่ไฟล์เสีย** เพราะไฟล์ทุกใบที่เขียนก่อนหน้านี้เป็น array เปล่า และเป็นส่วนใหญ่
- **ไฟล์จากรุ่นใหม่กว่าไม่ถูกเขียนทับ** — `save` ปฏิเสธพร้อมเหตุผล และข้อความบอกตรงข้ามกับกรณีไฟล์เสีย: ไฟล์ไม่เป็นไร แอปนี้ต่างหากที่เก่า และ**ไม่ได้แตะไฟล์เลย** (ใช้ default หนึ่งรอบยังกู้ได้ เขียนทับแล้วการตั้งค่าหายจากรุ่นที่จะกลับไปใช้)
- กฎใน check.sh จับการกลับไปใช้ `encoder.encode(list)` ตรง ๆ ซึ่งคอมไพล์ผ่าน round-trip ผ่าน และพังในรีลีสที่เพิ่มฟิลด์
- setting ในตาราง `settings` ของ SurrealDB ยังไม่มี migration path

### P9.3 — Secrets audit

**สถานะ**

✅ **ผ่าน Done-when (23 เทส + สคริปต์)**

- และสิ่งที่เจอตอนตรวจใหญ่กว่าที่ Done-when ถาม: [ARCH §15](../../ARCHITECTURE.md) เขียนไว้ตั้งแต่ต้นว่า secret อยู่ **Keychain** แต่โค้ดอ่านจาก **environment variable** มาตลอด
- วัดด้วยของจริงก่อนสรุป: `export FOO=…` แล้ว `launchctl getenv FOO` **ไม่คืนอะไรเลย** (`PATH` ก็ว่าง) — `.app` ที่เปิดจาก Finder ไม่ได้รับ environment ของเชลล์ แปลว่า **paid endpoint
- บอททั้งสามตัว
- connector ที่มีรหัสผ่าน
- MCP server ที่ต้องใช้โทเคน ไม่มีทางได้รับความลับเลยในแอปจริง** และไม่มีหน้าจอไหนให้พิมพ์ด้วย — **D6 ครั้งที่ 8** และครั้งแรกที่เกิดกับสิ่งที่สเปกเขียนถูกอยู่แล้ว
- แก้: `SecretVault` + `KeychainVault` (พิสูจน์กับ Keychain จริงด้วย probe ที่คอมไพล์แยก: add/read/update/list/delete ครบและลบตัวเองทิ้ง)
- `SecretField` ให้พิมพ์ค่าได้จริงในหน้า endpoint กับ connector — **เขียนอย่างเดียว ไม่มีปุ่ม “แสดง” และไม่มี API ไหนคืนค่าที่เก็บไว้กลับมาให้ UI** เพราะค่าที่ขึ้นจอคือค่าที่อยู่ในภาพหน้าจอ
- **กติกาที่แยกงานนี้ออกจากการย้ายที่เก็บเฉย ๆ**: `.unreadable` ไม่ใช่ `.absent` — Keychain ที่เปิดไม่ได้ต้องไม่ถูกรายงานว่า “ยังไม่ได้ตั้งคีย์” เพราะจะส่งคนไปพิมพ์คีย์ทับของที่มีอยู่แล้ว (กติกาเดียวกับ U21-2 และ P1.8)
- และค่าที่มาจาก environment **ขึ้นสีส้ม ไม่ใช่สีเขียว** เพราะ `launchctl setenv` อ่านได้จากทุกโปรเซสของผู้ใช้คนนั้น ต่างจาก Keychain item
- **การตรวจเป็นเทสจริงไม่ใช่การอ่านโค้ด**: target `SecretsAuditTests` ปลูกค่า canary แล้วขับ store ทั้งสี่ตัวผ่านการ save ปกติ จากนั้น**ค้นทุกไบต์ใต้โฟลเดอร์** (ไม่ใช่ฟิลด์ที่นึกออก)
- ตัวค้นเองมีเทสว่าหาไฟล์ที่มีความลับจริงเจอ เพราะ audit ที่ fail ไม่ได้คือ audit ที่ไม่ได้พิสูจน์อะไร
- `scripts/secrets-audit.sh` ตรวจโฟลเดอร์ข้อมูลจริงบนเครื่อง (รันแล้ว 76 ไฟล์ ไม่พบอะไร) และพิสูจน์แล้วว่าจับ canary ที่ปลูกไว้ได้ทั้งสามแบบ
- กฎใหม่ใน `check.sh` สามข้อ พิสูจน์ว่า fail ได้ทุกข้อ
- **หน้าตั้งค่าบอทมีแล้ว** (`ChannelsView` + `ChannelEditor` พร้อม `SecretField` สำหรับโทเคนและ channel secret ของ LINE) — ข้อความเดิมในแถวนี้ล้าสมัย
- `SecretField` ยังไม่ได้ขับบนหน้าจอจริง — ตัวขับพิมพ์ลง SwiftUI `SecureField` ไม่ได้ (ข้อจำกัดที่บันทึกไว้แล้ว) จึงยืนยันด้วย probe กับ Keychain จริงแทน

### P9.4 — Crash/hang resilience

**สถานะ**

✅ **ผ่าน Done-when (15 เทส)**

- ครึ่ง “ไม่ crash” **จริงอยู่แล้ว**: ทั้ง `Sources/` ไม่มี `fatalError` และไม่มี `try!` เลยนอก executable ที่ใช้ตรวจ และ sidecar มีเทสเดิม 9 ข้อครอบตั้งแต่ถูกฆ่าจากข้างนอก จำกัดจำนวน restart ไปจนถึง readiness timeout — รายงานตามจริง ไม่ได้เขียนใหม่ให้ดูเยอะ
- ครึ่งที่ **ไม่จริง** คือ “error ที่อ่านรู้เรื่อง”
- `ReadableFailure` แปลสี่กรณีที่ Done-when ระบุ โดย**วัดรหัสจริงก่อนเขียน** ไม่ใช่เปิดเอกสาร: ดิสก์เต็ม `NSCocoaErrorDomain 640 ← POSIX 28` (สร้าง disk image 2 MB แล้วเขียน 5 MB ใส่)
- ไม่มีสิทธิ์ `513 ← 13`
- ไม่มีอะไรฟัง `URLError -1004`
- ไฟล์เสีย `DecodingError`
- **กติกาที่สำคัญที่สุดคือคำแนะนำที่ห้ามพูด**: ดิสก์เต็มต้องไม่ลงท้ายว่า “ลองใหม่อีกครั้ง” เพราะบนดิสก์ที่เต็มนั่นคือวงวน — `isTransient` เป็น `false` และมีเทสว่าประโยคไม่มีคำนั้น
- สามในสี่กรณีเทส**สร้างเงื่อนไขจริง** (โฟลเดอร์ที่เขียนไม่ได้จริง · ไบต์ที่ไม่ใช่ JSON จริง · พอร์ตที่ไม่มีใครฟังจริง) ส่วนดิสก์เต็มใช้รูปที่วัดมา เพราะเทสไม่ควรไปสร้างวอลุมบนเครื่องคนอื่น
- **และช่องว่างที่เจอระหว่างทาง**: ไฟล์ list ที่พังถูกสำรองไว้ถูกต้องตั้งแต่ P9.2 แต่**ไม่เคยบอกใคร** — ร่องรอยเดียวอยู่ใน unified log สิ่งที่ผู้ใช้เจอจริงคือรายชื่อบอทว่างเปล่าเช้าวันหนึ่งโดยไม่มีเหตุผล ตอนนี้ `FileStoreIncidents` เก็บรายงานไว้ให้หน้าสถานะแสดง
- `ReadableFailure.message(for:)` **ปล่อยข้อความที่เราเขียนเองผ่านไปตรง ๆ** และแปลเฉพาะของ OS — ไม่งั้นคำปฏิเสธที่ดีอยู่แล้วจะถูกยุบเป็น “ไม่สำเร็จ” เหมือนกันหมด
- สถานะ sidecar บอกด้วยว่า**อะไรจะใช้ไม่ได้**ระหว่างนั้น ไม่ใช่แค่ exit code
- endpoint ที่ตอบแล้วปฏิเสธคีย์ (401/403) แยกเป็น verdict ของตัวเอง เพราะ “ต่อไม่ได้: HTTP 401” ส่งคนไปตรวจเครือข่ายที่ไม่ได้เสีย

### P9.5 — Performance pass

**สถานะ**

- 🔶 **วัดแล้วและแก้ที่เจอ
- Instruments/MetricKit ยังค้าง (2026-08-16, E.29 + 1 กฎ)** — เปลี่ยนคำถามให้วัดได้ก่อน: ไม่ใช่ "ลื่นไหม" แต่คือ **งานที่ถึงคิวบน main actor ถูกดองนานแค่ไหน** (เฟรมละ 16.7 ms)
- วัดด้วย archive 24 MB: decode บน main actor = **ค้าง 81.6 ms (ห้าเฟรม)**
- ย้ายออก = **2.6 ms** — **งานใช้เวลาเท่ากัน ต่างกันที่ใครรอ** ซึ่งคือประเด็นทั้งหมด
- แก้สี่จุดที่เจอ: export/import คลังความรู้ (ไม่มีอะไรจำกัดขนาด) และการเขียน `.docx` สามที่
- **กฎ**: การอ่าน/เขียนไฟล์แบบ synchronous ในไฟล์ของแอปต้องอยู่ใน `Task.detached` (พิสูจน์ว่า fail ได้)
- **ค้าง**: Instruments + MetricKit บนแอปจริงระหว่าง agent ทำงานยาว — เป็นการวัดคนละแบบและต้องมีคนนั่งดู

### P9.6 — Packaging

**สถานะ**

🔶 **แก้ตัวขัดขวางที่ใหญ่ที่สุดแล้ว และวัดข้อจำกัดที่เหลือด้วยของจริง**

- วัดด้วย probe ที่เซ็น App Sandbox จริงก่อนเขียนโค้ด: `/usr/bin/python3`, `/usr/bin/git`, `/usr/bin/swift` เป็น**ไบนารีเดียวกัน** (SHA-256 ตรงกัน) คือ shim ที่เรียก `xcrun` และ `xcrun` รันใน sandbox ไม่ได้ (`cannot be used within an App Sandbox`) ส่วนตัวจริงใต้ shim รันได้ปกติ — จึงเพิ่ม `ExecutableSearch` ใน M9 ที่หาล่ามตัวจริงก่อน `PATH` และใช้ร่วมกันทั้ง notebook kernel กับ MCP/plugin (7 เทส) **ผลคือปลั๊กอินที่ติดตั้งในแอปจริง (sandbox) ขึ้นทูล `mcp__weather__forecast` บน tool list ได้จริงแล้ว** ซึ่ง P8.4 ทำไม่ได้มาก่อน
- **เจอ landmine ของเครื่องอื่น**: binary อ้าง resource bundle ของ SwiftPM ด้วยพาธ build directory ของเครื่องที่คอมไพล์ และ `build-app.sh` ก๊อปเข้าไปแค่ bundle ของ Metal — อีกสามอัน (รวม `swift-transformers_Hub` ที่เรียก `Bundle.module` ตอนโหลดโมเดล) ไม่ได้เข้าไป แปลว่าแอปทำงานบนเครื่องนี้และ trap ที่เครื่องแรกที่ไม่ใช่เครื่องนี้ — ก๊อปครบแล้ว
- **`package-audit.sh`** ตรวจเฉพาะสิ่งที่ผ่านบนเครื่องนี้เสมอไม่ว่าจะพาไปได้หรือไม่ (resource bundle ครบตามที่ binary อ้าง, ไม่มี dylib นอกระบบ, sidecar/Metal/AppIntents ครบ, ลายเซ็น+sandbox ผ่าน) และ `build-app.sh` เรียกมันเป็นขั้นสุดท้ายเลยลืมไม่ได้ — พิสูจน์ว่ากฎจับได้จริงด้วยการเอา bundle ออกแล้วดูว่า fail
- **ปิดเคสตามการตัดสินใจของเจ้าของ (2026-08-16)**: ยังไม่มีและยังไม่สมัคร Developer ID จึง**ข้ามทั้ง notarization และการทดสอบบนเครื่องสะอาด** — ไม่ใช่ของค้างรอโค้ด และแอปเซ็น ad-hoc ซึ่งใช้บนเครื่องนี้ได้ แต่ Gatekeeper เครื่องอื่นจะปฏิเสธ
- เดิมเขียนว่า: **notarization ทำแทนไม่ได้** — ต้องมี Developer ID ของเจ้าของแอป ตอนนี้เซ็น ad-hoc ซึ่ง Gatekeeper เครื่องอื่นปฏิเสธ (ขั้นตอนครบเขียนไว้ใน README แล้ว)
- **ยังไม่ได้ทดสอบบนเครื่องสะอาดจริง** — container ของแอปถูก SIP ป้องกัน ย้ายออกไปทดสอบ first-run ไม่ได้ และผมไม่ลบข้อมูลจริงของผู้ใช้เพื่อจำลอง จึงพิสูจน์ได้แค่ว่า bundle พึ่งตัวเองครบ + แอปเปิดและเริ่ม DB จาก sidecar ใน bundle ได้ ข้อนี้ต้องเครื่องที่สองหรือ user account ใหม่
- **แพ็กเกจ Python ภายนอกยังใช้ในแอปไม่ได้**: ใน sandbox `/opt/homebrew` กับ `/usr/local` **มองไม่เห็นเลย** (วัดแล้ว) ล่ามเดียวที่รันได้คือตัวจาก Command Line Tools ซึ่งไม่มี pandas/numpy — notebook (P6.4) ในแอปจริงจึงได้ Python 3.9 เปล่า ๆ และ venv ของ SearXNG (Homebrew 3.14) ก๊อปเข้า `.app` ไม่ได้ (P3.1) ทางแก้เดียวคือพา Python framework เข้า bundle ซึ่งเป็นงานก้อนถัดไปของ P9.6
