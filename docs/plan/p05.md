## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P5.1 — `MLXRuntime`

**สถานะ**

🔶 **รันโมเดลบนเครื่องได้จริงผ่าน `LLMExecutor` ตัวเดียวกัน และผ่าน contract ชุดเดียวกับ executor อื่น**

- contract ย้ายออกจากไฟล์เทสมาเป็น target `ExecutorContract` เพราะ Tier 0.5 รันใน `swift test` ไม่ได้เลย (MLX หา metallib ผ่าน main bundle — E.13 เดิม) ถ้าเขียนแยกกันสองชุด ชุดที่อ่อนกว่าจะกลายเป็นชุดที่คุ้ม tier ที่ทุกอย่างตกลงมาพอดี
- `Tests/LLMProvidersTests` รัน 8 เคสนี้กับ Tier 0/Tier 1, `MLXCheck` รันเคสเดียวกันกับน้ำหนักจริงใน `check.sh`
- **ผลจริงบน qwen3.5-9B-4bit**: สตรีม 29 text + 456 reasoning delta
- reasoning แยกจากคำตอบ
- structured output 1.3 วิ
- tool call ประกอบกลับเป็น JSON ที่ใช้ได้
- prompt เกิน context ถูกปฏิเสธก่อนยิง
- **สามอย่างที่ tier นี้ต้องทำเอง** เพราะไม่มีโปรโตคอลไหนทำให้: (1) **`<think>` ไม่มีแท็กเปิด** — chat template ของ Qwen เปิด think block ไว้ใน*พรอมป์ต์* ผลลัพธ์จึงเริ่มกลางความคิด จึง**ถาม template ตอนรัน** ไม่ใช่เดาจาก output (เดาไม่ทัน — กว่า `</think>` จะพิสูจน์ว่าที่ผ่านมาคือความคิด ความคิดนั้นก็ถูกสตรีมออกไปเป็นคำตอบแล้ว เป็น E.9 เคส 8c เวอร์ชัน local) (2) **ไม่มี guided generation ใน mlx-swift-lm** — schema จึงเป็นคำสั่งใน prompt แล้วดึง JSON object แรกออกมา; ไม่มี JSON = error ที่ escalate ได้ ไม่ใช่สตริงว่างที่ปลายทางอ่านว่า "ไม่มีข้อขัดแย้ง" (3) **ปิด thinking เมื่อขอ schema** — วัดจริง: ขอ routing object เพดาน 2,048 token โมเดลคิดจนหมดเพดานแล้วไม่ตอบอะไรเลย **102.7 วิ ได้สตริงว่าง** → ปิด thinking เหลือ **1.3 วิ**
- **context window ประกาศ 32,768 ไม่ใช่ 262,144 ที่ config บอก** — บน 16GB prompt 7.6k โทเคนกิน ~7.4GB (บันทึกไว้ใน `Engine.swift`) ตัวเลขที่ใจกว้างจะดึงพรอมป์ต์ที่ทำเครื่องล่มเข้ามาพอดี (P5.3 จะวัดจาก RAM จริง)
- **residency**: โหลดครั้งแรกแล้วค้างไว้ ปลดเมื่อ idle แล้วโหลดกลับได้ — เช็คทั้งสามข้อกับของจริง
- **ค้าง**: **แอปที่ sandbox มองไม่เห็น `~/.lmstudio`** — โมเดลสองตัวบนเครื่องนี้อยู่นอก container ทั้งคู่ แอปจริงจึงยังไม่มี Tier 0.5 (หน้าบูตบอกไว้แล้วว่า "พื้นรับประกันหายไป") เข้าถึงโฟลเดอร์ของผู้ใช้ต้องผ่าน open panel = งาน P5.2
- ยังไม่ได้กดใช้บนหน้าแชทจริง (ผ่าน contract กับน้ำหนักจริงแล้ว)

### P5.2 — Model manager UI

**สถานะ**

✅ **ผ่าน Done-when

- กดโหลดจริงในแอปที่ sandbox แล้ว (ปิด U16)**
- แท็บที่ห้า "โมเดล": รายการที่ติดตั้งแล้ว + รายการแนะนำพร้อมขนาด/RAM ที่ต้องใช้ + แถบโควตา
- **หลักฐานบนหน้าจอ**: แอปขึ้น "ยังไม่มีโมเดลบนเครื่องนี้" (ยืนยัน U16 ว่าโมเดลใน `~/.lmstudio` มองไม่เห็นจากใน container) → กดโหลด Qwen3-0.6B → progress bar เดิน → เสร็จแล้วขึ้นในรายการ "ใช้อยู่" 335 MB context 32768 → โควตาอัปเดตเป็น 335 MB/60 GB → **ปิดแอปเปิดใหม่ยังจำได้** (`localModel` ลง bootstrap.plist) → กดยกเลิกกลางคัน ได้ข้อความว่าไฟล์ที่โหลดเสร็จยังอยู่
- **เลือกโมเดลแล้วใช้ได้เลยไม่ต้องรีสตาร์ท** — router ถือ `LocalTier` ซึ่งเป็น "ช่อง" ไม่ใช่โมเดลตายตัว (การโหลดครั้งแรกบนเครื่องที่ไม่เคยมีโมเดล คือจังหวะที่คนกำลังดูอยู่พอดีว่ามันใช้ได้ไหม)
- **รายการแนะนำ = สิ่งที่ runtime โหลดได้จริง** ไม่ใช่ทุกอย่างบน Hub — อ่านจาก type registry ของ mlx-swift-lm เอง
- **ห้าบั๊กที่เจอเพราะกดจริง**: (1) `Qwen3-VL-4B` มีไฟล์ครบทุกอย่างของโมเดลแชทแต่ `unsupportedModelType("qwen3_vl")` ตอนโหลด — และมันเป็นโมเดลที่ใหญ่ที่สุดบนเครื่อง จึงเป็น Tier 0.5 พอดี (2) `HubApi` เก็บ **สำเนาที่สองในแคชกลาง** คู่กับ snapshot ที่มันคลายให้ (335 MB กลายเป็น 670 MB) และสำเนาที่โควตามองไม่เห็นคือสำเนาที่ทำดิสก์เต็ม → `cache: nil` (3) ยกเลิกดาวน์โหลดขึ้นเป็น **error สีแดง `NSURLErrorDomain -999`** เพราะ URLSession โยน error ก่อน `CancellationError` จะเกิด (4) แถบ progress ขยับแต่ตัวเลขค้าง "0 MB / 0 MB" — Progress ของ Hub นับ**ไฟล์** ไม่ใช่ byte (5) โมเดลใน HF cache รายงานขนาด ~0 เพราะเป็น symlink ไป `blobs/` ทำให้ `preferred()` แพ้ให้ไฟล์จริงทุกครั้ง
- **ดาวน์โหลดที่ยกเลิกไว้ต้องไม่ถูกนับว่าติดตั้งแล้ว** — ไฟล์เล็กมาก่อน โมเดล 17 GB ที่ค้างจึงมี config+template+shard เดียวและอ่านว่าพร้อมใช้ จนไปพังตอนโหลด (เช็ค shard จาก `model.safetensors.index.json`)
- **ลบไฟล์ที่ค้างได้แล้ว (2026-08-16, 5 เทส)** — `incompleteDownloads` หาไดเรกทอรีที่หน้าตาเป็นโมเดลแต่โหลดไม่ได้ แล้วบอก**ว่าขาดอะไรและใหญ่แค่ไหน** ("ขาดไฟล์น้ำหนัก 2 ชิ้น · 4.1 GB") เพราะคำว่า "ไม่สมบูรณ์" ไม่บอกว่าเกือบเสร็จหรือเพิ่งเริ่ม
- แยกจากรายการที่ติดตั้งแล้วโดยตั้งใจ — มันไม่ใช่โมเดล และการเอาไปรวมกันคือวิธีที่ไดเรกทอรีพัง 17 GB ถูกเลือกเป็น Tier 0.5
- **ลบได้เฉพาะของที่แอปนี้โหลดเอง** — ของที่ค้างอยู่ในคลัง LM Studio หรือ HF cache ขึ้นรายการพร้อมพาธแต่ไม่มีปุ่มลบ เพราะการเก็บกวาดที่เอื้อมเข้าไปในของโปรแกรมอื่น สุดท้ายจะลบของที่คนอื่นใช้อยู่ (กฎอยู่ใน catalog ไม่ใช่ในหน้าจอ)
- resume เป็นระดับไฟล์ไม่ใช่ระดับ byte (ไฟล์ที่โหลดเสร็จไม่ถูกดึงซ้ำ ไฟล์ที่กำลังโหลดเริ่มใหม่)
- quota ยังแก้ในแอปไม่ได้ ต้องแก้ `modelQuotaGigabytes` ใน bootstrap.plist

### P5.3 — Admission control

**สถานะ**

✅ **ผ่าน Done-when

- บังคับสามชั้น 12 เทส (ตรวจซ้ำ 2026-08-17)**
- การกดบนหน้าจอเป็นของแถม ไม่ใช่เงื่อนไขของแถว และ**ต้องมีโมเดลที่ใหญ่กว่าแรมว่างติดตั้งอยู่จริงถึงจะเห็นปุ่มถูก disable** ซึ่งเครื่องนี้ไม่มี (มีแค่ 0.6B กับ 4B) — เป็นเหตุผลที่ระบุได้ ไม่ใช่ "ยังไม่ได้ทำ" ลอย ๆ
- สิ่งที่กันคือ**เครื่องค้าง ไม่ใช่คำตอบผิด**: โมเดลที่ใหญ่กว่าที่ว่างไม่ได้ตอบช้า แต่ทำให้ทั้งเครื่องใช้ไม่ได้เป็นนาทีระหว่าง swap
- **ประเมินจากรูปร่างของโมเดลเอง ไม่ใช่กฎคร่าวๆ**: weights + KV cache ที่คำนวณจาก `num_hidden_layers`/`num_key_value_heads`/`head_dim` ใน config (qwen3.5-9B = **128 KB ต่อ token**) + overhead 0.5 GB
- ยึดกับการวัดจริงที่เดียวที่มี: 9B-4bit บนดิสก์ 5.6 GB, prompt 7.6k โทเคนใช้ ~7.4 GB → ประเมินได้ 7.1 GB (คลาด <10% มีเทสยืนยัน)
- **สามจุดที่บังคับ**: (1) `select()` บนหน้าโมเดล — เกินแล้ว**กดไม่ได้** พร้อมตัวเลขทั้งสองข้าง (2) `isAvailable()` ถามทุกครั้ง ไม่ใช่ตอนบูต — โมเดลที่พอดีตอนเปิดแอปไม่พอดีตอนงานวิเคราะห์ถือ 10 GB และ tier ที่ตอบว่า "ไม่ว่าง" ทำให้ router ขึ้น tier ถัดไป ซึ่งดีกว่า tier ที่ตอบว่าได้แล้วทำเครื่องล่ม (3) `preferred()` เลือก**ตัวใหญ่ที่สุดที่พอดี** ไม่ใช่ตัวใหญ่ที่สุด
- **ตาราง §9.4 อยู่ในโค้ดจริง**: เครื่องนี้ 16 GB → แนะนำ 7–8B → รับ routing/extraction/สรุป/งานเขียนสั้น
- **เห็นผลทันทีบนเครื่องนี้**: ตอน LM Studio ถือ RAM อยู่ เหลือว่าง 6.1 GB → 9B (ต้องการ 7.1 GB) ถูกปฏิเสธ contract จึงข้ามแบบดังๆ แทนที่จะรัน — และนั่นคือพฤติกรรมที่ถูก
- **ค้าง**: ยังไม่ได้กดปุ่มที่ถูก disable บนหน้าจอจริง (จอเครื่องหลับตอนถึงคิว)
- ยังไม่มีทางกด "ใช้ทั้งที่เตือน" ถ้าผู้ใช้ยืนยันเอง — §9.4 บอกว่าห้ามตั้ง default ก็ยังห้ามอยู่

### P5.4 — Tier 0.5 เป็นพื้นรับประกัน

**สถานะ**

✅ **ผ่าน

- ปิด LM Studio จริงแล้วแอปยังตอบได้จากโมเดลบนเครื่อง**
- หัวแชทขึ้น `mlx:mlx-community/Qwen3-VL-4B-Instruct-4bit · tier 0.5` ไม่ใช่ endpoint
- **ไม่ได้ตัดเน็ตของเครื่องจริง** — จำลองแบบที่ระบบจะเจอจริง: endpoint ถูกตั้งไว้แต่ไม่มีใครตอบ (พอร์ต 9) ซึ่งคือหน้าตาเดียวกันกับเน็ตล่ม/ปิดฝา/งบหมด
- เช็คอัตโนมัติใน `MLXCheck`: (1) endpoint ต่อไม่ได้จริง (2) **งาน high-impact ตกลงมาที่ Tier 0.5 และได้ JSON กลับมา** (3) **ตรวจข้อขัดแย้งแล้วโมเดลตอบ ไม่ใช่เงียบ** — ข้อ 3 คือหัวใจของ U13: tier ที่ต่อไม่ได้ต้องไม่อ่านว่า "สองแหล่งตรงกัน"
- **Tier 0.5 ใช้ Qwen3-VL-4B ได้แล้ว** — VL checkpoint สร้างด้วย `VLMModelFactory` คนละตัวกับ text (เดิมตกที่ `unsupportedModelType("qwen3_vl")`) และบนเครื่องนี้มันคือโมเดลเดียวที่ใช้ได้จริง
- **สี่อย่างที่ต้องแก้เพื่อให้โมเดล 4B ใช้งานได้จริง**: (1) schema เป็น **ตัวอย่างให้ลอก** ไม่ใช่ spec ให้ตีความ (โมเดลคืน `{"role: "engineer"` ขาดทั้ง quote และปีกกา) (2) **temperature 0 ตอนขอ JSON** + retry ที่ sample ต่างออกไป (retry ที่ temp 0 ซ้ำความผิดเดิมทุกโทเคน) (3) **ซ่อมวงเล็บ/quote แบบมีขอบเขต** — ซ่อมเฉพาะเครื่องหมาย ไม่แตะค่า (4) **repetition penalty 1.05** — ไม่มีมันโมเดลตอบ "ไมรนบน" สามร้อยรอบบน transcript ภาษาไทยที่ย่อแล้ว
- **คุณภาพที่ได้จริงบน 4B**: ตอบเลขถูก (17×3 = 51) แต่สะกดไทยเพี้ยน ("เทากบ") และตัดสินข้อขัดแย้ง metformin ว่า "ไม่ขัดแย้ง" — ตรงกับตาราง §9.4 ที่บอกว่าเครื่อง <16GB ได้โมเดลระดับ fallback ไม่ใช่ระดับนักวิเคราะห์
- **ค้าง**: ยังไม่ได้ทดสอบตัดเน็ตจริงทั้งเครื่อง (ปิด Wi-Fi = เปลี่ยน system setting ไม่ทำให้เอง)
- KB/embedding ทำงาน local อยู่แล้วแต่ยังไม่ได้รวมในเช็คเดียวกัน

### P5.5 — Endpoint registry + validation

**สถานะ**

✅ **แท็บที่หก "ระยะไกล"

- กดจริงแล้ว**
- หลายๆ endpoint พร้อมกัน แต่ละอันประกาศ `kind` ซึ่งเป็นเส้นแบ่งเดียวระหว่างฟรีกับเสียเงิน
- **จุดสถานะถาวร + ปุ่มตรวจใหม่ทั้งหมด** (probe ไม่กิน token)
- **บันทึกได้ต่อเมื่อ probe ผ่าน** — หลักฐานบนหน้าจอ: กดบันทึก endpoint ที่ต่อไม่ได้ → ขึ้นแดง "ยังไม่บันทึก — ต่อไม่ได้" และไม่ถูกเพิ่มเข้ารายการ (Done-when ข้อนี้พอดี เพราะ E.9 เคส 8a บอกว่าเซิร์ฟเวอร์ยอมรับชื่อโมเดลที่ไม่มีอยู่)
- **ของเดิมย้ายเข้ามาเอง** — `selfHostedEndpoint`/`selfHostedModel` ใน bootstrap.plist กลายเป็น endpoint แรกในทะเบียนโดยผู้ใช้ไม่ต้องทำอะไร (เห็นบนหน้าจอ: "Self-hosted · ค่าเริ่มต้น")
- **API key ไม่เคยลงไฟล์** เก็บแค่*ชื่อตัวแปร* env (Keychain จริงคือ P9.2)
- ตั้ง override ต่อ role ได้ในโครงสร้างแล้ว (ยังไม่มี UI)
- 14 เทส
- **ค้าง**: เส้นทางบันทึกสำเร็จยังไม่ได้กดจริง เพราะไม่มี endpoint ที่รันอยู่ตอนนี้

### P5.6 — Budget Governor

**สถานะ**

✅ **ผ่าน Done-when ด้วยเทสตรงตัว**

- ตั้งเพดานต่ำ → router ข้าม paid ไปใช้ tier ที่ฟรี และงาน**สำเร็จ** ไม่ใช่ error (เกินเพดานเป็นสัญญาณ routing ตาม §9.2 ข้อ 4)
- เพดานสี่ชั้น (ครั้ง/session/วัน/เดือน) ชั้นไหนถึงก่อนบล็อกก่อน และ**ข้อความบอกว่าชั้นไหน** — "เกินงบ" เฉยๆ คือข้อความที่ทำให้คนปิดระบบงบทิ้ง
- **ประเมินก่อนยิง** จาก `maxTokens` (มองโลกในแง่ร้ายโดยตั้งใจ) แล้ว**ลงบัญชีจริงจาก usage ที่ endpoint คืนมา**
- **endpoint ที่คิดเงินแต่ไม่ได้ตั้งราคา = ไม่ยอมใช้** ดีกว่าเดาด้วยเงินคนอื่น
- `SpendLedger` อยู่ใน AgentKit (Config เขียนเพดาน, Persistence เก็บยอด, LLMProviders บังคับ — รูปแบบเดียวกับ `Embedder`) และยอดเก็บลง SurrealDB เพราะเพดานต่อวัน/เดือนที่รีเซ็ตตอนปิดแอปไม่ใช่เพดาน
- 8 เทส

### P5.7 — Cost/usage UI

**สถานะ**

🔶 **อยู่บนแท็บเดียวกับ endpoint** เพราะเป็นการตัดสินใจเดียวกัน (สวิตช์กับฟิวส์ควรอยู่ห้องเดียวกัน)

- ช่องเพดานทั้งสี่พร้อมแถบ "ใช้ไป $X / $Y" ข้างๆ และรายงานเดือนนี้แยกตามโมเดล·role พร้อมจำนวน token
- หน้าจอขึ้นถูกต้องแล้วว่า **ยังไม่มี endpoint ที่คิดเงิน เพดานจึงยังไม่มีผลกับอะไร** — ซึ่งเป็นความจริงของเครื่องนี้
- **ค้าง**: ยังไม่เคยมีตัวเลขจริงให้ดู เพราะยังไม่มี paid endpoint (จะเห็นค่าจริงเมื่อ GX10 หรือ hosted API พร้อม)
- แถบงบยังไม่โผล่บนหัวแชท มีแต่ในแท็บนี้
