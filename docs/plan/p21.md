## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P21.1 — หลายโปรเจกต์เปิดพร้อมกัน

**สถานะ**

- ✅ **ครบ และยืนยันบนหน้าจอจริงแล้ว ([E.34](../verification/03-e31-e46.md#e34-แท็บจำที่ของตัวเองไหม--และการวัดที่กลืนคำปฏิเสธของตัวเองทิ้ง-2026-08-16), 2026-08-16, 13+5 เทส)** — `OpenWorkspaces` ใน ProjectKit ถือกฎทั้งสี่ข้อ: General ปิดไม่ได้
- เปิดซ้ำ = ย้ายไปแท็บนั้นไม่ใช่เปิดใหม่ (สองแท็บบนโปรเจกต์เดียวคือสองมุมมองที่เถียงกันว่าใครบันทึกทีหลัง)
- **ปิดแท็บที่กำลังดูอยู่แล้วไปที่แท็บข้างเคียง ไม่ใช่เด้งกลับ General**
- โปรเจกต์ที่ถูกลบ/ถูกปิดจากที่อื่น ถูก reconcile ทุกครั้งที่รายการโหลดใหม่
- ✅ **ต่อเข้าหน้าจอแล้ว (2026-08-16)** — `ProjectsViewModel` ถือ `OpenWorkspaces` แทน `selection` เดี่ยว (`selection` เหลือเป็นค่าที่*อ่านจาก* `workspaces.active` จึงไม่มีทางถือสองค่าที่ขัดกัน)
- มีแถบแท็บอยู่เหนือทุกพื้นที่ ไม่ใช่ในหน้า Plan อย่างเดียว เพราะ workspace ไม่ใช่ state ของหน้าจอใดหน้าจอหนึ่ง
- **แต่ละแท็บจำว่าค้างอยู่พื้นที่ไหน** (`areaByTab` คีย์ด้วย id ของแท็บ ⇒ ปิดแล้วเปิดใหม่เริ่มที่ Chat ไม่ใช่ทวงที่เดิมจากก่อนปิด)
- แท็บที่เป็น archive ขึ้นแม่กุญแจและบอกด้วยเสียง เพราะคนที่มองไม่เห็นสถานะจะอ่านการปฏิเสธการแก้ว่าเป็นบั๊ก
- เมนูเปิดโปรเจกต์แสดงโปรเจกต์ที่ปิดแล้วด้วย พร้อมป้าย "อ่านอย่างเดียว" — การไม่แสดงทำให้ "ปิดแล้ว" อ่านว่า "หายไปแล้ว"
- **กฎใหม่สองข้อใน `check.sh` พิสูจน์แล้วว่าจับได้**: selection ที่กลับไปเป็นค่าเดี่ยวที่เก็บไว้
- แถบแท็บที่ไม่มีใครวาด (D6 รูปเดิม)
- **ข้อที่ค้างไว้ (`.id(scope.storageKey)` 8 จุด) จบใน P21.2 แต่ไม่ใช่ด้วยการลบทิ้ง** — ดูแถวถัดไป
- **ขับจริงสามแท็บแล้ว (2026-08-16)**: ตั้ง tab1=โต๊ะทำงาน
- General=คลังความรู้
- tab2=ระบบ แล้วไล่กลับ — แต่ละอันคืนที่เดิมครบทั้งสาม ⇒ Done-when ผ่านบนของจริง
- **ระหว่างทางเปลี่ยนการจำที่ให้รัดกุมขึ้น**: เดิมเป็น `onChange` สองตัวที่ทิ้งค่า `previous` ที่ SwiftUI ส่งให้ แล้วอ่าน `active` มาเป็นคีย์ ซึ่งระหว่างสลับมันขยับไปแล้ว ⇒ ย้ายกฎมาเป็น `TabAreaMemory` ใน ProjectKit ที่รับทั้งสองปลายของการสลับพร้อมกัน (5 เทส)
- **ไม่ใช่การแก้บั๊กที่วัดได้** — build โค้ดเดิมแล้ววัดด้วยวิธีเดียวกัน โค้ดเดิมก็ผ่าน จึงบันทึกไว้ตามนั้น

### P21.2 — งานที่รันอยู่ไม่ตายเพราะสลับแท็บ

**สถานะ**

✅ **ทำแล้ว (2026-08-16, 4 เทส + 3 กฎใน check.sh)**

- **หัวหน้าทีมมีคนละคนต่อ workspace** (`WorkspaceTeams` ใน CoreEngine): เดิมมี `TeamOrchestrator` ตัวเดียวทั้งแอปแล้วหมุนด้วย `use(scope:)` ทุกครั้งที่สลับแท็บ ซึ่ง**กลางรันจะถูกปฏิเสธ** (ถูกแล้ว — ครึ่งรันลงโปรเจกต์หนึ่ง อีกครึ่งลงอีกโปรเจกต์ คือบันทึกที่ไม่มีใครอ่านได้) **แต่การปฏิเสธเงียบ ๆ แปลว่าแท็บที่สลับ*ไป* ลงบันทึกใต้ชื่อโปรเจกต์ที่เพิ่งออกมา** — เทสยิงตรงบรรทัดนั้น และพิสูจน์แล้วว่าแดงเมื่อเอาแบบเดิมกลับมา
- **แบบจำลองหน้าจอก็เป็นของ workspace** (`WorkspaceModels`): ของเดิมมี `TeamViewModel`/`AnalysisViewModel` อย่างละตัวแล้วหมุนตามแท็บ ⇒ แถวของโปรเจกต์ที่ออกมากับที่เข้าไปรวมเป็นรายการเดียว
- **แชทเป็นเคสที่หนักที่สุด**: view model ถูกสร้าง*ในวิว*ที่ identity คือ scope ⇒ สลับแท็บ = โยนโมเดลทิ้งทั้งที่เทิร์นยังสตรีมอยู่ ตอนนี้โมเดลอยู่กับ workspace จึงอยู่ข้ามการ rebuild
- **ปิดแท็บ = ปิดหน้าต่าง ไม่ใช่หยุดงาน** — ทั้งสองทะเบียนปฏิเสธการปล่อย workspace ที่ยังทำงานอยู่ เพราะปล่อยไปก็ไม่ได้หยุดรัน แค่ทิ้งสิ่งเดียวที่ยังมองเห็นมัน
- **attach ครั้งเดียวต่อ workspace** ⇒ กลับมาที่แท็บเดิมไม่อ่านฐานข้อมูลใหม่อีกรอบ (นี่คือข้อที่ P21.1 ค้างไว้)
- **`.id(scope.storageKey)` ยังอยู่ และตั้งใจให้อยู่** — มันคือ identity ที่ถูกสำหรับ state ของ*วิว* (ข้อความที่พิมพ์ค้าง ชีตที่เปิดอยู่ เป็นของแท็บนั้น) การลบทิ้งเฉย ๆ โดยไม่ทำที่เก็บ state ต่อแท็บ จะกลายเป็น**วิวเดียวใช้ `@State` ร่วมกันข้ามโปรเจกต์** ซึ่งคือการรั่วที่ P21.1 เขียนเทสกันไว้พอดี สิ่งที่เปลี่ยนคือไม่มีอะไรที่สำคัญห้อยอยู่กับมันแล้ว
- **ค้าง**: state ของวิวเอง (ตำแหน่งสกรอลล์ ฟอร์มที่กรอกค้าง) ยัง reset เมื่อกลับมา เพราะมีวิวของแท็บเดียวที่มีชีวิตอยู่ในแต่ละขณะ — แก้ได้ด้วยการเลี้ยงวิวของทุกแท็บไว้พร้อมกัน ซึ่งแลกด้วยการรัน `task` ของทุกแท็บพร้อมกัน

### P21.3 — ปิดโปรเจกต์ = archive เขียนไม่ได้

**สถานะ**

✅ **ทำแล้ว (2026-08-15, 7 เทส + กฎใน check.sh)**

- ประตูปิดโครงการมี 8 เงื่อนไขมาตั้งแต่ P10.10 และ **หลังผ่านแล้วไม่มีอะไรห้ามใครแก้ต่อเลย** ⇒ รายงานปิดโครงการเป็นคำกล่าวถึงสถานะที่ขยับได้หลังเขียน
- `requireWritable` อยู่ที่ `ProjectService` ทุกทางเขียน (แก้โปรเจกต์ · ใบงาน · ลบใบงาน · ปิดใบงาน · ทะเบียน · ตัดสินคำขอเปลี่ยนแปลง) ไม่ใช่ซ่อนปุ่ม เพราะทูลของ agent กับช่องทางแชทก็เขียนได้เหมือนกัน
- **ข้อยกเว้นเดียวคือการวัดผลประโยชน์** (§19.12 นัดทบทวนอยู่หลังปิดหลายเดือน — การวัดคือ*เพิ่มข้อเท็จจริง* ไม่ใช่แก้ข้อตกลง) และมีเทสคุมทั้งสองฝั่ง
- **การปิดเองต้องไม่ถูกกั้น** — guard อยู่บน `update` สาธารณะ ไม่ใช่บน `persist` ที่ transition เขียนผ่าน ไม่งั้นการเปลี่ยนขั้นครั้งสุดท้ายจะเป็นสิ่งเดียวที่ระบบบันทึกไม่ได้
- กฎใน `check.sh` **พิสูจน์แล้วว่าจับได้** เมื่อมีคนเพิ่มทางเขียนใหม่แล้วลืม guard

### P21.4 — ความรู้ย้ายขึ้นส่วนกลางตอนปิด

**สถานะ**

✅ **ทำแล้ว (2026-08-16, 8 เทส + ขับผ่านฐานข้อมูลจริงใน `EmbeddingCheck` + 2 กฎใน check.sh)**

- กฎอยู่ที่ `ClosingHandoverPolicy` (Knowledge, ตรวจได้โดยไม่ต้องมีฐานข้อมูล) ส่วนการย้ายอยู่ที่ `ClosingHandoverStore` (Persistence) และ `ProjectService` เรียกตอนปิด**พร้อมกับบทเรียน** ไม่ใช่คนละจังหวะ
- **ขึ้น**: เอกสารอ้างอิงภายนอก (upload/web) **พร้อม tier เดิม** — ขึ้นไปโดยไม่มี tier คือถูกจัดอันดับใหม่เหมือนไม่เคยมีใครประเมิน
- คำตัดสินข้อขัดแย้งที่**คนประกาศเป็น central** เท่านั้น (คำตัดสินที่ผูกกับนิยามของงานนี้ ไม่ใช่กฎของงานหน้า และคำตัดสินที่ระบบทำเองไม่ใช่ precedent ของใคร)
- **ไม่ขึ้น**: `.fieldwork` — **นี่คือข้อจริยธรรม ไม่ใช่ข้อจัดเก็บ**: บทสัมภาษณ์กับ paper เป็นข้อความในดัชนีเดียวกัน รูปร่างเดียวกัน ขนาดพอกัน มีแต่ `Origin` ที่บอกได้ว่าอันไหนไปต่อได้
- ตารางที่ดึงจากฐานข้อมูลก็ไม่ขึ้น เพราะระบบบอกไม่ได้ว่ามีข้อมูลบุคคลอยู่ไหม — ปฏิเสธคือด้านที่ผิดแล้วแก้คืนได้
- ร่างระหว่างทางไม่ขึ้น (บทเรียนขึ้นทางของมันเอง เพราะ*การเป็นบทเรียน*คือการตัดสินใจของคน ไม่ใช่คุณสมบัติของข้อความ)
- **ปิดซ้ำไม่ทำสำเนา** เพราะ id เดิม
- **ของที่ไม่ขึ้นยังอ่านได้ในโปรเจกต์ที่ปิดแล้ว** — คำสัญญาคือเรื่องการเผยแพร่ต่อ ไม่ใช่การลบ
- **กฎใน check.sh สองข้อ พิสูจน์แล้วทั้งคู่**: `.fieldwork` ที่เลิกตอบว่า `stays`
- `default:` ที่โผล่มา ซึ่งจะทำให้แหล่งข้อมูลชนิดใหม่ได้คำตอบของคนอื่นโดยไม่มีใครถาม
