## เหตุผลและสิ่งที่วัดได้ — รายละเอียดต่อ task


### P13.1 — เลือก backend ที่แพ็กเข้าแอป sandbox ได้

**สถานะ**

✅ **ผ่าน Done-when (14 เทส + ขับจริงใน .app ที่ sandbox)**

- `WKWebView` แบบไม่มีหน้าต่างในแอป: ค้นได้ผลจริง 8 รายการ และ "อ่านหน้านี้" ได้บทความ 38 ย่อหน้าเข้าท่อ `Readability`/provenance เส้นเดิม
- **`HeadlessPageReader` conform `PageReading`** ⇒ `fetch_page`/`ingest_url` ทั้งเส้นได้เบราว์เซอร์ไปใช้โดยไม่ต้องแก้อะไร (นี่คือเหตุผลที่ยอมทำเป็น protocol ตั้งแต่ P3)
- **DOM เป็นตัว parse** (`querySelectorAll` ผ่าน `evaluateJavaScript`) ไม่ใช่ regex บน HTML แบบ v1 ที่พังทุกครั้งที่ markup ขยับ
- **หน้าโหลดสำเร็จแต่อ่านไม่ได้เลย = error ของตัวอ่าน ไม่ใช่ 'ไม่มีผลลัพธ์'** (เทสยืนยันข้อความ)
- **เจอ CAPTCHA/403/429/`/sorry/` = ขอให้คนช่วย** ไม่ใช่ผลว่าง และระบบไม่แก้ CAPTCHA
- เทสแยกด้วยว่า*บทความเกี่ยวกับ* CAPTCHA ไม่ใช่ CAPTCHA (สแกนแค่หัวเอกสาร)
- ล้าง cookie/storage ทุกครั้งที่ค้น + หน่วงต่อโดเมน + cache ต่อคำค้น
- ค่าเริ่มต้นไม่ใช่ Google โดยตั้งใจ (เทสกันไว้)
- **บั๊กที่การขับจับได้**: ผลค้นไทยเป็น T5 ทั้งหมด ⇒ งานวิจัยไทยอ้างอิงไม่ได้เลยตามกติกา §14.1 — เพิ่ม TCI/ThaiJO เป็น T2 และคลังมหาวิทยาลัย/ThaiLIS/วช. เป็น T3 แล้วค้นซ้ำได้ tier จริง

### P13.2 — ต่อเข้า tier registry + tool

**สถานะ**

✅ **ผ่าน Done-when (11 เทส + 1 ด่านขับ)**

- **กติกา §14.1 เคยเป็นแค่ย่อหน้าในรายงาน ไม่ใช่ประตู**: `CrossSource.assess` ถูกใช้ที่เดียวคือส่วน Limitations ของเอกสาร ⇒ QA ของ Researcher นับจำนวน citation แต่**ไม่เคยดู tier** ⇒ บล็อกสองอันผ่านได้
- แก้โดยย้ายตัวกฎไป `AgentKit.Corroboration` (โมดูลที่ทั้งสองฝั่งพึ่งอยู่แล้ว) แล้วให้ทั้ง Limitations และ QA เรียกตัวเดียวกัน — สองสำเนาของกฎเดียวจะเพี้ยนครั้งแรกที่มีใครปรับ และสำเนาที่สำคัญคืออันที่ปล่อยงานผ่าน (§0.2 ข้อ 3)
- **tier เดินทางจาก tool ถึง QA**: `Evidence` มี `tier` แล้ว
- `fetch_page` เขียน `tier:` เป็น**บรรทัดแรก** (จึงรอดการตัด 200 ตัวอักษรตอนทำ evidence)
- `CitationTier` เขียน/อ่านที่เดียวและมีเทส round-trip
- **citation ที่ไม่มี tier ไม่ใช่ 'น่าจะโอเค'** — ถือว่าแบกข้อสรุปไม่ได้เหมือนบล็อก
- **อ่านหน้าเดียวสองครั้ง = แหล่งเดียว** (retry อ่านซ้ำจะกลายเป็น consensus ปลอม)
- ขับจริงผ่าน `FetchPageTool` ตัวจริง → evidence → `QAReviewer` ตัวจริง: T5×2 ไม่ผ่าน
- เติม T2 แล้วผ่าน
- **ยุบเป็น type เดียวแล้ว (2026-08-16, 7 เทส)** — `SourceTier` เป็น alias ของ `CredibilityTier`
- **สิ่งที่เจอตอนยุบคือเหตุผลว่าทำไมต้องยุบ**: สอง enum นี้มี `<` **กลับทางกัน** (`t1 < t2` จริงในฝั่งหนึ่ง เท็จในอีกฝั่ง) ⇒ "แหล่งดีอย่างน้อย T2" อ่านได้คนละความหมายห่างกันหนึ่งโมดูล และมันไม่ crash แค่กรองผิด ซึ่งคือความผิดพลาดที่ §0.2 ข้อ 3 พูดถึง
- เจอจุดที่กลับทางจริงสี่จุดตอนคอมไพล์+เทส: ตัวกรอง tier ของ `SourceRegistry`
- `KnowledgeView.minTier`
- การขยายสิทธิ์ (`widened`)
- และกฎ "แหล่งที่ดีกว่าเปิดคำถามที่ตัดสินแล้วได้อีก" ของ conflict ledger — สามในสี่จุดนี้ทำงาน*ถูก*มาตลอดเพราะอยู่ในโมดูลที่ `<` แปลว่า "น่าเชื่อกว่า"
- **decode ได้ทั้งสองรูปที่เคยเก็บไว้** (`"t3"` ของ provenance ตั้งแต่ P2 และ `3` ของ evidence ตั้งแต่ P1) เพราะตัว decoder ที่รับรูปเดียวคือการทำให้ครึ่งหนึ่งของคลังอ่านไม่ได้ (กฎเดียวกับ P9.2)
- `TierParityTests` เปลี่ยนจากยามเฝ้าการเพี้ยน เป็นการยืนยันว่ามันเป็น type เดียวกันจริง
