## 0. สี่คำที่ห้ามใช้ปนกัน

| คำ | หมายถึง | ตัวอย่าง |
|---|---|---|
| **ผ่าน** | ตรวจแล้ว ได้ผลตามที่คาด | 1,727 เทสรันและเขียว |
| **ข้าม** | **ไม่ได้ตรวจ** เพราะเงื่อนไขไม่พร้อม — **ไม่ใช่ผ่าน** | ไม่มี Python ⇒ ข้ามเทส notebook |
| **ไม่เกี่ยว** | ตรวจไม่ได้เพราะไม่ใช่ความสามารถของสิ่งนั้น — **นับว่าถูกต้อง** | Tier 0 ไม่ประกาศว่าเรียกทูลได้ ⇒ ไม่ต้องตรวจทูล |
| **ตก** | ตรวจแล้ว ผลไม่ตรงที่คาด | เทสแดง |

**รายงานที่บอกว่า "ผ่านหมด" โดยไม่บอกจำนวน *ข้าม* เป็นรายงานที่ผิด** แม้ตัวเลขทุกตัวจะถูก

## 1. pre-flight — ทำก่อนทุกรอบ

```bash
pkill -if 'helpers/surreal' 2>/dev/null; sleep 1     # 1
vm_stat | awk '/free|inactive/ {print}'                     # 2
curl -s --max-time 5 http://192.168.1.205:8000/v1/models >/dev/null \
  && echo "GX10: UP" || echo "GX10: DOWN"                   # 3
```

| # | ทำไม |
|---|---|
| 1 | รันที่ถูกฆ่ากลางคันทิ้ง sidecar ไว้ 11 ตัว ตัวละ ~200 MB ⇒ รอบถัดไปไม่มี RAM ให้โมเดล ⇒ P5.3 รายงานผิดว่า "แรมไม่พอ" ทั้งที่เป็นขยะจากรอบก่อน (U17) |
| 2 | `Qwen3.5-9B` ต้องการ ~7.1 GB บนเครื่อง 16 GB ⇒ **ผลเปลี่ยนตาม RAM ไม่ใช่ตามโค้ด** = อาการ "ตอนแรกได้ ตอนหลังไม่ได้" |
| 3 | Tier 1 คือสมองหลัก — ต้องรู้ก่อนอ่านผลว่ามันอยู่หรือไม่ |

**ก่อนขับหน้าจอ เพิ่มอีกสองข้อ**

```bash
./scripts/build-app.sh
ls -l "build/Co-AI Workspace.app/Contents/MacOS/CoAIWorkspace"   # ต้องใหม่กว่าเวลาเริ่มโปรเซส
```

## 2. ห้าระดับของการทดสอบ

| ระดับ | ตอบคำถามว่า | คำสั่ง | เวลา | ต้องผ่านเมื่อ |
|---|---|---|---|---|
| **L0** ตรรกะ | ตรรกะถูกไหม | `swift test` | ~3 นาที | ทุก commit |
| **L1** โครงสร้าง | ต่อสายถูกไหม · กฎยังอยู่ไหม | `scripts/check.sh` | ~4 นาที | ทุก commit |
| **L2** ระบบจริง | โมเดล/DB/endpoint จริงตอบไหม | `check.sh --full` | ~5 นาที | **ก่อนปิดทุก task** |
| **L3** หน้าจอ | คนกดแล้วได้ผลไหม | `ScreenDriver` | ~20 นาที | **ทุก task ที่มี UI** |
| **L4** end-to-end | เส้นทางจริงยังต่อกันอยู่ไหม | scenario ([§5](#5-l4-end-to-end--scenario-ที่ต้องผ่าน)) | ~1 ชม. | **ทุก task ที่แตะเส้นทางของผู้ใช้** |

### สิ่งที่แต่ละระดับ *มองไม่เห็น*

| ระดับ | มองไม่เห็นอะไร | เคยหลุดจริง |
|---|---|---|
| L0 | การต่อสายในแอป (`CoAIWorkspaceApp` เป็น executable จึงไม่มี unit test) | `ConflictDetector` ผ่าน 7 เทสขณะที่ไม่มีอะไรในแอปสร้างมัน ⇒ หน้าจอว่างถาวร |
| L1 | คุณภาพของผลลัพธ์ · ความเร็ว · หน้าตา | กฎบอกว่า "ทุก view ใช้ token" ขณะที่มีระยะดิบ ~114 จุด |
| L2 | อะไรที่คนต้องกดถึงเกิด | endpoint ที่เพิ่มบนหน้าจอไม่ถึง router (F-1) |
| L3 | **ชิ้นส่วนที่ยังต่อกันอยู่ไหมหลังแก้ที่อื่น** | `HookChain(stageGate:)` ทำให้ policy ในแอปดับ ขณะที่ 11 เทสยังเขียว |
| L4 | อะไรที่พังหลังใช้ไปหลายสัปดาห์ | — |

> **L0+L1 เขียว = "ยังไม่พบว่าพัง" ไม่ใช่ "ใช้ได้"** ตราบใดที่ยังไม่ผ่าน L2 และ L4

## 3. L2 ระบบจริง — กติกา 3 ข้อ

### 3.1 หา endpoint เอง ไม่รอให้คนตั้ง env

```
ลำดับ probe:  COAI_TEST_ENDPOINT  →  GX10 (192.168.1.205:8000)  →  ไม่มี
```

**ไม่มี LM Studio ในลำดับนี้แล้ว** ([C7](DECISIONS.md#c-คำตัดสินของเจ้าของโปรเจกต์--2026-08-17)) · ตัวไหนตอบก่อนใช้ตัวนั้น แล้ว**พิมพ์ออกมาว่าใช้ตัวไหน**

**รอบตรวจปกติยิง Tier 1 ด้วย** ([C1](DECISIONS.md#c-คำตัดสินของเจ้าของโปรเจกต์--2026-08-17)) — ยอมให้รอบยาวขึ้น ~1 นาที เพราะถูกกว่าการค้นพบตอนปิด task

### 3.2 Skip มีสองชั้น และชั้นบนคือ FAIL

| ชั้น | นิยาม | ผล | ตัวอย่าง |
|---|---|---|---|
| **ข้ามได้** | ไม่กระทบแกนหลักตามแผน | ⊘ เหลือง · รอบยังเขียว | ไม่มี Python · ไม่มี `sqlite_scanner` |
| **ข้ามไม่ได้** | แตะแกนหลัก | 🔴 **แดง** | **Tier 1 / GX10** · Tier 0.5 floor (P5.4) · SurrealDB |

รายการ "ข้ามไม่ได้" ต้องเขียนไว้ในไฟล์ ไม่ใช่ความจำ

### 3.3 ทุกรอบจบด้วยสรุปว่าครอบคลุมอะไร

```
── สรุปความครอบคลุม ──
   Tier 1:    http://192.168.1.205:8000/v1 · unsloth/Qwen3.8-27B-NVFP4 · 32768
   Tier 0.5:  Qwen3.5-9B-MLX-4bit · ต้องการ 7.1 GB · ว่าง 3.1 GB → ⊘ ข้าม
   RAM:       ก่อน 3.1 GB → หลัง 2.8 GB
   ผ่าน 1727 · ตก 0 · ข้ามได้ 2 · ข้ามไม่ได้ 0     ← ต้องเป็น 0 ถึงเรียกว่าเขียว
```

### 3.4 L2 ต้องเรียกอะไรบ้าง

| เครื่องมือ | ตรวจอะไร |
|---|---|
| `scripts/gx10-check.sh` | Tier 1 ทำได้ครบ 6 ด่าน (tool call · reasoning split · structured output · window · throughput · metrics) |
| `swift test --filter ExecutorContract` กับ endpoint จริง | สัญญาของ executor ทั้งชุด |
| `swift run MLXCheck` | Tier 0.5 กับ weights จริง |
| `swift run TierOneCheck` | เพดานจำนวนสายขนาน — เลขที่ P16 ต้องใช้ |

## 4. L3 ขับหน้าจอ

**ที่นี่ขับเองได้ และต้องขับ** ([C4](DECISIONS.md#c-คำตัดสินของเจ้าของโปรเจกต์--2026-08-17)) — สิทธิ์ Accessibility เปิดแล้ว · `ScreenDriver` (`AXNavigator.press/type/snapshot`) กดและพิมพ์ได้จริงตั้งแต่ P17 ([E.33](VERIFICATION_LOG.md))

**"ทดสอบไม่ได้เพราะขับไม่ได้" หมดอายุแล้ว** — ของค้างที่ยังอ้างเหตุผลนี้ ต้องถูกขับ ไม่ใช่ถูกเลื่อน

### กติกา

1. ขับบน `.app` ที่ build + sandbox แล้ว **ไม่ใช่ `swift run`**
2. **ปิดแอปด้วย ⌘Q เสมอ** — `kill -9` ทำให้ macOS restore เป็น "ไม่มีหน้าต่าง" ซึ่งหน้าตาเหมือน boot ล้มเหลวเป๊ะ (U24-2)
3. บันทึกลง [`DRIVING_LOG.md`](DRIVING_LOG.md) ทุกรอบ **รวมถึงรอบที่ไม่เจออะไร**
4. อ่านผลจากหน้าจอ ไม่ใช่จากสมมติฐาน — snapshot ก่อนและหลังทุก action

### เช็กลิสต์ต่อหน้าจอ

| # | ตรวจอะไร | เคยหลุดจริง |
|---|---|---|
| 1 | เปิดตอน**ไม่มีข้อมูล** — empty state ต่างจากหน้าโหลดล้มเหลวไหม | U23-7 |
| 2 | กดทุกปุ่ม **รวมปุ่มที่คิดว่าไม่มีใครกด** | sheet ที่ force-unwrap crash ตอนกดบันทึก (U33-1) |
| 3 | พิมพ์**ภาษาไทยยาว ๆ** ทุกช่อง แล้วดูว่าตัวอักษรครบ | เคยกินอักษรรอบละตัวเพราะเขียนทุก keystroke |
| 4 | ค่าที่แก้แล้ว**มีผลทันทีไหม** ถ้าไม่ หน้าจอบอกไหม | F-1 |
| 5 | สลับ workspace ไป-กลับ แล้วสถานะยังถูกไหม | P21.1 |
| 6 | โหมดมืด + สว่าง — **ตัวเลขทุกตัวอ่านออกไหม** | — |
| 7 | Tab ไล่ทั้งหน้า ถึงทุกปุ่มโดยไม่ต้องเปิด Full Keyboard Access | P8.7 |
| 8 | มี `Optional(…)` หรือ `**` โผล่บนจอไหม | หลุดมาแล้วอย่างละสองครั้ง |

## 5. L4 end-to-end — scenario ที่ต้องผ่าน

**นี่คือชั้นที่กัน "แก้อันหนึ่งพังอันอื่น"** — เทสหน่วยพิสูจน์ว่าชิ้นส่วนถูก ไม่ได้พิสูจน์ว่าชิ้นส่วนยังต่อกันอยู่ ([กฎ M7](../RULES.md#1-กฎแม่-8-ข้อ))

**นิยาม E2E ที่นี่**: จากจุดที่ผู้ใช้เริ่ม ถึงผลที่ผู้ใช้เห็น **ผ่านชั้นจริงทุกชั้น ไม่ mock ตรงกลาง**

| # | Scenario | ผ่านเมื่อ | วันนี้ |
|---|---|---|---|
| **S1** | ถามภาษาไทยในแชท แล้ว GX10 ตอบ | สระ/วรรณยุกต์ครบ · บรรทัดเหตุผลบอกว่ามาจาก GX10 | ✅ **ทำซ้ำหลังแก้ F-1 แล้ว 2026-08-17** — `23 คูณ 4 เท่ากับ 92` |
| **S2** | ตัดสายกลางสตรีมแล้วแอปไม่ตาย | ตกไป Tier 0.5 หรือแจ้งชัด ไม่ใช่ค้าง | 🔶 ค้าง P15.1 |
| **S3** | สร้างโปรเจกต์ → ผ่าน G1–G4 → ปิดโครงการ | ความรู้ย้ายขึ้นส่วนกลาง · โปรเจกต์ถัดไปค้นเจอ | 🔶 ค้าง P11 |

| **S7** | เพิ่ม endpoint ใหม่ → ใช้ได้ทันทีโดยไม่รีสตาร์ท | โผล่ในตัวเลือกโมเดลทันที | ✅ **ขับผ่าน 2026-08-17** ([E.40](verification/03-e31-e46.md#e40-ปิด-f-1--ค่าที่ตั้งบนหน้าจอมีผลทันที-และ-s7-ผ่านบนหน้าจอจริง-2026-08-17)) |

## 6. นิยามของ Done-when

Task ปิดได้เมื่อ **ครบทุกข้อที่เกี่ยวข้อง**

| # | เงื่อนไข | บังคับกับ |
|---|---|---|
| 1 | L0 + L1 เขียว | ทุก task |

| 3 | มี integration test ที่พิสูจน์ว่ามันถูกเรียกใช้จริงใน path ของผู้ใช้ | ทุก task ที่ให้ความสามารถ agent |

| 5 | **L4 scenario ที่เกี่ยวข้องยังผ่าน** | ทุก task ที่แตะเส้นทางของผู้ใช้ |
| 6 | มีเทสที่จะแดงถ้าบั๊กที่เพิ่งแก้กลับมา | ทุก task ที่แก้บั๊ก |
| 7 | ช่อง "ค้าง" ในแถวว่าง · ตัวเลขที่อ้างมีที่มาใน `VERIFICATION_LOG` | ทุก task |

## 7. ข้อห้าม

| ห้าม | เพราะ |
|---|---|
| นับ SKIP เป็น PASS | สาเหตุของ F-2 โดยตรง |
| รายงาน "ผ่านหมด" โดยไม่บอกจำนวนข้าม | ตัวเลขถูกทุกตัว ข้อสรุปผิด |
| ปิด task ด้วย "โค้ดเขียนเสร็จแล้ว" | v1 พังด้วยข้อนี้ |
| ปิด task ที่มี UI โดยไม่ขับหน้าจอ | ทุกรอบที่ขับเจอบั๊กที่เทสมองไม่เห็น |
| ปิด task ที่แตะเส้นทางผู้ใช้ โดยไม่มีเทสครบวง | แก้อันหนึ่งแล้วพังอันอื่น = โหมดความล้มเหลวประจำของโปรเจกต์นี้ |
| อ้างตัวเลขที่ไม่ได้วัดเอง | Done-when ของ P15.4 ระบุข้อนี้ไว้เอง |
| รันเทสโดยไม่เก็บ sidecar ค้างก่อน | ผลรอบถัดไปบิดเบือน |
| อ่านผลจากหน้าจอของ build เก่า | เคยสรุปผิดมาแล้ว |
| แก้เทสให้ผ่านแทนที่จะแก้โค้ด · ปิดเทส flaky | — |
| เลื่อนงานด้วยเหตุผลว่า "ขับหน้าจอไม่ได้" | หมดอายุแล้วตั้งแต่ P17 |

## 8. การจัดการเทสที่ไม่เสถียร (flaky)

| สถานะวันนี้ | |
|---|---|
| **ด่านสัญญา Tier 1 (`keeps the executor contract`)** | 🔴 **F-11** — ผ่านเดี่ยว 73 วิ · ตกตอนรันทั้งชุด 200 วิ · ผ่านอีกรอบ 168 วิ · ยังไม่รู้สาเหตุ |
| `ProcessRegistryTests` 2 ตัวที่ขึ้นกับ wall-clock (U12) | 🔶 รอบล่าสุดผ่านทั้งคู่ แต่ยังพึ่งเวลาจริง |
| เทสที่ใช้ `Task.sleep` | 32 จุด ใน 14 ไฟล์ |
| เทสที่เดาพอร์ต | 0 ✅ |

**กติกา**

1. ห้ามปิดเทส flaky — เทสที่ปิดคือเทสที่หายไป
2. flaky = บั๊กของเทส แก้ให้ไม่ขึ้นกับเวลา (ใช้สัญญาณ/`AsyncStream` แทน `Task.sleep`)
3. **แดงแล้วรันใหม่ผ่าน = ยังไม่ผ่าน** — การรันซ้ำจนเขียวคือการซ่อนตัวแปร ซึ่งที่นี่มักคือ RAM
4. `Task.sleep` ใหม่ทุกจุดต้องเขียนเหตุผลว่าทำไมรอเวลาแทนรอสัญญาณ

| ช่องทางแชตจริง (Telegram/Discord/LINE) | ต้องมีโทเคนของผู้ใช้ | stub server ในเทส |
